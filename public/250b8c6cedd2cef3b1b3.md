# はじめに

2026年10月26日、Databricks のブログに大学教員向けのガイド「How to teach with Databricks Free Edition」が公開されました。

- [How to teach with Databricks Free Edition](https://www.databricks.com/blog/how-teach-databricks-free-edition)
- [Databricks Free Edition](https://docs.databricks.com/aws/ja/getting-started/free-edition)
- [Databricks Free Edition の制限事項](https://docs.databricks.com/aws/ja/getting-started/free-edition-limitations)

私はこれまで、Free Edition を使って大学や社会人向け講座の講義を担当してきました。ブログの内容にはおおむね同意しますが、実際に授業を組んで回してみると、ブログには書かれていない準備がいくつか必要でした。

この記事では、ブログの要点を紹介したうえで、授業を組む前に確かめておくことと、当日の運営で効いたことを書いていきます。

# ブログで言っていること

ブログの主張は次の3点です。

- 1つの環境で、統計やデータサイエンスの入門から、データエンジニアリング、BI、機械学習、AI、卒業研究までをまかなえる
- Free Edition は授業用に機能を削った環境ではなく、企業が本番で使っているものと同じプラットフォームなので、授業で身につけたことがそのまま実務で使える
- 無料で期限がなく、クレジットカードもクラウド契約も要らない。学生が各自でサインアップするので、大学側でサーバーを用意する必要がない

中心にあるのは、授業科目ごとにどの機能を使えばよいかを整理した対応表です。たとえば、ビッグデータの授業なら Apache Spark、トランザクション処理の授業なら Lakebase、卒業研究やハッカソンなら Databricks Apps、という具合です。

後半は教員向けの FAQ で、課題の配り方、大きなデータセットの配り方、グループ課題、計算量の上限について答えています。

# 授業を組む前に、制限事項のページを読む

ブログの対応表は「この授業ならこの機能が使える」という地図です。一方、Free Edition にはアカウントごとに使える数の上限があります。授業の設計に入る前に、制限事項のページを一度読んでおくことをおすすめします。

## 対応表の機能には、アカウントごとの上限がある

授業の設計に関係しそうな上限を、授業での意味と並べるとこうなります。

| 機能 | 上限 | 授業で気をつけること |
| --- | --- | --- |
| SQL ウェアハウス | 1つ。サイズは 2X-Small | 大きなデータに重いクエリを投げる課題は、事前に時間を測っておく |
| ジョブ | 同時に動かせるタスクは5つまで | タスクを多数並べるワークフローの課題は組み方に注意する |
| Lakeflow パイプライン | パイプラインの種類ごとに、動かせるのは1つ | 複数のパイプラインを並行して動かす課題は組めない |
| Databricks Apps | 3つまで。起動から24時間で自動的に止まる | 翌日もアプリを見せる場合は、再起動の手順を伝えておく |
| Lakebase | プロジェクトは1つ | 学生1人あたり1つのデータベースで完結する課題にする |
| AI Search | エンドポイントは1つ | RAG の課題では、索引を作り直す前提で手順を組む |

上限の多くはアカウント単位です。ブログによると Free Edition は最大5人で1つのアカウントを共有してグループ課題に使えますが、その場合は5人でこの上限を分け合うことになります。グループで共有するか、1人1アカウントにするかは、課題で使う機能を見て決めるのがよいと思います。

## GPU は、LinkedIn で本人確認すると一部が使える

ブログの対応表では、機械学習の行に GPU が挙がっています。制限事項のページを見ると、GPU のモデルサービングエンドポイントは Free Edition の対象外です。一方で、LinkedIn で本人確認をすると AI Runtime が限定的に使えるようになる、とも書かれています。

本人確認ができるアカウントはワークスペースの上部に「Verify identity」ボタンが出る、という形なので、全員が同じ条件になるとは限りません。GPU を使う課題を出す場合は、学生の手元で使えるかを先に確かめておく必要があります。今回は、GPU を使う課題までは試せていません。

## R と Scala は使えない

ノートブックで使える言語は Python と SQL です。R と Scala はサポートされていません。統計の授業で R を使っている場合は、Python に置き換えるか、R の部分だけ別の環境を使うかを決めておく必要があります。

このほか、Knowledge Assistant も Free Edition では使えません。

# 当日の運営で効いたこと

ここからは、実際に講義をしてみて効いたことです。

## サインアップは事前に済ませてもらう

ハンズオンのある講義では、事前準備ガイドを Qiita で公開し、講義の前に Free Edition への登録とログインの確認を済ませてもらいました。

- [【事前準備】生成AIによる情報システムへのインパクト](https://qiita.com/taka_yayoi/items/84c49a3491dca9a680c7)

登録手順は1分ほどの動画にしてあります。サインアップの方法はメールアドレスのほか、Google アカウントと Microsoft アカウントが使えます。大学のアカウントが Microsoft の場合は、そのまま使えることが多いはずです。

登録だけでなく、一度ログインできることまで確かめてもらうのがポイントです。当日になって「ログインできない」となると、その受講者は最初の数十分を失います。講師が1人で対応している場合は、ほかの受講者の進行も止まります。

## 教材は Git フォルダにクローンしてもらう

ブログでは、課題のノートブックを `.ipynb` で書き出し、LMS や GitHub で配る方法が紹介されています。私は教材を GitHub のリポジトリに置き、受講者に Free Edition の Git フォルダとしてクローンしてもらう形にしています。

- [Databricks Git フォルダー](https://docs.databricks.com/aws/ja/repos/)

![Screenshot 2026-10-27 at 13.25.58.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/ee4f169f-251e-4139-a5eb-4f992bd902e8.png)

この形にすると、受講者がする作業はリポジトリの URL を貼り付けるだけで、ノートブックが何本あっても1回で揃います。講義の直前に教材を直した場合も、受講者に Git フォルダでプルしてもらえば最新版になります。ファイルを1本ずつ配り直す必要はありません。

## 使えない機能は講師のデモに回す

Free Edition で使える機能は増え続けていますが、すべてではありません。私が担当している「生成AIによる情報システムへのインパクト」の講義では、確かめた結果が次のとおりでした。

- Genie One と Genie Agents は使える
- Lakeflow Designer も使える
- Genie App Builder は使えない

11月の講義では、Lakeflow Designer をハンズオンに入れ、Genie App Builder は講師のデモにする予定です。講義のあとの課題でアプリを作る部分は、有償版の環境を持っている人向けの任意課題にしました。

使えない機能を外すのではなく、デモに回すのがポイントです。授業で伝えたいことが「AIでアプリを作れるようになった」なら、受講者が自分の手で触れなくても、画面で見せるだけで伝わる部分は大きいです。

また、Free Edition の Genie Agent では、エージェントモードでエラーになる場合がありました。ハンズオンの手順は、エージェントモードが動かなくても進められる形にしておくと安心です。

## 準備の少ない題材を選ぶ

大学院の講義で AI エージェントのハンズオンを作ったときは、文書検索(ベクトル検索)を使わない題材を選びました。

- [受講者が「ループ」になる AI エージェントのハンズオンを作った](https://qiita.com/taka_yayoi/items/a0c5c4f5fba482c36688)

PDF を取り込んで索引を作る手順がなくなるので、事前準備は Free Edition へのログインとリポジトリのクローンだけになりました。AI Search のエンドポイントが1つという上限にも引っかかりません。

90分の講義では、環境の準備に使える時間はほとんどありません。授業で伝えたいことに関係しない準備は、題材の選び方で減らせるなら減らしたほうがよいと考えています。

## モデルは、題材の質問で実際に動かして選ぶ

同じハンズオンでは、最初に使ったモデルでツール呼び出しの返し方が期待と違うことがありました。そこで、Free Edition で使えるモデルのうち6つに同じ質問を投げ、題材の質問で最後まで期待どおりに動いたモデルを選びました。

モデルの性能表を見て選ぶよりも、授業で使う質問で実際に動かして選ぶほうが確実です。授業の当日に受講者全員の画面で同じことが起きる、という点では、ここが一番準備しておきたい部分でした。

## MLflow の評価は1問ずつ実行する

同じハンズオンで `mlflow.genai.evaluate` を使ったところ、既定では複数の問いが同時に実行されるため、基盤モデルの呼び出し回数の上限を超えて `429 REQUEST_LIMIT_EXCEEDED` のエラーになりました。評価の前に環境変数で同時実行数を1にし、再試行の回数を増やすと、最後まで動きました。

```python
import os

# 評価データの問いを1問ずつ順番に実行する (既定は 10)
os.environ["MLFLOW_GENAI_EVAL_MAX_WORKERS"] = "1"
# 429 が返ったときの再試行回数 (既定は 3。MLflow 3.11.1 以降で使える)
os.environ["MLFLOW_GENAI_EVAL_MAX_RETRIES"] = "5"
```

これで、10問の評価が1回あたり約75秒で終わります。受講者全員が同時に評価のセルを実行する場面でも、1人ずつのアカウントで動いているので、ほかの受講者の実行には影響しません。この点は、Free Edition を1人1アカウントで使う利点です。

## 上限に達したときのことを伝えておく

Free Edition では、計算量の上限を超えるとそのワークスペースのコンピュートがその日の残り時間は止まります。データと設定は消えず、上限がリセットされれば再開できます。

ブログによると、1日あたりのクレジットを2倍にする操作が年3回までできるので、試験前や課題の締め切り前に使えます。ブログでも勧めているとおり、課題は出す前に教員自身が Free Edition で一度通しておくのが一番の予防策です。そのうえで、止まったときは翌日に再開できることと、2倍にする操作があることを、最初の授業で受講者に伝えておくと慌てずに済みます。

# まとめ

Databricks のブログ「How to teach with Databricks Free Edition」の内容と、実際に講義をしてみて分かったことをまとめます。

- ブログの主張は、1つの環境で入門から卒業研究までまかなえること、本番と同じプラットフォームで学べること、無料で大学側の準備が要らないこと
- **授業を組む前に、制限事項のページを読む。SQL ウェアハウス、Apps、Lakebase、AI Search などはアカウントごとに上限がある**
- 1つのアカウントを最大5人で共有できるが、その場合は上限も5人で分け合う
- GPU は、LinkedIn で本人確認すると AI Runtime が限定的に使えるようになる。GPU のモデルサービングエンドポイントは対象外
- R と Scala は使えない
- **サインアップとログインの確認は、事前準備ガイドで講義の前に済ませてもらう**
- 教材は GitHub に置き、Git フォルダにクローンしてもらうと配布と更新が1回で済む
- Free Edition で使えない機能は外さずに講師のデモに回す
- モデルは、授業で使う質問で実際に動かして選ぶ
- MLflow の評価は、同時実行数を1にすると Free Edition の呼び出し上限に引っかからない

一番の収穫は、ブログの対応表と制限事項のページを並べて読むと、授業の設計で先に決めておくことがはっきりする、と分かったことでした。対応表は「何ができるか」、制限事項は「いくつまでできるか」を教えてくれます。授業は受講者全員が同じ時間に同じことをする場なので、後者を先に確かめておくと、当日に慌てる場面がかなり減ると思います。

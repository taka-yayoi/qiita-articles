# はじめに

Databricks の MLflow に、レビューキュー (Review Queues) がベータとして提供されています。トレースなどの確認したい対象をキューに入れ、確認する人が1件ずつ質問に回答していく仕組みです。

- [レビューキューを使用して構造化された人間のフィードバックを収集する](https://docs.databricks.com/aws/ja/mlflow3/genai/human-feedback/expert-feedback/review-queues)

人によるレビューについては、以前にラベリングセッションを使った記事を書きました。

- [DatabricksとMLflowによる人間のフィードバック収集を通じた生成AIアプリの品質改善](https://qiita.com/taka_yayoi/items/0ab0e5cd21f5296bd938)
- [MLflow 3 ヒューマンフィードバック: ラベリングセッションのデータモデル詳解](https://qiita.com/taka_yayoi/items/8a8944a326afc4551026)

ドキュメントでは、新しく人によるレビューの流れを作る場合にはレビューキューが推奨されています。そこで、LLM で帳票の画像を分類するパイプラインを例に、人が正しい種別を選ぶ画面としてレビューキューを使ってみました。選んだ結果を正解にして、`mlflow.genai.evaluate()` で評価するところまでを通します。

実際に動かしてみると、確認の画面を開いた直後には帳票の画像が出ておらず、少し戸惑いました。そこも含めて書いていきます。

# レビューキューとは

レビューキューは、次の3つを組み合わせて使います。

| 用語 | 内容 |
| --- | --- |
| 質問 | 確認する人に答えてもらう問い。MLflow エクスペリメントの単位で定義する |
| キュー | 確認する対象を並べたもの。出す質問と、確認する人を設定する |
| 項目 | キューに入れた確認の対象 |

キューに入れられる対象は、ドキュメントによると次の2種類です。

- トレース
- 評価データセットのレコード

今回はトレースを入れます。評価データセットのレコードは試していません。

レビューキューはベータです。使うには、ワークスペース管理者がプレビューの管理から「MLflow Review Queues」を有効にします。今回使ったワークスペースでは、すでに有効になっていました。

# 試す内容

流れは次のとおりです。

1. 帳票の画像を LLM で分類して、トレースを3件作る
2. 質問とレビューキューを作り、トレースを入れる
3. 画面で3件に回答する
4. 回答がトレースに入っているのを確かめる
5. 回答を正解にして `mlflow.genai.evaluate()` を実行する

2026年11月24日に、AWS 東京リージョンのワークスペースのノートブックで、MLflow 3.18.0 を使って実行しました。帳票は、この記事のために作った架空のものです。

# 帳票の画像を分類してトレースを作る

## ライブラリを入れる

レビューキューの SDK は `mlflow.genai.databricks.review_queues` で、MLflow 3.17.1 以上が必要です。`matplotlib-fontja` は、帳票の画像に日本語を描くためのフォントを使う目的で入れています。


## 準備

MLflow エクスペリメントを用意します。この検証では、途中で画面での回答を挟みます。回答のあとでノートブックを最初から実行し直しても同じトレースやキューを二重に作らないよう、作ったものの ID をワークスペースのファイルに保存しています。

```python
dbutils.widgets.text("llm_endpoint", "databricks-claude-sonnet-4-5", "画像を読める LLM のエンドポイント")
```

```python
import os, io, json, base64
import pandas as pd
import mlflow
from databricks.sdk import WorkspaceClient
from mlflow.genai.databricks import review_queues as rq

w = WorkspaceClient()
ME = w.current_user.me().user_name
LLM_ENDPOINT = dbutils.widgets.get("llm_endpoint")

exp = mlflow.set_experiment(f"/Users/{ME}/review_queue_walkthrough")
EXP_ID = exp.experiment_id
print("MLflow:", mlflow.__version__, "/ 実験 ID:", EXP_ID)

# 作ったトレース、質問、キューの ID を保存するファイル。
# 「すべて実行」をやり直しても、同じものを二重に作らないために使います
STATE_PATH = f"/Workspace/Users/{ME}/review_queue_walkthrough_state.json"
STATE = json.load(open(STATE_PATH)) if os.path.exists(STATE_PATH) else {}


def save_state():
    with open(STATE_PATH, "w") as f:
        json.dump(STATE, f, ensure_ascii=False, indent=1)
```

## 架空の帳票を画像にする

架空の帳票を3件、画像として作ります。LLM に渡すメッセージは OpenAI 形式で、画像は data URL で入れています。

```python
from PIL import Image, ImageDraw, ImageFont
import matplotlib_fontja

# 日本語を描くために、matplotlib-fontja に入っているフォントを使います
FONT = ImageFont.truetype(os.path.join(os.path.dirname(matplotlib_fontja.__file__), "fonts", "ipaexg.ttf"), 28)

DOCS = [
    {"file_name": "sample_001.png", "title": "修理見積書 (サンプル)", "lines": ["見積番号 0001", "部品代 10,000円", "工賃 5,000円"]},
    {"file_name": "sample_002.png", "title": "自動車検査証 (サンプル)", "lines": ["車台番号 XXXX", "有効期間の満了する日 2027-01-01"]},
    {"file_name": "sample_003.png", "title": "診療の記録 (サンプル)", "lines": ["傷病名 ○○", "初診日 2026-01-01"]},
]


def make_png(doc):
    im = Image.new("RGB", (640, 420), "white")
    d = ImageDraw.Draw(im)
    d.rectangle((10, 10, 630, 410), outline="black", width=2)
    d.text((30, 30), doc["title"], font=FONT, fill="black")
    for i, line in enumerate(doc["lines"]):
        d.text((30, 100 + i * 44), line, font=FONT, fill="black")
    b = io.BytesIO()
    im.save(b, "PNG")
    return b.getvalue()


for doc in DOCS:
    png = make_png(doc)
    # OpenAI 形式のメッセージ。画像は data URL で渡します
    doc["messages"] = [{"role": "user", "content": [
        {"type": "text", "text": "この帳票の種別を1つ選んでください"},
        {"type": "image_url", "image_url": {"url": "data:image/png;base64," + base64.b64encode(png).decode()}},
    ]}]

display(Image.open(io.BytesIO(make_png(DOCS[0]))))
```

1件目の帳票はこのような画像になります。

## LLM で分類する

画像を LLM に渡して、帳票の種別を1つ答えさせる関数です。`@mlflow.trace` を付けて、呼び出しをトレースに記録します。

```python
mlflow.openai.autolog()
client = w.serving_endpoints.get_open_ai_client()

LABELS = ["修理見積書", "車検証", "診断書", "領収書", "事故状況説明書", "請求書", "送付状", "その他"]
SYSTEM = "あなたは帳票の分類器です。次の種別から1つだけ選び、種別の名前だけを答えてください: " + "、".join(LABELS)


@mlflow.trace(name="classify_document", span_type="CHAIN")
def classify(file_name, messages):
    resp = client.chat.completions.create(
        model=LLM_ENDPOINT, messages=[{"role": "system", "content": SYSTEM}] + list(messages), max_tokens=1000)
    answer = resp.choices[0].message.content
    # 答えの文から、種別の名前を取り出します。どれにも当たらなければ「その他」にします
    return {"label": next((l for l in LABELS if l in answer), "その他")}
```

実行すると、`get_open_ai_client()` は非推奨だという警告が出ます。警告の文面のとおり、`databricks-openai` パッケージの `DatabricksOpenAI` に置き換えられます。今回はそのまま進めました。

3件を分類して、トレースの ID を控えます。

```python
if "trace_ids" not in STATE:
    STATE["trace_ids"], STATE["labels"] = [], []
    for doc in DOCS:
        STATE["labels"].append(classify(doc["file_name"], doc["messages"])["label"])
        STATE["trace_ids"].append(mlflow.get_last_active_trace_id())
    # トレースは裏で非同期に保存されます。キューに入れる前に、保存が終わるのを待ちます
    mlflow.flush_trace_async_logging()
    save_state()

TRACE_IDS = STATE["trace_ids"]
display(pd.DataFrame({"file_name": [d["file_name"] for d in DOCS], "LLM の分類": STATE["labels"], "trace_id": TRACE_IDS}))
```

LLM の分類は次のようになりました。

| file_name | LLM の分類 |
| --- | --- |
| sample_001.png | 修理見積書 |
| sample_002.png | 車検証 |
| sample_003.png | 診断書 |

# 質問とレビューキューを作る

## 質問は EXPECTATION 型にする

質問には `FEEDBACK` と `EXPECTATION` の2つの型があります。出力の良し悪しを答えてもらうなら `FEEDBACK`、正解を答えてもらうなら `EXPECTATION` です。今回は人が正しい帳票種別を選ぶので、`EXPECTATION` にします。

回答の形式は `input` で指定します。SDK には次の4つがあります。

- `InputPassFail`: 合格か不合格か
- `InputCategorical`: 選択肢から選ぶ。`multi_select=True` で複数選択になる
- `InputNumeric`: 数値
- `InputText`: 文字の入力

今回は `InputCategorical` に、帳票種別の一覧をそのまま渡します。

```python
if "question_id" not in STATE:
    q = rq.create_review_question(
        EXP_ID,
        title="正しい帳票種別",
        type="EXPECTATION",  # 正解を集める質問。良し悪しの評価を集めるなら "FEEDBACK"
        input=rq.InputCategorical(options=LABELS),
        instruction="帳票を見て、正しい帳票種別を1つ選んでください",
    )
    STATE["question_id"] = q.question_id
    save_state()
print("質問 ID:", STATE["question_id"])
```

## キューにトレースと確認する人を入れる

キューを作り、確認する人とトレースを入れます。確認する人は自分にしています。

```python
if "queue_id" not in STATE:
    queue = rq.create_review_queue(EXP_ID, "帳票分類の確認", question_ids=[STATE["question_id"]])
    rq.add_review_queue_member(EXP_ID, queue.queue_id, ME)
    rq.add_review_queue_items(EXP_ID, queue.queue_id, trace_ids=TRACE_IDS)
    STATE["queue_id"] = queue.queue_id
    save_state()
QUEUE_ID = STATE["queue_id"]
print("キュー ID:", QUEUE_ID)
```

これでキューができました。MLflow エクスペリメントの左のメニューにある「レビュー」から、作ったキューを開けます。次のコードで、キューを選んだ状態の URL を出せます。

```python
print(f"{w.config.host.rstrip('/')}/ml/experiments/{EXP_ID}/review-queue?selectedQueueId={QUEUE_ID}")
```

キューの詳細には、入れたトレースが3件並びます。リクエストとレスポンスの内容、ステータス、追加された日付が見えます。

![Screenshot 2026-11-24 at 18.12.33.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/ad0ab913-49fb-4b12-b461-ce14aa86abf2.png)

確認する人にキューを使ってもらうときの権限は、ドキュメントに記載があります。回答するだけなら、エクスペリメントの読み取り権限と、キューへの割り当てで足ります。

# 画面で回答する

## デフォルトビューには帳票の画像が出ない

「レビューを開始」を押すと、確認の画面に入ります。左に確認する対象、右に質問が出ます。上には「3件中0件をレビュー済み」という進み具合と、前へ、次へ、次の未確認項目のボタンがあります。

![Screenshot 2026-11-24 at 18.12.52.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/af624044-10ee-497c-89e8-5395aeb86072.png)

ここで少し戸惑いました。左に出ているのは、リクエストの文字の部分 (「この帳票の種別を1つ選んでください」) と、分類結果の JSON です。帳票の画像は出ていません。この画面だけでは、正しい種別を選べません。

## 「完全なトレースを表示」を押すと画像が出る

左上の「完全なトレースを表示」を押すと、スパンの一覧と、入力と出力の詳細に切り替わります。入力のところに帳票の画像が表示されます。右の質問はそのまま残るので、画像を見ながら種別を選べます。

![Screenshot 2026-11-24 at 18.19.54.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/1adceb3b-2a01-4f73-ac14-877e6aca2416.png)

デフォルトビューが見せるのは、リクエストとレスポンスの要点です。文字でやり取りするチャットのようなアプリであれば、これで足ります。ドキュメントにも、より詳しい情報が必要なときは項目の全体を開ける、と書かれています。入力が画像の場合は、「完全なトレースを表示」を押してから確認する、という手順になります。確認する人に依頼するときは、この一手を伝えておくのが良さそうです。

「デフォルトビュー」の右には「＋」があり、カスタムトレースビューを作る画面が開きます。帳票の画像が最初から出るビューを作って確認の画面で使えるかどうかは、今回は確認できていません。

## 回答はトレースの Expectation として入る

トレースに付いた assessment を読みます。

```python
rows = []
for doc, tid in zip(DOCS, TRACE_IDS):
    for a in mlflow.get_trace(tid).info.assessments or []:
        rows.append({"file_name": doc["file_name"], "種類": type(a).__name__, "name": a.name, "value": a.value,
                     "source_type": str(a.source.source_type), "source_id": a.source.source_id})

if rows:
    display(pd.DataFrame(rows))
else:
    print("まだ回答がありません。画面で回答してから、このセルを実行してください")
```

結果は次のとおりです。

| file_name | 種類 | name | value | source_type | source_id |
| --- | --- | --- | --- | --- | --- |
| sample_001.png | Expectation | 正しい帳票種別 | 修理見積書 | HUMAN | (回答した人のメールアドレス) |
| sample_002.png | Expectation | 正しい帳票種別 | 車検証 | HUMAN | (回答した人のメールアドレス) |
| sample_003.png | Expectation | 正しい帳票種別 | 診断書 | HUMAN | (回答した人のメールアドレス) |

読み取れることは次の4点です。

- `EXPECTATION` 型の質問への回答は、トレースの Expectation として入る
- 名前 (`name`) は、質問のタイトルになる
- 値 (`value`) は、選んだ選択肢の文字列になる
- `source_type` は `HUMAN` で、`source_id` に回答した人が入る

回答はキューの中に留まるのではなく、トレースに付きます。以前の記事で見たラベリングセッションと同じ考え方です。トレースを読めば回答が取れるので、あとの処理はレビューキューを意識せずに書けます。

# 回答を正解にして評価する

人が選んだ種別を正解 (expectations) にして、分類の関数を `mlflow.genai.evaluate()` で評価します。スコアラーは、LLM の分類が人の選んだ種別と一致するかを見るものを1つ用意しました。

```python
from mlflow.genai.scorers import scorer

# 回答が入っている名前。上の表の name 列と同じものです
answers = [r for r in rows if r["種類"] == "Expectation"]
EXPECTATION_NAME = answers[0]["name"] if answers else None
print("正解として使う名前:", EXPECTATION_NAME)

# 回答のあった帳票だけを、評価用のデータにします
answer_by_file = {r["file_name"]: r["value"] for r in answers}
eval_data = [{"inputs": {"file_name": d["file_name"], "messages": d["messages"]},
              "expectations": {EXPECTATION_NAME: answer_by_file[d["file_name"]]}}
             for d in DOCS if d["file_name"] in answer_by_file]


@scorer
def label_match(outputs, expectations):
    # LLM の分類が、人がレビューキューで選んだ種別と一致するか
    return outputs["label"] == expectations[EXPECTATION_NAME]


if eval_data:
    result = mlflow.genai.evaluate(data=eval_data, predict_fn=classify, scorers=[label_match])
    print(result.metrics)
else:
    print("回答がないので、評価は実行していません")
```

```
正解として使う名前: 正しい帳票種別
{'label_match/mean': np.float64(1.0)}
```

3件とも、LLM の分類と人の選んだ種別が一致しました。帳票は種別がはっきり分かるように作った架空のものなので、この数字は分類の精度を示すものではありません。確かめたかったのは、レビューキューで集めた回答を、そのまま評価の正解として渡せることです。

実際の運用では、すべての帳票を人が見る必要はありません。分類結果のうち確認が必要なトレースだけをキューに入れ、人が選んだ種別を正解としてためていく、という使い方になります。たとえば、ルールによる判定と LLM の結果が食い違ったものや、信頼度が低いものです。

# まとめ

Databricks の MLflow レビューキューを、帳票の画像の分類で試して分かったことをまとめます。

- レビューキューの SDK は `mlflow.genai.databricks.review_queues`。質問、キュー、確認する人、項目を、それぞれ別の関数で作る
- 人に正解を選んでもらう質問は `EXPECTATION` 型にする。選択式は `InputCategorical` で、画面ではプルダウンになる
- **確認の画面のデフォルトビューには、帳票の画像が出ない。「完全なトレースを表示」を押すと、右の質問を残したまま画像が出る**
- **回答はトレースの Expectation として入る。名前は質問のタイトル、値は選んだ選択肢になる**
- トレースから読んだ回答を expectations に入れれば、`mlflow.genai.evaluate()` の正解として使える
- 評価データセットのレコードをキューに入れる使い方と、カスタムトレースビューとの組み合わせは、今回は試していない

一番の収穫は、回答の行き先がトレースだと確かめられたことでした。確認する人は画面で選ぶだけで、選んだ結果はトレースに正解として残ります。評価する側は、トレースを読めば正解が手に入ります。人が見る工程と評価の工程が、トレースを間に置いてつながる形です。画像を扱う場合は、確認する人に「完全なトレースを表示」を押してもらう一手が要る点だけ、先に伝えておくと安心です。

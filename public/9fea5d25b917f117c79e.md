# 変更点

## Agent EvaluationはMLflowに統合

まず大きな変更点としては、**Agent Evaluation**と呼んでいた機能がMLflow 3に統合されたということです。

https://docs.databricks.com/aws/ja/mlflow3/genai/agent-eval-migration

なので、今後は特にAgent Evaluationという用語は使いません(最近まで気づいてませんでした)。

## モニタリングはスコアリングに

これが結構わかりにくい。以前の記事では[**モニタリング**や**モニター**](https://qiita.com/taka_yayoi/items/411c9c1e67140f237c4a#%E3%82%A8%E3%83%BC%E3%82%B8%E3%82%A7%E3%83%B3%E3%83%88%E8%A9%95%E4%BE%A1%E3%81%AE%E7%B5%84%E3%81%BF%E8%BE%BC%E3%81%BF%E3%82%B8%E3%83%A3%E3%83%83%E3%82%B8)という用語が使われていましたが、今はスコアラーがモニターを兼ねる形になっています。

こちらのクイックリファレンスを見てみましょう。

![Screenshot 2025-09-11 at 9.46.21.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/8b2a4f1f-09a6-411a-9d1f-9910b3b225ce.png)

最初の行と最後の行の使用方法の両方に**Scorer**という単語があります。

最初のスコアラーは一般的な評価の概念としてのスコアラーです。一方、下のスコアラーは本番運用における品質モニタリングのためのスコアラーです。

### 一般的な評価概念としてのスコアラー

https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/concepts/#scorers

トレースの品質評価のための基本的な評価メトリクスを定義するものです。

特徴：
- `@scorer` デコレータを使った関数として定義
- オフライン評価（開発時）とオンライン評価（本番時）の両方で使用可能
- より基本的な評価メトリクスの定義

### 本番運用品質モニタリングのスコアラー

https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/concepts/production-quality-monitoring

本番環境でライブトラフィックに対してスコアラーを自動的に実行することで、生成AIアプリケーションの継続的な品質評価を可能にする機能です。

特徴：

- ライフサイクル管理（登録、アクティベーション、更新、削除）が可能
- `.register()`, `.start()`, `.stop()`, `.delete()` などのメソッドを持つ 
- サンプリングレートの設定が可能
- 本番環境での継続的なモニタリングに特化

### 二つのスコアラーの関係性

1. [基本的なスコアラー](https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/concepts/)は評価メトリクスの定義
1. [本番運用モニタリング](https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/concepts/production-quality-monitoring)は、その基本的なスコアラーを本番環境で管理・運用するための拡張機能

[開発と本番運用で同じスコアラーを使用して、一貫した評価を確保できる](https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/concepts/production-quality-monitoring)という記述があるように、基本的なスコアラーを定義して、それを本番環境でライフサイクル管理する、という流れになっています。

```py
import mlflow
from databricks.sdk import WorkspaceClient

# MLflowの自動ロギングを有効にして、アプリケーションにトレースを追加
mlflow.openai.autolog()

# DatabricksにMLflowトラッキングを設定
mlflow.set_tracking_uri("databricks")

# DatabricksホストのLLMに接続されたOpenAIクライアントを作成
w = WorkspaceClient()
client = w.serving_endpoints.get_open_ai_client()

# LLMを選択
model_name = "databricks-claude-sonnet-4"
```

LLMを呼び出してトレースを取得します。

```py
import json

# 基本的なシステムプロンプト
SYSTEM_PROMPT = """あなたは、文のテンプレートを面白く完成させることができる賢いボットです。創造的でエッジの効いたものにしてください。"""

@mlflow.trace
def generate_game(template: str):
    """LLMを使用して文のテンプレートを完成させます。"""

    response = client.chat.completions.create(
        model=model_name,  # この例ではDatabricksホストのClaude 3 Sonnetを使用しています。独自のOpenAI資格情報を提供する場合は、有効なOpenAIモデル（例：gpt-4oなど）に置き換えてください。
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": template},
        ],
    )
    return response.choices[0].message.content

# アプリをテスト
sample_template = "昨日、____ (人) が ____ (アイテム) を持ってきて、それを使って ____ (動詞) で ____ (オブジェクト) をしました"
result = generate_game(sample_template)
print(f"入力: {sample_template}")
print(f"出力: {result}")
```

## 評価概念としてのスコアラーの定義

評価スコアラーを作成します。これは[一般的な評価概念としてのスコアラー](https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/concepts/#scorers)です。

```py
from mlflow.genai.scorers import Guidelines, Safety
import mlflow.genai

# 評価スコアラーを定義
scorers = [
    Guidelines(
        guidelines="応答は入力と同じ言語でなければなりません",
        name="same_language",
    ),
    Guidelines(
        guidelines="応答は面白いか創造的でなければなりません",
        name="funny"
    ),
    Guidelines(
        guidelines="応答は子供に適したものでなければなりません",
        name="child_safe"
    ),
    Guidelines(
        guidelines="応答はリクエストの入力テンプレート構造に従い、空欄を埋めるだけで他の言葉を変更してはいけません。",
        name="template_match",
    ),
    Safety(),  # 組み込みの安全性スコアラー
]
```

評価を実施します。これは**オフライン評価**となります。

```py
# 評価を実行
print("基本的なプロンプトで評価中...")
results = mlflow.genai.evaluate(
    data=eval_data,
    predict_fn=generate_game,
    scorers=scorers
)
```

## 本番運用品質モニタリングのスコアラーの定義

ここで注目すべきは画面上の**スコアラー**です。これが[本番運用品質モニタリングのスコアラー](https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/concepts/production-quality-monitoring)です。

この時点では何も設定されていません。
![Screenshot 2025-09-11 at 10.21.16.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/7fb8928d-12ba-4761-9710-2f66412f3f62.png)

**New scorer**をクリックすることで本番運用品質モニタリングのスコアラーを追加することができます。ビルトインのLLMジャッジを追加することもできますし、カスタムコードのスコアラーも追加できます。[ベストプラクティス](https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/production-monitoring#%E6%A6%82%E8%A6%81)に従って開発時に使用したスコアラーを追加します。
![Screenshot 2025-09-11 at 10.21.53.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/a3fefe1e-a9ab-4876-967f-e82449bbf935.png)

カスタムコードのスコアラーを登録するにはコードを使用します。[こちら](https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/production-monitoring)を参考にスコアラーをエクスペリメントに登録します。
![Screenshot 2025-09-11 at 10.24.50.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/f635388a-83d1-4678-ba06-bccab051285c.png)

本当は上のスコアラーを定義する時点で登録を前提とした方がいいですね。

```py
from mlflow.genai.scorers import scorer, ScorerSamplingConfig

# ガイドラインスコアラーの作成と登録
same_language_scorer = Guidelines(
  name="same_language",
  guidelines=["応答は入力と同じ言語でなければなりません"]
).register(name="same_language")  # エクスペリメントで一意な名前

funny_scorer = Guidelines(
  name="funny",
  guidelines=["応答は面白いか創造的でなければなりません"]
).register(name="funny")  # エクスペリメントで一意な名前

child_safe_scorer = Guidelines(
  name="child_safe",
  guidelines=["応答は子供に適したものでなければなりません"]
).register(name="child_safe")  # エクスペリメントで一意な名前

template_match_scorer = Guidelines(
  name="template_match",
  guidelines=["応答はリクエストの入力テンプレート構造に従い、空欄を埋めるだけで他の言葉を変更してはいけません。"]
).register(name="template_match")  # エクスペリメントで一意な名前

safety_scorer = Safety().register(name="my_safety_scorer")

# 指定したサンプリングレートでモニタリングをスタート
same_language_scorer = same_language_scorer.start(sampling_config=ScorerSamplingConfig(sample_rate=0.7))
funny_scorer = funny_scorer.start(sampling_config=ScorerSamplingConfig(sample_rate=0.7))
child_safe_scorer = child_safe_scorer.start(sampling_config=ScorerSamplingConfig(sample_rate=0.7))
template_match_scorer = template_match_scorer.start(sampling_config=ScorerSamplingConfig(sample_rate=0.7))
safety_scorer = safety_scorer.start(sampling_config=ScorerSamplingConfig(sample_rate=0.7))
```

## トレースの永続化

これはこれで便利なのですが、より包括的にモニタリングしたいと思います。[トレースをDeltaテーブルに永続化](https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/production-monitoring#%E3%82%A2%E3%83%BC%E3%82%AB%E3%82%A4%E3%83%96%E3%83%88%E3%83%AC%E3%83%BC%E3%82%B9)することでより高度な分析や可視化が可能になります。


ちなみに、**トレース**タブの**チャート**にアクセスすると**このエクスペリメントではDelta同期が有効になっていません**とメッセージが表示されます。また、右上の**Delta同期：有効になっていません**からも、現時点ではトレースがDeltaテーブルに同期されていないことがわかります。

![Screenshot 2025-09-11 at 10.44.23.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/b4096c64-0f61-4f34-954b-1cf38d208043.png)

GUIからも同期を有効化できます。テーブルパスを指定するだけです。
![Screenshot 2025-09-11 at 10.46.02.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/edc455b8-8171-4cdf-b0ba-9423a3c88ff6.png)

コードでも有効化できます。

```py
from mlflow.tracing.archival import enable_databricks_trace_archival

# 特定のエクスペリメントからのトレースをUnity Catalog Deltaテーブルにアーカイブ
enable_databricks_trace_archival(
    delta_table_fullname="takaakiyayoi_catalog.genie_ai.archived_traces",
    experiment_id="3024811511536124",
)
```

# はじめに

MLflowの組み込みジャッジ(Built-in LLM judges)は、`model=` を指定しなければDatabricksがホストする既定のジャッジモデルで判定します。

- [組み込みのLLMジャッジ](https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/concepts/judges)
- [カスタムジャッジ](https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/custom-judge)

ドキュメントのサンプルはほとんどがDatabricksのノートブック上で動かす前提なので、「ノートブックの外、たとえば手元のPCやCIから、この既定のジャッジを呼べるのか」という質問を受けました。

結論から言うと呼べます。実際に手元のMacから呼んでみたところ、ノートブックと同じコードで既定のジャッジが判定を返しました。ただし1行省くと、エラーメッセージからは原因が分かりにくい形で失敗します。そのあたりも含めて書いていきます。

# MLflowのジャッジはどこで動いているのか

最初に仕組みを整理しておくと、なぜ外から呼べるのかが腑に落ちます。

MLflowはもともと、Databricksがなくても手元で動くように作られたライブラリです。`mlflow.genai.evaluate()` もスコアラーも、評価を実行しているPythonプロセスの中で動きます。ジャッジが外部に送るのは、判定のためのLLMの呼び出しだけです。

その呼び出し先が、接続先によって変わります。トラッキングの接続先をDatabricksにしておくと、既定のジャッジはDatabricksがホストするBuilt-in Judgeモデルになり、評価結果もDatabricksのMLflowトラッキングに記録されます。

![fig_judge_outside.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/59e85620-b46a-4c3a-9508-6a5ecd4d8a86.png)

つまり「外から呼ぶ」ための特別な機能があるわけではありません。ローカル開発からDatabricksのトラッキングサーバーに接続するのと同じ作法で、ジャッジも使えます。ローカル開発でDatabricksのトラッキングサーバーに記録する使い方自体は、ドキュメントでも想定されているシナリオです。

- [MLflowデータの保存場所を選択する](https://docs.databricks.com/aws/ja/mlflow/tracking-server-configuration)

# 手元のPCから既定のジャッジを呼ぶ

確認した環境は次のとおりです。

| 項目 | バージョン |
| --- | --- |
| 実行環境 | macOS上のPython 3.14 |
| MLflow | 3.18.0 |
| databricks-agents | 1.13.0 |

## パッケージと認証の準備

`mlflow[databricks]` に加えて `databricks-agents` が必要です。既定のジャッジの呼び出しは、このパッケージを経由して行われます。

```bash
pip install "mlflow[databricks]" databricks-agents
```

認証はDatabricks CLIのOAuthログインで済ませます。個人アクセストークンを作る必要はありません。

```bash
databricks auth login --host https://<ワークスペースのURL> --profile my-workspace
export DATABRICKS_CONFIG_PROFILE=my-workspace
```

CIで動かす場合は、サービスプリンシパルのOAuth(`DATABRICKS_CLIENT_ID` と `DATABRICKS_CLIENT_SECRET`)を環境変数で渡す形になります。

## スコアラーを単体で呼ぶ

まずは評価を回さず、スコアラーを直接呼んでみます。ポイントは先頭の `mlflow.set_tracking_uri("databricks")` です。

```python
import mlflow
from mlflow.genai.scorers import Safety, Guidelines
from mlflow.genai.judges import make_judge

# 既定のジャッジをDatabricksのBuilt-in Judgeモデルにするために必須です
# 省くとOpenAIのモデルを使おうとして失敗します(後述)
mlflow.set_tracking_uri("databricks")

feedback = Safety()(outputs="明日の東京は晴れの予報です。")
# source_id が "databricks" なら、既定のBuilt-in Judgeモデルで判定されています
print(feedback.value, feedback.source.source_type, feedback.source.source_id)

place = Guidelines(name="mentions_place", guidelines="回答に具体的な地名が含まれていること")
feedback = place(inputs={"question": "明日の天気は？"}, outputs="明日の東京は晴れの予報です。")
print(feedback.value, feedback.source.source_id)
print(feedback.rationale)

# model= を省略した make_judge も、既定のBuilt-in Judgeモデルで動きます
concise = make_judge(
    name="concise",
    instructions="{{ outputs }} が1文で簡潔に書かれているかを判定し、yes か no で答えてください。",
    feedback_value_type=str,
)
feedback = concise(outputs="明日の東京は晴れの予報です。")
print(feedback.value, feedback.source.source_id)
```

実行結果です。

```text
yes LLM_JUDGE databricks
yes databricks
The guideline requires that the response includes a specific place name. The response contains '東京' (Tokyo), which is a specific geographic location. Therefore, the response satisfies the guideline.
yes databricks
```

3つとも `source_id` が `databricks` になっています。ノートブックで実行したときと同じ、既定のBuilt-in Judgeモデルで判定されたということです。

## evaluate()も同じコードで動く

続いて、`mlflow.genai.evaluate()` で評価を回します。こちらも結果はワークスペースのエクスペリメントに記録されます。

```python
import mlflow
from mlflow.genai.scorers import Safety, Guidelines

mlflow.set_tracking_uri("databricks")
# ワークスペース上のパスで指定します。存在しなければ作成されます
mlflow.set_experiment("/Shared/qiita-judge-from-local")

data = [
    {"inputs": {"question": "明日の天気は？"}, "outputs": "明日の東京は晴れの予報です。"},
    {"inputs": {"question": "明日の天気は？"}, "outputs": "晴れ。"},
]
results = mlflow.genai.evaluate(
    data=data,
    scorers=[Safety(), Guidelines(name="mentions_place", guidelines="回答に具体的な地名が含まれていること")],
)
print(results.run_id, results.metrics)
```

```text
✨ Evaluation completed.

Metrics and evaluation results are logged to the MLflow run:
  Run name: redolent-ray-899
  Run ID: 0078313478444f27a13de75572eafb12
View the evaluation results at https://<ワークスペースのURL>/ml/experiments/<エクスペリメントID>/evaluation-runs?selectedRunUuid=0078313478444f27a13de75572eafb12

0078313478444f27a13de75572eafb12 {'mentions_place/mean': np.float64(0.5), 'safety/mean': np.float64(1.0)}
```

地名を含まない「晴れ。」のほうが `mentions_place` で不合格になったので、平均は0.5です。

ワークスペースのエクスペリメントを開くと、手元から実行した評価ランが記録されています。

# tracking_uriを省くとOpenAIのモデルになる

ここが最初のハマりどころです。`mlflow.set_tracking_uri("databricks")` を省いて同じスコアラーを呼ぶと、次のように失敗します。

```python
import mlflow
from mlflow.genai.scorers import Safety

# tracking_uri を設定していないので、ローカルの既定値になります
print(mlflow.get_tracking_uri())
feedback = Safety()(outputs="明日の東京は晴れの予報です。")
```

```text
sqlite:////private/tmp/qiita-demo/mlflow.db
mlflow.exceptions.MlflowException: OPENAI_API_KEY environment variable must be set to use the openai provider.
```

Databricksの認証情報は渡しているのに、OpenAIのAPIキーを求められます。トラッキングの接続先がDatabricksでないと、MLflowはOSS版としての既定どおり、OpenAIのモデルをジャッジに使おうとするためです。`set_tracking_uri("databricks")` は記録先を決めるだけでなく、既定のジャッジがどのモデルになるかも決めています。

ノートブックではトラッキングの接続先が最初からDatabricksになっているので、この行を意識することはありません。ノートブックで動いていたコードを手元に持ってきたときに、この1行が抜けていると上のエラーになります。

# 外から呼ぶときに気をつけること

- **MLflowを通して呼ぶ形が前提です。** 既定のジャッジは、MLflowと `databricks-agents` から呼び出す形で提供されています。MLflowを使わずにHTTPで直接呼び出すAPIは、公開ドキュメントには載っていません
- **`databricks-agents` が入っていないと動きません。** MLflowのソースを見ると、既定のジャッジを使う前にこのパッケージが入っているかを確認し、なければ例外を投げる作りになっています
- **実行環境からワークスペースのURLに接続できる必要があります。** 判定のたびにワークスペースへのリクエストが発生するためです
- **ワークスペースの上限は、呼び出し元に関係なくかかります。** 判定はワークスペースの既定のジャッジに対して行われるので、ノートブックから実行した場合と同じ上限が適用されます

なお、`model="databricks:/<エンドポイント名>"` のようにサービングエンドポイントを指定するジャッジも、同じくDatabricksの認証で呼び出す仕組みです。ただし、手元から動くことは今回確認できていません。

# まとめ

Databricks Notebookの外からMLflowの既定のジャッジを呼んでみて分かったことをまとめます。

- MLflowのジャッジは、評価を実行しているPythonプロセスの中で動く。Databricksに送られるのは判定のためのLLMの呼び出しだけ
- 手元のPCやCIからでも、`mlflow[databricks]` と `databricks-agents` を入れてDatabricksに認証すれば、ノートブックと同じコードで既定のBuilt-in Judgeモデルが動く
- 組み込みのスコアラー(Safety、Guidelines)、`model=` を省略した `make_judge`、`mlflow.genai.evaluate()` のいずれも、`source_id` が `databricks` で判定された
- **`mlflow.set_tracking_uri("databricks")` は必須。省くと既定のジャッジがOpenAIのモデルになり、`OPENAI_API_KEY` を求めるエラーになる**
- MLflowを使わずにHTTPで直接呼び出すAPIは、公開ドキュメントにはない

一番の収穫は、「外から呼べるか」という問いが、MLflowの作りを理解すると自然に解けたことでした。MLflowはクライアント側のライブラリで、Databricksはその接続先の1つです。そう捉えると、トラッキングと同じ作法でジャッジも使えること、接続先の設定を外すとOSSの既定に戻ることの両方が、同じ理由で説明できます。

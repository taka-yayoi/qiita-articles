# UNDROP TABLEコマンドとは

日本語マニュアルもあります。

https://docs.databricks.com/ja/sql/language-manual/sql-ref-syntax-ddl-undrop-table.html

> `UNDROP` コマンドは、 Unity Catalog にあるマネージ テーブルまたは外部テーブルが誤って削除または削除されるという問題に対処します。 デフォルトでは、このコマンドは、指定されたテーブル名のユーザーが所有する最後にドロップされたテーブルをアンドロップ (リカバリ) します。 親スキーマとカタログが存在する必要があります。 この機能は、7 日間の保持期間内に削除されたテーブルを回復することをサポートします。

:::note
**注意**
テーブル権限、列仕様、プロパティなどのテーブルメタデータがリカバリされます。 主キー制約と外部キー制約は、 `UNDROP` コマンドでは回復されません。
:::

# テーブルの作成

Unity Catalogでカタログ・スキーマを作成し、その中にテーブルを作成します。`drop_table_schema`というあからさまなスキーマ名にしています。
![Screenshot 2023-10-31 at 20.38.03.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/93c09c16-9f2f-671f-82ed-bf76505d4474.png)

# 削除済みテーブルの確認

まず、この状態で削除済みのテーブルが無いか確認します。

https://docs.databricks.com/ja/sql/language-manual/sql-ref-syntax-aux-show-tables-dropped.html

```sql:SQL
SHOW TABLES DROPPED IN takaakiyayoi_catalog.drop_table_schema;
```

この時点では当該スキーマでテーブルは削除されていないのでレコードは返却されません。

```
クエリー結果が返されませんでした
```

# テーブルの削除

```sql:SQL
DROP TABLE takaakiyayoi_catalog.drop_table_schema.japan_cases_20220818;
```
テーブルが削除されました。
![Screenshot 2023-10-31 at 20.41.32.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/1dcf111c-9ad2-072e-e24f-065ea33dce63.png)

再度、`SHOW TABLES DROPPED`を実行します。

```sql:SQL
SHOW TABLES DROPPED IN takaakiyayoi_catalog.drop_table_schema;
```
削除されたテーブルの情報を確認できます。
![Screenshot 2023-10-31 at 20.42.34.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/34d5fd3a-afd2-e17c-442a-da016e557071.png)

# テーブルのリカバリ

```sql:SQL
UNDROP TABLE takaakiyayoi_catalog.drop_table_schema.japan_cases_20220818;
```

テーブルが復旧しました！
![Screenshot 2023-10-31 at 20.45.09.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/683451b2-9ef0-7b53-0f79-ef6ab24d79b7.png)

# データとAIの準備

やったことは去年とほぼ同じです。

1. Qiita APIで自分の記事を全件取得して、Unity Catalogのテーブルに入れる
1. 6年目に書いた記事を、AI関数の `ai_query` で要約し、キーワードを付ける
1. 集計結果をもう一度 `ai_query` に渡して、1年間の変化をまとめてもらう

ノートブックはDatabricksのサーバーレスで動かしました。

## 一覧APIだけで閲覧数まで取れる

ここで少し手間取りました。

Qiita APIで自分の記事の閲覧数を取る方法を調べると、「一覧API (`/api/v2/authenticated_user/items`) では閲覧数が null になるので、記事ごとに `/api/v2/items/:id` を呼ぶ」という説明がいくつも見つかります。その通りに記事ごとに呼ぶ形で作ったところ、2,500本を1本ずつ呼ぶことになり、認証ありでも1時間1,000回の呼び出し上限にすぐ当たりました。

改めて一覧APIの応答を確かめると、公開している2,509本すべてに `page_views_count` が入っていました。今は一覧APIだけで閲覧数まで取れます。100件ずつ26回呼べば全件そろいます。

アクセストークンは Unity Catalog のシークレットに置いています。

```python
import requests

# Unity Catalog シークレットから読みます。値は出力で [REDACTED] になります
token = dbutils.secrets.get(catalog="takaakiyayoi_catalog", schema="qiita_look_back", key="qiita_token")

session = requests.Session()
session.headers.update({"Authorization": f"Bearer {token}"})

items, page = [], 1
while page <= 100:  # per_page=100 × 100ページが一覧APIの上限
    batch = session.get(
        "https://qiita.com/api/v2/authenticated_user/items",
        params={"page": page, "per_page": 100},
        timeout=30,
    ).json()
    if not batch:
        break
    items.extend(batch)
    page += 1

# 限定共有の記事も返るので、集計からは外します
public = [it for it in items if not it["private"]]
print(len(public), sum(it["page_views_count"] is not None for it in public))
```

これで記事本文、タグ、いいねの数、閲覧数がまとめて取れます。

## AI関数で要約とキーワードを付ける

6年目に書いた322本を `ai_query` に渡し、要約とキーワードをJSONで返してもらいました。モデルは `databricks-claude-sonnet-5-5` です。プロンプトはタイトルと本文の先頭6,000文字から組み立てて、`prompt` 列に入れてあります。

```sql
SELECT
  id,
  ai_query('databricks-claude-sonnet-5-5', prompt, failOnError => false) AS r
FROM summary_input
```

`failOnError => false` を付けると、1件が失敗してもクエリ全体は止まらず、結果と失敗理由が構造体で返ります。今回は322本すべて成功しました。

# AIによる総括

最後に、集計結果を `ai_query` に渡して、5年目からの変化をまとめてもらいました。返ってきた文章をそのまま載せます。

> 6年目は、BIやSparkが中心だった題材が、AIエージェントとLLMOpsの運用領域へ大きく移った1年でした。
>
> タグでは、生成AIが12件から72件、LLMOpsが14件から65件、AIエージェントが2件から44件に急増しました。MLflowも39件から77件になり、最多です。キーワードにはMLflow Tracing、LLM-as-a-Judge、GEPA、OpenTelemetryが並び、エージェントの評価、可観測性、プロンプト最適化といった実運用寄りの話題が目立ちます。
>
> 新しい題材も加わりました。Genie Codeは0件から23件、Omnigentは0件から14件、SDPは0件から13件です。Claude Codeは4件から17件、LakeFlowは6件から24件に増えました。一方で、Databricks_AI_BIは32件から9件、Sparkは25件から13件へ減りました。
>
> Unity Catalogは27件から33件と微増にとどまりますが、キーワードでは102回と最多で、基盤の話題として書き続けています。
>
> 閲覧数上位には、Genie関連、Omnigent、Claude Code連携、Jevやai_decideの検証、入門ガイドが入りました。新機能の整理と、実際に試した検証記事がよく読まれたようです。

数字は渡したものだけを使うよう指示していて、確かめた範囲では集計と合っていました。自分で書くよりも素直にまとまっていると思います。

# まとめ

6年目の数字をまとめます。

- 6年目に書いた記事は322本。累計は2,509本になり、2026年11月5日に2,500本を超えた
- 総閲覧数は7,973,252回。去年の記事の時点から288万回増えた
- **過去に書いた2,109本が、この1年で168万回読まれた。** 6年目に書いた322本の合計の約2.9倍
- 題材は、エージェントを作る話から、評価して運用する話に移った。MLflow、生成AI、LLMOpsのタグが大きく伸びた
- **タグでは33件のUnity Catalogが、AIが要約から抜き出したキーワードでは102件で最多。** 主題にしなくても、ほぼ3本に1本の記事で触れている
- よく読まれたのは入門の記事と、新しい概念を整理する記事
- Qiita APIの一覧APIは、今は閲覧数も返す。記事ごとにAPIを呼ばなくてよい

一番の収穫は、過去記事の閲覧数の伸びを見られたことでした。毎日新しい機能を試して書いていると、つい新しい記事の読まれ方ばかり気にしてしまいます。ところが実際には、2021年に書いた記事も含めて、過去の記事が新しい記事の3倍近く読まれていました。新しいことを追いかける記事と、基本を説明する記事は役割が違う。7年目も両方を書き続けていきます。

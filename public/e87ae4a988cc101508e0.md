# 準備

事前に`DS`というグループを作成しておき、ユーザーAのみを追加しておきます。

対象のテーブルは`target`とします。以下のように`pickup_zip`などの郵便番号が含まれているテーブルです。ちなみにこちらはNYのタクシーの乗降記録です。
![Screenshot 2023-09-13 at 10.56.05.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/d36e13bc-a4e5-3ee4-ce0e-7d73e97960a1.png)

Sharedクラスターを作成して起動します。シングルユーザークラスターでは本機能は動作しません。

# ユーザーAの作業

```sql
USE main.default;
```

列マスクの関数を定義します。このフィルターは、テーブルにアクセスするユーザーがグループ`DS`に所属している場合には全レコードをそのまま返却しますが、そうではない場合にはzipコードを`****`にマスキングします。

```sql
CREATE FUNCTION zip_mask(zip STRING)
  RETURN IF(IS_ACCOUNT_GROUP_MEMBER('DS'), zip, '****');
```
![Screenshot 2023-09-14 at 11.12.52.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/19e8d2be-bdeb-0607-6d8b-0c5ae1a2cdfc.png)

テーブルに列マスクを設定します。

```sql
ALTER TABLE target ALTER COLUMN dropoff_zip SET MASK zip_mask;
```

`DESCRIBE EXTENDED`で列マスクが設定されていることを確認できます。

```sql
DESCRIBE EXTENDED target;
```
![Screenshot 2023-09-14 at 11.15.20.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/ea53f71b-8142-b99f-4d39-f8bde96938b2.png)

ユーザーAはグループ`DS`に所属しているので、列マスクは適用されません。

```sql
SELECT * FROM target;
```
![Screenshot 2023-09-14 at 11.21.39.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/135b8027-6219-cced-28c7-e3cf262afe4d.png)

# ユーザーBの作業

ユーザーBはグループ`DS`には属していません。

```sql
SELECT * FROM target;
```

列マスクが動作して、`dropoff_zip`が`****`にマスキングされます。
![Screenshot 2023-09-14 at 11.16.02.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/23afbce5-df9c-4fd8-7e8d-6cc52a1730aa.png)

より複雑なマスキングのロジックも実装できますので、例えば、メールアドレスの前半のみをマスキングすることも可能です。ぜひご活用ください！

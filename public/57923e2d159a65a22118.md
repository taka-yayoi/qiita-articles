# [パブリックプレビューで利用できるようになった複数テーブル間でのトランザクション処理](https://docs.databricks.com/aws/en/release-notes/product/2026/march#multi-table-transactions-are-now-in-public-preview)
**2026-03-09**
<p>複数のテーブルにわたる複数の SQL ステートメントを<code>BEGIN ATOMIC ... END;</code>構文を使って単一の原子トランザクションにまとめられるようになりました。すべての変更は一緒に成功するか、一緒にロールバックされるため、操作全体でのデータの一貫性が確保されます。 複数テーブルのトランザクションには、参加テーブルで有効になっている<a href="https://docs.databricks.com/aws/ja/delta/catalog-managed-commits">カタログ管理のコミット</a>が必要であり、Unity Catalog で管理される Delta テーブルでサポートされています。</p>
<p><a href="https://docs.databricks.com/aws/ja/transactions">トランザクション</a>をご覧ください。</p>

**ユーザーへのインパクト**

Databricksのリリースにより、Unity Catalogで管理されるDeltaテーブルにおいて、複数のテーブルに対するSQLステートメントを`BEGIN ATOMIC ... END;`構文で1つのトランザクションとして実行できるようになりました。これにより、データの一貫性が確保され、すべての変更が成功するか、すべてロールバックされることが保証されます。ユーザーは、カタログ管理のコミットが有効になっていることを確認する必要があります。

### より多くの SQL コンテキストでパラメータマーカーがサポートされるようになりました

名前付き（`:param`）および名前なし（`?`）のパラメータマーカーを、適切なタイプのリテラル値が許可されている場所であればどこでも使用できるようになりました。これには、`CREATE VIEW v AS SELECT ?

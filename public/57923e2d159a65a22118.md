# [Databricks Runtime 18: 2026年6月8日](https://docs.databricks.com/aws/en/release-notes/runtime/18#databricks-runtime-18-june-8-2026)
**2026-06-08**
Apache Sparkの修正と改善
このリリースには、Sparkに対して行われた以下のバグ修正と改善が含まれています:
* `NEAREST BY`が、top-K最近傍探索クエリのためのSQL結合タイプとしてサポートされました。
* `DESCRIBE TABLE ... PARTITION`がv2カタログテーブルでサポートされるようになりました。以前は、この構文はv1テーブルでのみ利用可能でした。
* SQL PATHのサポートが拡張されました: `SET PATH`がサポートされるSQL文となり、`CURRENT_PATH()`が現在のパスを返し、PATHがビューおよびSQL関数定義に永続化され、`DESCRIBE`出力に含まれるようになりました。
* DSv2テーブルの`UPDATE`クエリに、クエリ出力のオペレーションメトリクスが含まれるようになりました。
* DSv2のパーティション述語が、ネストされたパーティション列をサポートするようになりました。
* `PartialMerge`あるいは`Final`の集計実行を用いた集計クエリが、必要な入力属性の欠如により失敗する可能性がある不具合を修正しました。
* 大規模な外部ソートで、ディスクへのデータのスピル時にメモリ不足エラーとなることを減らすためにバウンドk-wayマージが用いられるようになりました。

**ユーザーへのインパクト**

Databricks Runtime 18のリリースにより、以下の変更がDatabricksユーザーに影響を与えます：

* `NEAREST BY`を使用して、top-K最近傍探索クエリを実行できるようになりました。
* v2カタログテーブルのパーティション情報を`DESCRIBE TABLE ... PARTITION`で取得できるようになりました。
* SQL PATHが強化され、`SET PATH`文、`CURRENT_PATH()`関数が利用可能になり、ビューやSQL関数定義に永続化されるようになりました。
* DSv2テーブルの`UPDATE`クエリでオペレーションメトリクスが表示されるようになりました。
* DSv2のパーティション述語でネストされたパーティション列をサポートするようになりました。
* 一部の集計クエリで発生していた不具合が修正されました。
* 大規模な外部ソートでメモリ不足エラーが発生する可能性が低減されました。

**ユーザーへのインパクト**

Databricksの今後の動作変更に関するリリースノートを読み、その影響を簡潔にまとめると以下のようになります。

### 変更内容

- 2026年9月14日から、Databricksワークスペースにプリンシパル（ユーザーやグループ）を追加する際、そのプリンシパルに明示的に権限を付与する必要があります。これまでは、`users`システムグループからの継承により権限が付与されていました。
- ワークスペース管理者は2026年6月15日からこの新しい動作にオプトインできます。

### 影響

1. **新しいプリンシパルの権限付与方法の変更**: 新しく追加されるプリンシパルには、`users`グループからの継承ではなく、明示的に権限を付与する必要があります。これにより、コンシューマのみのユーザーなど、特定のアクセスレベルを持つプリンシパルをより細かく制御できます。

- 管理者は、新しいプリンシパルを追加する際に、必要な権限を明示的に付与する必要があります。
- `users`と`admins`グループの権限変更について理解し、必要に応じて既存のアクセス制御の見直しを行うことが推奨されます。

この変更により、Databricksワークスペースのアクセス制御がより細かく、明示的になることが期待されています。

# [Microsoft Excel から Databricks へのデータの書き戻し

Databricks は、Apache Spark をベースにしたビッグデータ処理および分析プラットフォームです。一方、Microsoft Excel は、データ分析や可視化のための一般的なツールです。Excel から Databricks にデータを書き戻すことで、両方のツールを組み合わせて使用することができます。

Excel から Databricks にデータを書き戻すには、いくつかの方法があります。

1. **Databricks Excel アドインを使用する**: Databricks は、Excel アドインを提供しています。このアドインを使用すると、Excel から Databricks にデータを直接書き戻すことができます。
2. **Databricks REST API を使用する**: Databricks は、REST API を提供しています。この API を使用すると、Excel から Databricks にデータをプログラムで書き戻すことができます。
3. **Spark Excel ライブラリを使用する**: Spark Excel ライブラリは、Excel ファイルを読み書きするための Spark ライブラリです。このライブラリを使用すると、Excel ファイルを Spark DataFrame に読み込み、Databricks に書き戻すことができます。

以下は、Databricks REST API を使用して Excel から Databricks にデータを書き戻す例です。

1. Databricks REST API のエンドポイントと認証トークンを取得します。
2. Excel データを JSON 形式に変換します。
3. JSON データを Databricks REST API を使用して Databricks に送信します。

以下は、Python と `requests` ライブラリを使用して、Excel データを Databricks に書き戻す例です。
```python
import pandas as pd
import requests

# Excel ファイルを読み込みます
df = pd.read_excel('example.xlsx')

# JSON データに変換します
data = df.to_json(orient='records')

# Databricks REST API のエンドポイントと認証トークンを設定します
databricks_url = 'https://your-databricks-instance.com/api/2.0/dbfs/put'
token = 'your-auth-token'
```

# [Databricks Runtime 18: 2026年6月4日](https://docs.databricks.com/aws/en/release-notes/runtime/18#databricks-runtime-18-june-4-2026)
**2026-06-04**
<h3><div></div>動作の変更</h3>
<p>クラスターがこのランタイムで再起動したときに有効になる以下の変更を確認してください。</p>
<ul>
<li><strong><code>NATURAL JOIN</code>の大文字と小文字を区別しないカラムマッチング</strong>: <a href="https://docs.databricks.com/aws/ja/sql/language-manual/sql-ref-syntax-qry-select-join"><code>NATURAL JOIN</code></a>は、結合の左側と右側の共通のカラムをマッチングする際に<code>spark.sql.caseSensitive</code>の設定値(デフォルト: <code>false</code>)を参照するようになりました。これまでは、カラムマッチングは常に大文字と小文字を区別していたため、大文字と小文字のみが異なるカラム（例えば、<code>ID</code>と<code>id</code>）は共通のカラムとして認識されませんでした。これにより、期待される等価結合の代わりにサイレントクロスジョインが発生していました。同等の<code>USING</code>結合は、すでにこれを正しく処理していました。以前の動作に戻すには、<code>spark.sql.legacy.naturalJoinCaseSensitiveColumnMatching</code>を<code>true</code>に設定します。 </li>
</ul>

**ユーザーへのインパクト**

Databricks Runtime 18へのアップグレードに伴い、`NATURAL JOIN`の挙動が変更されます。これまでは大文字小文字を区別してカラムをマッチングしていましたが、今後は`spark.sql.caseSensitive`の設定値に従うようになります。デフォルトでは大文字小文字を区別しないため、`ID`と`id`のようなカラムは共通のカラムとして認識されます。以前の動作に戻したい場合は、`spark.sql.legacy.naturalJoinCaseSensitiveColumnMatching`を`true`に設定してください。 

この変更により、これまでサイレントクロスジョインが発生していたケースで、意図した等価結合が実行されるようになります。影響を受ける可能性のある`NATURAL JOIN`クエリを事前に確認し、必要に応じて設定やクエリの修正を行うことを推奨します。

2. **Unity Catalogの外部カタログテーブルの権限保持**: 以前は、外部カタログテーブル（例：Snowflake接続テーブル）のメタデータを更新すると、テーブルレベルの権限が失われ、`INSUFFICIENT_PERMISSIONS`エラーが発生していました。この問題は修正され、メタデータの更新後も権限が保持されるようになりました。これにより、ユーザーは権限の問題を気にせずに外部テーブルのメタデータを更新できます。

# [Databricks SQL バージョン2026.15 がプレビューで利用できるようになりました。](https://docs.databricks.com/aws/en/sql/release-notes/2026#databricks-sql-version-202615-is-now-available-in-preview)
**2026-05-26**
<p>Databricks SQL バージョン2026.15が<strong>プレビュー</strong>チャンネルで利用可能になりました。以下のセクションを確認して、新機能、動作の変更、バグ修正について学んでください。</p>
<h4>XPathが外部DTDを取得しなくなった</h4>
<p>XMLに対して<a href="https://docs.databricks.com/aws/ja/sql/language-manual/functions/xpath">xpath</a>を評価する際、Databricksはドキュメント内で宣言された外部DTD（Document Type Definitions）をロードしなくなりました。以前は、XMLに不正なURLや到達不能なエンドポイントを指す外部DTD参照が含まれている場合、XPathは失敗する可能性がありました。DTD検証はXPath評価とは別であるため、すでに成功していたクエリは以前と同じ結果を返します。以前は外部DTD取得中にのみ失敗していたクエリが、成功するようになりました。</p>

# [Lakeflow Designer のアップデート内容](https://docs.databricks.com/aws/en/release-notes/product/2026/may#lakeflow-designer-updates)
**2026-05-19**
<p>Lakeflow Designer への以下の更新を行いました:</p>
<ul>
<li><strong>デフォルトで有効化</strong>: Lakeflow Designer は、すべての無料エディション、プレミアム、およびエンタープライズティアのワークスペースでデフォルトで有効になりました。開始するには、サイドバーの<strong>+新規</strong>をクリックし、<strong>ビジュアルデータ準備</strong>を選択します。このオプションが表示されない場合は、ワークスペースの管理者にお問い合わせください。</li>
<li><strong>AIオペレーター検索</strong>: オペレーターパネルが意図に基づいてオペレーターを提案するようになりました。たとえば、「average by month」と入力すると、集計オペレーターが表示されます。</li>
<li><strong>サンプルサイズの構成</strong>: 各オペレーターで実行するサンプル行数を設定できるようになりました。各オペレーターは独自のカスタム制限を記憶します。</li>
<li><strong>Git、インポート、クローン、エクスポート</strong>: <strong>ファイル &gt; エクスポート</strong> または <strong>ファイル &gt; クローン</strong> を使用して、ビジュアルデータ準備ファイルをエクスポート、クローン、およびインポートできるようになりました。ファイルを Git フォルダーに保存して管理することもできます。</li>
<li><strong>ユーザー定義オペレーター (パブリックプレビュー)</strong>:  組み込みのオペレーターと並んで表示されるユーザー定義オペレーターを作成できるようになりました。これらを使用して、Lakeflow Designer を独自のビジネスロジック、計算、または統合で拡張します。3 つのオペレータータイプがサポートされています: <code>uc-udf</code>、<code>uc-udtf</code>、および <code>python-run-function</code>。「<a href="https://docs.databricks.com/aws/ja/designer/user-operators">Lakeflow Designer のユーザー定義オペレーター</a>」を参照してください。</li>
<li><strong>バグの修正と改善</strong>: 右クリック時のキャンバスの動作、元に戻す/やり直しボタンの状態、Markdown ノードの下線の書式設定、未設定のフィルター条件の処理など、複数の問題を修正しました。</li>
</ul

**ユーザーへのインパクト**

Databricksユーザーは、Lakeflow Designerの以下の更新内容の影響を受けます：

* Lakeflow Designerがデフォルトで有効になり、サイドバーの「新規」から「ビジュアルデータ準備」を選択して使用を開始できます。
* オペレーターパネルで、意図に基づいてオペレーターを検索できるようになりました。
* 各オペレーターでサンプル行数を設定できるようになりました。
* ビジュアルデータ準備ファイルをGitで管理したり、エクスポート、クローン、インポートできるようになりました。
* ユーザー定義オペレーターを作成できるようになり、Lakeflow Designerを独自のビジネスロジックで拡張できます（パブリックプレビュー）。
* 複数のバグが修正され、改善が行われました。

# [Databricks Runtime 18: 2026年5月18日](https://docs.databricks.com/aws/en/release-notes/runtime/18#databricks-runtime-18-may-18-2026)
**2026-05-18**
<h3><div></div>動作の変更</h3>
<p>このランタイムでクラスターが再起動したときに有効になる以下の変更を確認します。</p>
<ul>
<li><strong><code>CREATE OR REPLACE TABLE</code></strong>: <a href="https://docs.databricks.com/aws/ja/sql/language-manual/sql-ref-syntax-ddl-create-table"><code>CREATE OR REPLACE TABLE</code></a> は、デフォルトで既存の列およびテーブルのコメントを保持するようになりました。 以前は、テーブルを再作成するとコメントは削除されていました。 マネージドテーブルとビューは、 マテリアライズドビューとストリーミングテーブルの既存の動作と一致するようになりました。 </li>
<li><strong>DataFrame の名前による書き込み</strong>: <code>writeTo().append()</code>、<code>writeTo().overwrite()</code>、<code>writeTo().overwritePartitions()</code>、および <code>write.mode("append").saveAsTable()</code> は、ターゲットの Delta テーブルスキーマに一致するように、型互換の列（たとえば、<code>int</code> から <code>long</code>）を自動的にキャストするようになりました。 以前は、列の型は互換性があるものの同一ではない場合、これらの操作は <code>DELTA_FAILED_TO_MERGE_FIELDS</code> エラーで失敗していました。 この動作は、SQL の <code>INSERT INTO ... BY NAME</code> と一致するようになりました。 上書きモードの <code>save()</code> および <code>saveAsTable()</code> は影響を受けません。 </li>
<li><strong><code>pipelines.pipelineId</code> に対する <code>ALTER TABLE SET TBLPROPERTIES</code></strong>: <code>ALTER TABLE &#x3C;table> SET TBLPROPERTIES('pipelines.pipelineId' = '&#x3C;pipeline-id>')</code> は、指定されたテーブルをパイプラインによる書き込みの対象として設定しようとするようになりました。 以前は、通常のテーブルでこのプロパティを設定しても効果はありませんでした。 テーブルがパイプライン書き込みの対象でない場合、コマンドは <code>SETTING_PIPELINES_PIPELINE_ID_NOT_SUPPORTED</code> をスローします

**ユーザーへのインパクト**

Databricks Runtime 18へのアップデートにより、以下の変更がユーザーのワークフローに影響を及ぼします：

1. **`CREATE OR REPLACE TABLE`の動作変更**: テーブルを再作成する際に、既存の列やテーブルのコメントがデフォルトで保持されるようになりました。これにより、マネージドテーブルやビュー、マテリアライズドビュー、ストリーミングテーブルの動作が一貫します。

2. **DataFrameの名前による書き込みの改善**: `writeTo().append()`や`write.mode("append").saveAsTable()`などの操作で、Deltaテーブルのスキーマに一致するように、型互換の列（例：`int`から`long`）が自動的にキャストされるようになりました。これにより、SQLの`INSERT INTO ... BY NAME`と同様の動作になります。ただし、上書きモードの`save()`や`saveAsTable()`はこの変更の影響を受けません。

3. **`ALTER TABLE SET TBLPROPERTIES`の動作変更**: `pipelines.pipelineId`プロパティを設定する際に、指定されたテーブルをパイプラインによる書き込みの対象として設定するようになりました。テーブルがパイプライン書き込みの対象でない場合、コマンドはエラーをスローします。

これらの変更は、Databricks Runtime 18でクラスターが再起動したときに有効になります。ユーザーは、これらの変更が自分のワークフローに与える影響を確認し、必要に応じてコードの修正やテストを行う必要があります。特に、テーブルのメタデータの保持やDataFrameの書き込み動作に依存する処理がある場合は、注意が必要です。

近日、Databricksワークスペースのサイドバーナビゲーションが更新されます。主な変更点は以下の通りです：

1. **アナリティクス**セクションが新設され、ダッシュボード、Genieスペース、アラートが一つのセクションにまとめられます。
2. **SQL**セクションは**Lakehouse**に名称変更され、SQLエディタ、クエリ、クエリ履歴、SQLウェアハウスが含まれます。

さらに、アプリ切り替えメニューにおいても、「Lakehouse」の名称が「アナリティクスとAI」に変更されます。これらの変更により、ユーザーはより整理された形でDatabricksの機能にアクセスできるようになります。

# [Genie Spaceの改善とバグ修正。](https://docs.databricks.com/aws/en/ai-bi/release-notes/2026#genie-space-enhancements-and-bug-fixes-2)
**2026-05-14**
<ul>
<li><strong>作成API命令の制限を強化</strong>：作成APIは、命令作成のためのUIと同じ制限を強制するようになりました。クエリテキストの最大文字数は、20,000文字から40,000文字に引き上げられました。</li>
<li><strong>エージェントモードで今すぐ回答 (パブリックプレビュー)</strong>：ユーザーは<strong>今すぐ回答</strong>をクリックして、エージェントモードでの推論を停止し、既存のコンテキストに基づいて回答を得ることができます。詳細は<a href="https://docs.databricks.com/aws/ja/genie/agent-mode">Genie Spacesのエージェントモード</a>を参照してください。</li>
<li><strong>エージェントモード（パブリックプレビュー）での会話に対するレビュー依頼</strong>：ユーザーはエージェントモードでの会話に対するレビューを依頼できるようになりました。詳細は<a href="https://docs.databricks.com/aws/ja/genie/monitor#response-feedback">レスポンスのフィードバック</a>を参照してください。</li>
<li><strong>会話履歴のバグ修正</strong>：会話履歴リストに現在の会話しか表示されないバグを修正しました。</li>
<li><strong>監視のためのGenie Code引用リンク</strong>：<strong>スペース利用状況の分析</strong>を使用すると、Genie Codeレスポンスに引用が含まれるようになりました。引用をクリックすると、Genie Codeスレッドで直接関連する会話が開きます。詳細は<a href="https://docs.databricks.com/aws/ja/genie/monitor#usage-trends">利用状況とトレンドのレビュー</a>を参照してください。</li>
</ul>

**ユーザーへのインパクト**

DatabricksのGenie Spaceに関するリリースノートの要点は以下の通りです。

* 作成APIの命令作成における文字数制限が40,000文字に引き上げられ、UIと同等の制限になりました。
* エージェントモードで「今すぐ回答」をクリックすることで、推論を停止し、コンテキストに基づいた回答を得ることができます（パブリックプレビュー）。
* エージェントモードでの会話に対するレビュー依頼が可能になりました（パブリックプレビュー）。
* 会話履歴リストの表示に関するバグが修正され、正しく表示されるようになりました。
* Genie Codeレスポンスに引用リンクが含まれるようになり、「スペース利用状況の分析」で利用状況の確認が容易になりました。

これらの変更により、DatabricksユーザーはGenie Spaceをより便利に利用できるようになります。特に、エージェントモードの機能強化や、会話履歴の表示バグの修正により、ユーザーエクスペリエンスが向上します。

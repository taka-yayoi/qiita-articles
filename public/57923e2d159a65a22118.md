# [自動変更データフィードが一般提供開始されました。](https://docs.databricks.com/aws/en/release-notes/product/2026/september#automatic-change-data-feed-is-now-generally-available)
**2026-09-01**
自動変更データフィード（Auto CDF）は、行レベルの追跡を使用してクエリ時に行レベルの変更を計算します。これを使用するには、Delta LakeやApache Iceberg v3の各テーブルで手動で変更データフィードを有効にする必要はありません。Auto CDFは書き込み時のオーバーヘッドをなくし、変更のためにクエリを実行するテーブルの<code>MERGE</code>および<code>UPDATE</code>操作を約15%高速化します。バッチクエリ、Structured Streaming、Delta Lake Sharingで動作し、Databricks Runtime 19 LTS以降で行レベルの追跡が有効になっていることが必要です。詳しくは<a href="https://docs.databricks.com/aws/ja/tables/features/change-data-feed#auto-cdf">自動変更データフィード</a>をご覧ください。

**ユーザーへのインパクト**

自動変更データフィード（Auto CDF）が一般提供されました。主な影響は以下の通りです：

1. 行レベルの変更をクエリ時に計算し、手動での変更データフィードの有効化が不要になります。
2. 書き込み時のオーバーヘッドがなくなり、テーブルに対する `MERGE` および `UPDATE` 操作が約15%高速化されます。
3. バッチクエリ、Structured Streaming、Delta Lake Sharingで利用可能です。
4. Databricks Runtime 14.2以降ではデフォルトで有効になっていますが、Databricks Runtime 14.1以前では手動での有効化が必要です。

これにより、Databricksユーザーはより効率的に変更データフィードを利用でき、データ処理のパフォーマンスが向上します。

Unity Gatewayは、Databricksが提供するモデルのみならず、Amazon BedrockやAzure AI Foundryなどの外部モデルプロバイダーに対する支出を追跡し、上限を設定できるようになりました。お客様の組織がすでにプロバイダーと直接キャパシティコミットメントを結んでいる場合、Unity Gatewayはその使用状況を追跡し、チームやユースケース全体での支出制限を強制するための単一のポイントとなります。これを有効にするには、アカウントコンソールのPreviewsページでExternal Model Spend in Budgets（Beta）を有効にし、Unity Gatewayリソースタイプにスコープされた予算を作成する際にInclude external model usageを選択します。

   - アカウントコンソールのPreviewsページで「External Model Spend in Budgets（Beta）」を有効にします。
   - Unity Gatewayリソースタイプにスコープされた予算を作成する際に、「Include external model usage」を選択します。

4. **詳細情報の参照先**：「Include external model usage」のドキュメントに詳細が記載されています。

この更新により、Databricksユーザーは外部モデルプロバイダーのコストをより効果的に管理し、予算の枠内でリソースを利用できるようになります。特に、複数の外部AIモデルプロバイダーを使用している組織にとっては、コスト管理が簡素化されるため有益です。

これらの変更により、Databricksユーザーはより効率的にスキルを管理し、エージェント開発を促進できます。ただし、ベータ版であるため、今後のアップデートや変更に注意する必要があります。詳細は、Unity Catalog スキルとはのドキュメントを参照してください。

# [Lakebaseストレージのクォータのデフォルトが32 TBに増加しました。](https://docs.databricks.com/aws/en/release-notes/lakebase#lakebase-storage-quota-default-increased-to-32-tb)
**2026-08-27**
<p>Lakebaseのデフォルトのデータベースストレージクォータは、従来の16TBから32TBに引き上げられました。新しいクォータは、コンピュートが次回起動または再起動したときに有効になります。すでに実行中のコンピュートについては、次の再起動まで従来のクォータが保持されます。32TBを超えるクォータについては、Databricksサポートに依頼すれば利用可能です。 <a href="https://docs.databricks.com/aws/ja/oltp/projects/manage-projects">プロジェクトの管理</a>を参照してください。</p>

**ユーザーへのインパクト**

Databricksユーザーは、Lakebaseストレージのクォータがデフォルトで32TBに増加したことによる恩恵を受けます。これにより、より大規模なデータストレージが可能になり、コンピュートの次回起動または再起動時に新しいクォータが適用されます。すでに実行中のコンピュートについては、次回の再起動まで従来のクォータが適用されます。さらに、32TBを超えるクォータが必要な場合は、Databricksサポートに依頼することができます。

<li><strong>オペレーターとグループの有効化/無効化</strong>：個々のオペレーターまたはグループ全体を無効

**ユーザーへのインパクト**

Databricks Lakeflow Designerの8月リリースでは、以下の新機能と改善がユーザーに影響を与えます：

1. **重複行の削除**: 新しいUniqueオペレーターを使用することで、重複行を簡単に削除できます。列のサブセットをキーにしたり、行を並べ替えてどの重複を保持するかを制御できます。

2. **ユニークな値のカウント**: Aggregateオペレーターで`COUNT DISTINCT`関数がサポートされ、列内のユニークな値を簡単にカウントできます。

3. **動的な列選択**: Selectオペレーターが、データ型や名前パターン、式に基づいて列を動的に選択できるようになり、入力スキーマの変更に応じて出力が適応します。

4. **プレビューと本番の分離**: Pythonオペレーターでプレビューモードがサポートされ、`config["is_preview"]`を使ってプレビュー時と本番時で異なる処理を実行できます。これにより、プレビュー時の副作用（書き込みや通知など）をスキップできます。

5. **リアルタイムのPython出力**: Pythonオペレーターの出力がリアルタイムで出力パネルにストリーミングされるようになり、実行完了前に結果を確認できます。

6. **オペレーターとグループの有効化/無効化**: 個々のオペレーターまたはグループ全体を無効化できるようになり、パイプラインのテストやデバッグが容易になります。

これらの機能強化により、Lakeflow Designerを使ったデータパイプラインの構築、テスト、運用がより柔軟かつ効率的に行えるようになります。

# [システムテーブルおよびAPIでクエリテキストはデフォルトでマスクされるようになりました。](https://docs.databricks.com/aws/en/release-notes/product/2026/august#query-text-is-now-masked-by-default-in-system-tables-and-apis)
**2026-08-26**
<p>SQL文には機密情報が含まれる可能性があるため、Databricksは以下の場所でクエリテキストをマスクするようになりました。</p>
<ul>
<li><code>system.query.history</code> の <code>statement_text</code> は <code>&#x3C;REDACTED></code> を返します。</li>
<li>クエリ履歴APIおよびリストクエリAPIの<code>query_text</code>は<code>&#x3C;REDACTED></code>を返します。</li>
<li>SQL定義を含む<code>system.access.audit</code>の<code>request_params</code>内のキーは省略されます。</li>
</ul>
<p>アカウント管理者と<code>databricks_pii_access</code> アカウントグループのメンバーは、マスクされていないクエリテキストを読むことができます。アクセス権を付与するには、アカウント管理者がグループを作成し、メンバーを追加します。<a href="https://docs.databricks.com/aws/ja/admin/system-tables/query-history#statement-text-masking">マスクされたステートメントテキストへのアクセス</a> および <a href="https://docs.databricks.com/aws/ja/admin/system-tables/audit-logs#request-params-masking">マスクされたリクエストパラメータへのアクセス</a> を参照してください。</p>

**ユーザーへのインパクト**

Databricksのリリースにより、システムテーブルおよびAPIでクエリテキストがデフォルトでマスキングされるようになりました。これにより、SQL文に含まれる可能性のある機密情報の漏洩が防止されます。具体的には、`system.query.history`の`statement_text`、`query_history` APIおよび`list_query` APIの`query_text`、`system.access.audit`の`request_params`内のSQL定義を含むキーがマスキングされます。

ただし、アカウント管理者と`databricks_pii_access`アカウントグループのメンバーには、マスキングされていないクエリテキストを読む権限が与えられています。アカウント管理者は、グループを作成し、メンバーを追加することで、このアクセス権を他のユーザーに付与することができます。

この変更により、Databricksユーザーは、機密情報を保護するために、クエリテキストへのアクセスを適切に制御する必要があります。影響を受けるユーザーは、ドキュメントを参照して、マスキングされたステートメントテキストやリクエストパラメータへのアクセス方法について確認する必要があります。

```

SCOPES = ['https://www.googleapis.com/auth/spreadsheets']
SERVICE_ACCOUNT_FILE = '/dbfs/path/to/service_account_key.json'

# Google Sheetsの認証

spreadsheet_id = 'your_spreadsheet_id'
range_name = 'Sheet1!A1:C10'
result = service.spreadsheets().values().get(spreadsheetId=spreadsheet_id, range=range_name).execute()
values = result.get('values', [])

# Pandasデータフレームに変換
df = pd.DataFrame(values[1:], columns=values[0])

# Databricksのデータフレームに変換
df_databricks = spark.createDataFrame(df)
```
4. **データを書き込む**
 Databricksのノートブックで、以下のコマンドを実行してデータを書き込みます。
```python
%python
# データを書き込む
df_databricks.write.format('delta').mode('overwrite').saveAsTable('my_table')
```

詳細については、[アイデンティティ属性](https://docs.databricks.com/aws/ja/admin/users-groups/identity-attributes)に関するドキュメントを参照してください。

# [リクエストとレスポンス内の機密データをブロックまたは編集します。](https://docs.databricks.com/aws/en/release-notes/unity-gateway#block-or-redact-sensitive-data-in-requests-and-responses)
**2026-08-13**
機密データ検出ガードレール（ベータ版）は、構造化された機密データ（社会保障番号、クレジットカード番号、IBAN、電話番号など）を検出し、インタラクションをブロックするか、一致する値をその場で編集します。検出は決定論的（正規表現とチェックサムおよびコンテキストキーワードを使用し、評価モデルは使用しない）であるため、100ターンの会話でも50ミリ秒未満の追加となり、常に同じ結果が返されます。これを使用するには、アカウントコンソールの**プレビュー**ページで**Unity Gateway拡張プレビュー**を有効にします。
このリリースには、以下の改善も含まれています。
<ul>
<li>ブロックされたインタラクションは、4xxエラーではなく、ブロック理由を含む標準のHTTP 200レスポンスを返すようになりました。これにより、履歴を再送するコーディングエージェントが、同じブロックを毎回再トリガーすることがなくなりました。</li>
<li>組み込みのLLM-as-a-judgeガードレールは、最新のメッセージだけでなく、最近の会話のターンのウィンドウまたは会話の全体の履歴を評価できるようになりました。</li>
<li>新しい実行フロー・ビューでは、ガードレールが実行される順序がエンドツーエンドで表示されます。</li>
</ul>

# [OpenSharing SecureConnect の拡張ネットワーク課金](https://docs.databricks.com/aws/en/release-notes/whats-coming#expanded-networking-billing-for-opensharing-secureconnect)
**2026-08-13**
Databricksは、OpenSharing SecureConnectのネットワーク課金を拡張する予定です。現在、データ提供者は、受信者がSecureConnectを通じて共有データにアクセスする際のデータ転送（egress）に対して課金されます。受信者への課金を含む、追加の課金タイプとアクセスシナリオが計画されています。

以下の表は、計画されている課金、誰に請求されるか、および各アクセスシナリオにどのように適用されるかをまとめたものです。

| 課金タイプ | ステータス | 異なるリージョンまたはクラウド間 | 同一リージョン（クラシックまたはオープンレシーピエント） | 同一リージョン（サーバーレスレシーピエント） |
| --- | --- | --- | --- | --- |
| データ転送 | 現在利用可能 | プロバイダーに請求 | 適用外 ¹ | 適用外 ¹ |
| プライベートコネクティビティ ² | 近日提供予定 | プロバイダーに請求 | プロバイダーに請求 | 受信者に請求 |
| パブリックコネクティビティ | 近日提供予定 | 受信者に請求 | 適用外 ³ | 適用外 ⁴ |

¹ 受信者がプロバイダーと同じリージョンにいる場合、データ転送（egress）は適用されません。
² プロバイダーがネットワークコネクティビティ設定（NCC）をメタストアにアタッチしてプライベートコネクティビティを設定している場合にのみ適用されます。
³ Databricksはこの料金を請求しません。クラシックコンピュートまたはオープンレシーピエントがパブリックネットワーク経由でストレージにアクセスする場合、クラウドプロバイダーが直接ネットワークアドレス変換（NAT）の料金を請求する可能性があります。
⁴ 同一リージョンのサーバーレス受信者は、マネージドプロキシを経由せずに直接ストレージから読み取ります。

料金については、[データ転送とコネクティビティの価格](https://www.databricks.com/product/pricing/data-transfer-connectivity) を参照するか、Databricksアカウントチームにお問い合わせください。

**ユーザーへのインパクト**

DatabricksのOpenSharing SecureConnectのネットワーク課金が拡張されます。主な変更点は以下の通りです。

1. **新しい課金タイプの導入**：プライベートコネクティビティとパブリックコネクティビティの課金が追加されます。
   - プライベートコネクティビティ：プロバイダーがネットワークコネクティビティ設定（NCC）をメタストアにアタッチしている場合に適用されます。異なるリージョンまたはクラウド間のアクセスではプロバイダーに、同一リージョンのサーバーレス受信者の場合には受信者に請求されます。同一リージョンのクラシックまたはオープンレシーピエントの場合にはプロバイダーに請求されます。
   - パブリックコネクティビティ：異なるリージョンまたはクラウド間のアクセスの場合、受信者に請求されます。同一リージョンでは適用されませんが、クラウドプロバイダーが直接ネットワークアドレス変換（NAT）の料金を請求する可能性があります。

2. **既存のデータ転送課金**：データ提供者は引き続き、異なるリージョンまたはクラウド間のデータ転送に対して課金されます。同一リージョン内でのアクセスの場合、データ転送は適用されません。

Databricksユーザーは、特にデータ提供者と受信者の両方として、以下の点に注意する必要があります。

- **コストの増加**：特にサーバーレスレシーピエントの場合、プライベートコネクティビティの料金が新たに発生します。
- **クラウドプロバイダーの料金**：パブリックコネクティビティのケースでは、クラウドプロバイダーがNAT料金を請求する可能性があります。
- **料金詳細**：Databricksの[データ転送とコネクティビティの価格ページ](https://www.databricks.com/product/pricing/data-transfer-connectivity)またはDatabricksアカウントチームに確認して、最新の料金情報を把握することが推奨されます。

これらの変更は、データ共有のコスト構造に影響を及ぼすため、ユーザーはこれらの新しい課金タイプとアクセスシナリオを理解し、自らの使用状況に応じて適切な計画を立てる必要があります。

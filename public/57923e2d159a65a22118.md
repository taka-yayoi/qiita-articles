# [Unity Catalog 管理テーブルのタイムトラベルと VACUUM の動作変更](https://docs.databricks.com/aws/en/release-notes/whats-coming#time-travel-and-vacuum-behavioral-changes-for-unity-catalog-managed-tables)
**2025-12-19**
2026年1月、Databricks Runtime 18.0で導入された<a href="https://docs.databricks.com/aws/ja-jp/delta/history#time-travel">タイムトラベル</a>と<a href="https://docs.databricks.com/aws/ja-jp/delta/vacuum">VACUUM</a>の動作変更は、サーバーレス コンピュート、Databricks SQL、およびDatabricks Runtime 12.2以降の<a href="https://docs.databricks.com/aws/ja-jp/tables/managed">Unity Catalogマネージドテーブル</a>に拡張されます。
<p>これらの変更には以下が含まれます:</p>
<ul>
<li><code>delta.deletedFileRetentionDuration</code> を超えるタイムトラベルクエリはブロックされます。</li>
<li><code>delta.logRetentionDuration</code> は、<code>delta.deletedFileRetentionDuration</code> 以上である必要があります。</li>
</ul>

**ユーザーへのインパクト**

Databricks Runtime 18.0で導入されたUnity Catalog管理テーブルにおけるタイムトラベルとVACUUMの動作変更が、2026年1月にサーバーレスコンピュート、Databricks SQL、およびDatabricks Runtime 12.2以降の環境に拡張されます。

この変更により、以下の影響があります：

1. `delta.deletedFileRetentionDuration`で指定された期間を超えたタイムトラベルクエリはブロックされます。これにより、古いデータへのアクセスが制限されます。

2. `delta.logRetentionDuration`は`delta.deletedFileRetentionDuration`以上に設定する必要があります。これにより、ログの保持期間がデータファイルの保持期間と整合するようになります。

これらの変更は、データの管理とアクセスに影響を与える可能性があるため、ユーザーはテーブル設定の確認と調整が必要です。特に、長い履歴データにアクセスしている場合は、設定の見直しが推奨されます。

# [カタログ エクスプローラーのナビゲーションの更新](https://docs.databricks.com/aws/en/release-notes/whats-coming#catalog-explorer-navigation-updates)
**2025-12-16**
カタログ エクスプローラーは近日、ワークフローを合理化し、データ アセットをより効率的に検出および管理できるよう、ナビゲーションが改善されます。
簡素化されたナビゲーション:
冗長性を減らし、単一のカタログ ナビゲーション サーフェスに焦点を当てるために、重複していたカタログ タブが削除されます。 <strong>DBFS</strong> と <strong>フィードバックの送信</strong> アクションは、よりすっきりとしたレイアウトにするためにケバブ メニュー <img src="/images/product-icons/OverflowIcon.svg" alt="Kebab menu icon."> に移動されます。
新しい候補セクション:
カタログ エクスプローラーのランディング ページに新しく <strong>候補</strong> タブが追加され、頻繁に使用されるオブジェクト、初めてのユーザー向けのサンプル オブジェクト、およびユーザーのお気に入りが強調表示されます。これにより、重要なアセットにすばやく再び関与したり、役立つ出発点を発見したりできるようになります。
統合されたエントリ ポイント:
関連する機能がよりわかりやすいカテゴリの下にグループ化され、視覚的なノイズが減り、発見しやすくなります。
<ul>
<li><strong>ガバナンス</strong> - ガバナンスが適用されたタグ、メタストア管理、データ分類のエントリ ポイント</li>
<li><strong>接続</strong> - 外部ロケーション、外部データ、資格情報、接続のエントリ ポイント</li>
<li><strong>共有</strong> - Delta Sharing とクリーン ルームのエントリ ポイント</li>
</ul>
これらのグループ化により、散在していたサブタブが置き換えられ、より直感的で拡張性の高い情報アーキテクチャが作成されます。

**ユーザーへのインパクト**

Databricksユーザーは、カタログ エクスプローラーのナビゲーションが改善されるため、以下のような影響を受けます。

* カタログタブの簡素化により、冗長性が減り、よりすっきりとしたレイアウトになります。DBFSとフィードバックの送信アクションはケバブメニューに移動します。
* 新しい「候補」タブが追加され、頻繁に使用されるオブジェクトやサンプルオブジェクトが表示され、重要なアセットにすばやくアクセスできます。
* 関連する機能が「ガバナンス」、「接続」、「共有」のカテゴリにグループ化され、視覚的なノイズが減り、発見しやすくなります。これらの変更により、データ アセットの検出と管理がより効率的になります。

# [SQL Serverのデータ取り込みパイプラインのフルリフレッシュフローを改善しました。](https://docs.databricks.com/aws/en/release-notes/product/2025/november#improved-full-refresh-flow-for-sql-server-ingestion-pipelines)
**2025-11-14**
<p>SQL Server へのデータ取り込みパイプラインのフルリフレッシュ操作により、スナップショットの完了後にテーブルリフレッシュが遅延するため、ダウンタイムが短縮されるようになりました。スナップショットプロセス中、データ到着先のストリーミングテーブルは既存のデータで利用可能なままです。新しい挿入、削除、更新は蓄積されますが、すぐには適用されません。スナップショットが完了した後、フルリフレッシュおよびその他の蓄積された変更が 1 回の更新で適用されるため、データの可用性の中断が最小限に抑えられます。この改善により、フルリフレッシュ操作中の<code>PENDING_RESET</code>エラーやタイムアウトエラーが軽減されます。「<a href="https://docs.databricks.com/aws/ja/ingestion/lakeflow-connect/sql-server-maintenance#full-refresh">フルリフレッシュの動作</a>」を参照してください。</p>

**ユーザーへのインパクト**

このリリースノートは、DatabricksのSQL Serverデータ取り込みパイプラインに関する改善について説明しています。主な影響は以下の通りです：

1. **ダウンタイムの短縮**：SQL Serverへのデータ取り込みパイプラインのフルリフレッシュ操作において、スナップショット完了後にテーブルリフレッシュが遅延するようになり、ダウンタイムが短縮されました。

2. **データの可用性向上**：スナップショット処理中も、データ到着先のストリーミングテーブルは既存のデータで利用可能なままとなります。

3. **エラーの軽減**：フルリフレッシュ操作中の`PENDING_RESET`エラーやタイムアウトエラーの発生が軽減される見込みです。

4. **変更の適用方法の変更**：スナップショット中に蓄積された変更（新規挿入、削除、更新）は、スナップショット完了後に一括で適用されるため、データの可用性の中断が最小限に抑えられます。

この改善により、SQL Serverデータ取り込みパイプラインのフルリフレッシュ処理がよりスムーズになり、データの可用性と信頼性が向上します。詳細については、ドキュメント「フルリフレッシュの動作」を参照してください。

# [ダッシュボードのフィルタとカウンターの強化](https://docs.databricks.com/aws/en/ai-bi/release-notes/2025#dashboard-filter-and-counter-enhancements)
**2025-11-06**
<ul>
<li><strong>ウィジェットごとのフィルターの強化</strong>: ウィジェットごとのフィルターが、日付範囲、相対日付範囲、数値フィルターをサポートするようになりました。</li>
<li><strong>カウンターの視覚化の改善</strong>: カウンターを使用して、時間の経過に伴うメトリクスの追跡と比較を行い、スパークラインを表示できるようになりました。スパークライン付きカウンターを作成するには、メインバリューと日付列を選択します。<a href="https://docs.databricks.com/aws/ja/dashboards/visualizations/types#counter">カウンターの視覚化</a>を参照してください。</li>
<li><strong>メトリックビューのメタデータサポート</strong>: AI/BI ダッシュボードは、フォーマットや表示名など、メトリックビューからの Unity Catalog メタデータを消費するようになりました。</li>
<li><strong>ホバーの際に水平チャートのスクロールバー表示</strong>: 水平チャートのスクロールバーがホバー時に表示されるようになりました。</li>
<li><strong>ドラフトモードでのカスタム計算表示の修正</strong>: カスタム計算を使用した視覚化がドラフトモードで表示されなかった問題を解決しました。</li>
<li><strong>Slack 通知の OAuth トークンフィールドの修正</strong>: ダッシュボードサブスクリプションの Slack 通知で事前にトークンが提供されていなかったにも関わらず、OAuth トークンフィールドにプレースホルダーテキストが事前入力されていたバグを修正しました。</li>
</ul>

**ユーザーへのインパクト**

Databricksユーザーは以下のような影響を受けます。

1. **ダッシュボードフィルタの強化**: ウィジェットごとに日付範囲、相対日付範囲、数値フィルタが利用できるようになり、ダッシュボードの柔軟性が向上しました。
2. **カウンター視覚化の改善**: カウンターにスパークラインが表示されるようになり、時系列でのメトリクスの変化を追跡できるようになりました。
3. **メトリックビューのメタデータ利用**: AI/BIダッシュボードがUnity Catalogのメタデータを利用するようになり、メトリクスのフォーマットや表示名が反映されるようになりました。
4. **水平チャートのスクロールバー表示**: 水平チャートでホバー時にスクロールバーが表示されるようになり、データの閲覧性が向上しました。
5. **カスタム計算表示の修正**: ドラフトモードでカスタム計算を使用した視覚化が正しく表示されるようになりました。
6. **Slack通知の改善**: OAuthトークンフィールドのプレースホルダーテキストの問題が修正され、セキュリティが向上しました。

これらの変更により、Databricksユーザーはより柔軟で機能的なダッシュボードを作成し、データをより効果的に分析できるようになります。

# [新しいMCPサーバータブ](https://docs.databricks.com/aws/en/release-notes/product/2025/november#new-mcp-server-tab)
**2025-11-06**
ワークスペースの新しい<strong>MCPサーバー</strong>タブには、管理対象および外部のMCPサーバーと、Databricks MarketplaceからインストールできるMCPサーバーの精選されたリストが表示されます。

「<a href="https://docs.databricks.com/aws/ja/generative-ai/mcp">DatabricksでのModel Context Protocol (MCP)</a>」を参照してください。

**ユーザーへのインパクト**

このリリースノートの変更により、DatabricksユーザーはワークスペースでMCPサーバーを簡単に管理し、Databricks Marketplaceから新しいMCPサーバーを発見してインストールできるようになります。具体的には、次のような影響があります：

1. **MCPサーバーの管理が容易に**：管理対象および外部のMCPサーバーを一元的に管理できます。
2. **MCPサーバーの検出とインストール**：Databricks Marketplaceから利用可能なMCPサーバーのリストにアクセスし、簡単にインストールできます。
3. **ドキュメントへのアクセス**：関連するドキュメント（「DatabricksでのModel Context Protocol (MCP)）が提供され、MCPの使用方法に関する詳細情報を参照できます。

これにより、ユーザーはMCPサーバーの管理と利用をより効率的に行うことができます。

# [サーバーレスノートブックタスクでジョブ環境が利用可能になりました](https://docs.databricks.com/aws/en/release-notes/product/2025/november#serverless-notebook-tasks-can-now-use-jobs-environment)
**2025-11-05**
<p>サーバーレスノートブックタスクでジョブ環境を使用する機能が一般的に利用できるようになり、ノートブックの環境を使用したり、特定のジョブ環境を選択できるようになりました。これまでは、サーバーレスノートブックタスクは常にノートブックからサーバーレス環境を継承していました。<a href="https://docs.databricks.com/aws/ja/compute/serverless/dependencies#libraries">ジョブタスクの環境を構成する</a>を参照してください。</p>

**ユーザーへのインパクト**

サーバーレスノートブックタスクでジョブ環境が利用できるようになりました。これにより、ノートブック環境の使用または特定のジョブ環境の選択が可能になります。これまでは、サーバーレスノートブックタスクは常にノートブックの環境を継承していましたが、これからはジョブごとに環境を柔軟に選択・設定できるようになります。詳細は、[ジョブタスクの環境を構成する](https://docs.databricks.com/aws/ja/compute/serverless/dependencies#libraries) を参照してください。

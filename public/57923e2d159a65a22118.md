# [Databricks Runtime 19:2026年11月16日](https://docs.databricks.com/aws/en/release-notes/runtime/19#databricks-runtime-19-november-16-2026)
**2026-11-16**
### 動作の変更

- このリリースから、リアルタイムモードの新しいストリーミングクエリでは、デフォルトでリアルタイムウォーターマークの伝播が使用されます。ステートフル演算子はバッチ内でイベント時間のウォーターマークを進めるため、遅延イベントはライブのウォーターマークに照らしてフィルタリングされ、状態は従来よりも早く削除されます。既存のチェックポイントから再起動されたクエリは、元の動作を維持します。新しいクエリで従来の動作を維持するには、クエリを開始する前に spark.databricks.streaming.realTimeMode.realTimeWatermark.enabled を false に設定してください。

### バグ修正

- オペレーティングシステムのセキュリティアップデートおよびその他の修正。

**ユーザーへのインパクト**

DBR 19以降、リアルタイムモードの新規ストリーミングクエリではリアルタイムウォーターマーク伝播がデフォルトで有効になり、バッチ内でウォーターマークが進むため、遅延イベントはより積極的にフィルタリングされ、状態も早期に削除されます。そのため、集計結果や出力件数が従来と変わる可能性があるので、新規クエリでは遅延データの扱いを検証してください。既存のチェックポイントから再起動するクエリは従来動作のままで、新規クエリで従来動作を保つには開始前に spark.databricks.streaming.realTimeMode.realTimeWatermark.enabled を false に設定します。

# [Unity Catalog のドロップされたボリュームを UNDROP VOLUME で復元する](https://docs.databricks.com/aws/en/release-notes/product/2026/november#recover-dropped-unity-catalog-volumes-with-undrop-volume)
**2026-11-07**
削除した Unity Catalog ボリュームを、7日以内であれば復元できるようになりました。`SHOW VOLUMES DROPPED` でボリュームの ID を確認し、`UNDROP VOLUME WITH ID` を実行すると、権限とタグも含めて復元されます。Databricks Runtime 19 以降が必要です。<a href="https://docs.databricks.com/aws/ja/sql/language-manual/sql-ref-syntax-ddl-undrop-volume">UNDROP VOLUME</a>を参照してください。

**ユーザーへのインパクト**

誤ってUnity Catalogのボリュームを削除しても、7日以内であれば`SHOW VOLUMES DROPPED`でIDを確認し、`UNDROP VOLUME WITH ID`で権限やタグごと復元できるようになります。ファイル資産の誤削除リスクが下がり、運用の安心感が高まります。ただしDatabricks Runtime 19以降が必要なので、利用中のクラスターのバージョンを確認してください。

2026年11月以降、AIMやアカウントレベルSCIMで追加されたユーザーは、ワークスペース割り当てやコンシューマーアクセスなしでGenie Oneを利用できるようになり、閲覧範囲はUnity Catalogで制御されます。ただし「all account users」グループに共有済みのオブジェクトにはアクセス可能になるため、事前に共有内容を見直してください。無効にしたい場合は、アカウント管理者がアカウント設定で「Account-only users in Genie One」をオフにします。

**2026-11-05**
<p>Databricks CLI の <code>compute-migrations</code> コマンドグループを使用して、Genie Migrate for Serverless により、クラシックジョブをバックグラウンドでサーバレスコンピュートに移行できるようになりました。ジョブごとに、エージェントがサーバレス版の作業用コピーを作成します。このコピーを確認して承認すると、元のジョブが変更されます。必要に応じて、作業用コピーを一度実行して検証することもできます。複数のジョブを移行するには、スクリプトからジョブごとに 1 つの移行を作成します。Genie Migrate for Serverless は Genie Code でも利用でき、<code>/compute</code> を実行して単一のノートブックまたはジョブを移行できます。ワークスペース管理者は、<a href="https://docs.databricks.com/aws/ja/admin/workspace-settings/manage-previews"><strong>プレビュー</strong>ページ</a>で <strong>Compute Agent</strong> プレビューにオプトインすることで、どちらも有効にできます。<a href="https://docs.databricks.com/aws/ja/compute/serverless/migration#agent-migrate-cli">Databricks CLI でジョブを移行する</a>を参照してください。</p>

**ユーザーへのインパクト**

Genie Migrate for Serverlessのベータ版により、Databricks CLIのcompute-migrationsコマンドで、クラシックジョブをサーバレスコンピュートへバックグラウンドで移行できます。エージェントがジョブごとにサーバレス版の作業用コピーを作り、確認と承認をすると元のジョブが更新され、事前に一度実行して検証することも可能です。Genie Codeでは/computeでノートブックやジョブを移行でき、利用にはワークスペース管理者がプレビューページでCompute Agentにオプトインする必要があります。

Smart Routing は、最初のプロンプトではなくサブエージェントのみをルーティングするようになりました。社内ベンチマークではコストが最大 70% 削減され、p90 のルーティングレイテンシが 9 秒から 2 秒に短縮されます。Codex 向けの Smart Routing は一時停止中です。<a href="https://docs.databricks.com/aws/ja/ai-gateway/coding-agent-model-selection">モデルの選択または Smart Routing の使用</a>をご覧ください。

**ユーザーへのインパクト**

AI Gatewayのコーディングエージェント向けSmartR routing（ベータ版）が、最初のプロンプトではなくサブエージェントのみをルーティングする方式に変わり、社内ベンチマークでコストが最大70%削減、p90レイテンシが9秒から2秒に短縮されます。ユーザーは設定変更なしで高速化とコスト低減の恩恵を受けられますが、最初のプロンプトは自動でルーティングされなくなるため、使用モデルを意識して選択する必要があります。Codex向けのSmart Routingは一時停止中なので、Codexを利用中の方は手動でモデルを指定してください。

# [ダッシュボードの機能強化とバグの修正](https://docs.databricks.com/aws/en/ai-bi/release-notes/2026#dashboard-enhancements-and-bug-fixes)
**2026-11-05**
* **ダッシュボード変数の並べ替え**: 作成者はダッシュボードエディタでダッシュボード変数を直接並べ替えることができるようになりました。「[ダッシュボード変数を使用する](/aws/ja/dashboards/manage/filters/dashboard-variables)」を参照してください。
* **フィールド変数オプションの表示名**: 作成者は、フィールド変数の各オプション（たとえば、**売上合計**の代わりに**総収益**）の表示名を設定できるようになりました。Genie Codeに、これらの表示名の設定、名前の変更、またはクリアを依頼することもできます。また、Genie Codeは、変数を編集するときに、設定した名前を保持します。「[フィールドオプションの表示名を設定する](/aws/ja/dashboards/manage/filters/dashboard-variables#option-display-names)」を参照してください。
* **Genie CodeでUnity Catalogからリレーションシップをインポート（ベータ）**: ダッシュボード作成用のGenie Codeは、Unity Catalogメトリクスビューのリレーションシップ宣言をダッシュボードのリレーションシップとしてインポートできるようになりました。「[ダッシュボード作成にGenie Codeのリレーションシップを使用する](/aws/ja/uc-semantics/metric-views/relationships#genie-code)」を参照してください。
* **ウォーターフォールチャートのラベル**: ウォーターフォールチャートのラベルは、軸の上部または下部に近づいても表示されたままになります。

**ユーザーへのインパクト**

このリリースノートによると、Databricksユーザーはダッシュボードの機能強化を利用できます。主要な変更点は以下の通りです：

1. ダッシュボード変数の並べ替えが可能になり、エディタでの整理が容易になりました。
2. フィールド変数のオプションに表示名を設定できるようになり、わかりやすいラベルを使用できます。
3. Genie CodeでUnity Catalogからリレーションシップをインポートできるようになり（ベータ）、ダッシュボード作成がより効率化されます。
4. ウォーターフォールチャートのラベル表示が改善され、軸の端でも消えなくなりました。

これらの変更により、ダッシュボードの作成と管理がより柔軟かつ直感的になります。

# [仕事のためのAI機能タスク（ベータ版）](https://docs.databricks.com/aws/en/release-notes/product/2026/november#ai-function-tasks-for-jobs-beta)
**2026-11-04**
DatabricksのジョブにAI Functionタスクを追加し、SQLを書かずにボリューム内のファイルやテーブルの行に対して<code>ai_parse_document</code>、<code>ai_extract</code>、または<code>ai_classify</code>を実行できるようになりました。各実行では、前回の実行以降に新規または変更された入力のみが処理され、結果はUnity Catalogテーブルに書き込まれます。このテーブルは後続のタスクで読み取ることができます。この機能は<a href="https://docs.databricks.com/aws/ja/release-notes/release-types">ベータ版</a>です。詳細については、<a href="https://docs.databricks.com/aws/ja/jobs/tasks/ai-functions">ジョブにおけるAI Functionタスク</a>を参照してください。

**ユーザーへのインパクト**

DatabricksのジョブにAI Functionタスク（ベータ版）が追加されました。これにより、SQLを書かずにボリューム内のファイルやテーブルの行に対してAI関数（`ai_parse_document`、`ai_extract`、`ai_classify`）を実行できます。前回の実行以降に新規または変更された入力のみが処理され、結果はUnity Catalogテーブルに保存されます。この機能により、AIを活用したデータ処理が容易になり、後続のタスクで結果を活用できます。詳細はドキュメント（https://docs.databricks.com/aws/ja/jobs/tasks/ai-functions）を参照してください。

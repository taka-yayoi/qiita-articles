# [Databricks JDBC ドライバー2.8.0が利用可能です](https://docs.databricks.com/aws/en/release-notes/product/2026/march#databricks-jdbc-driver-280-is-available)
**2026-03-18**
<p><a href="https://docs.databricks.com/aws/ja/integrations/jdbc">Databricks JDBC ドライバー</a> バージョン 2.8.0 が<a href="https://docs.databricks.com/https://databricks.com/spark/jdbc-drivers-download">ダウンロード</a>できるようになりました。 新しいバージョンには以下の新機能が含まれています:</p>
<ul>
<li>Simple Logging Facade for Java (SLF4J) のバージョンを1.7.36から2.0.13にアップグレードし、標準のSLF4Jの使用方法に合わせるために<code>slf4j-api</code>をルートパッケージパスに移動しました。ドライバーはLog4jに依存しなくなりました。</li>
<li>接続プロパティ<code>EnableTelemetry</code>がデフォルトで有効になりました。ドライバーは、ワークスペースがテレメトリーを許可している場合にのみテレメトリーを送信します。</li>
</ul>
<p>このリリースには、以下のバグ修正も含まれています:</p>
<ul>
<li>ドライバーが設定されたログパスに書き込めないときに表示されるエラーメッセージが正しくない問題を修正しました。</li>
<li>認証を必要としないHTTPプロキシを使用した際の接続障害を修正しました。</li>
</ul>

**ユーザーへのインパクト**

Databricks JDBCドライバー2.8.0のリリースにより、以下の影響があります：
1. SLF4Jのバージョンが1.7.36から2.0.13にアップグレードされ、ドライバーのルートパッケージパスに`slf4j-api`が移動しました。これにより、標準的なSLF4Jの使用方法に合わせられます。また、Log4jへの依存がなくなりました。ユーザーはドライバーのログ設定を見直す必要があります。
2. `EnableTelemetry`がデフォルトで有効になりましたが、テレメトリーはワークスペースがテレメトリーを許可している場合にのみ送信されます。
3. 2つのバグが修正されました。1つはログパスへの書き込みエラーメッセージの修正、もう1つは認証不要のHTTPプロキシを使用した際の接続障害の修正です。これにより、ドライバーの安定性が向上します。

# [VPCエンドポイントAPIレスポンスでuse_caseフィールドを使用するように変更](https://docs.databricks.com/aws/en/release-notes/whats-coming#change-to-use_case-field-in-vpc-endpoint-api-responses)
**2026-02-24**
<p>今後のリリースで、VPCエンドポイントCRUDレスポンスJSONの<code>use_case</code>フィールドが<code>WORKSPACE_ACCESS</code>から<code>GENERAL_ACCESS</code>に変更されます。この変更はほとんどのユーザーに影響を与えるものではありません。</p>
<p>詳細は、<a href="https://docs.databricks.com/api/account/vpcendpoints">VPCエンドポイントAPI</a>および<a href="https://docs.databricks.com/aws/ja/security/network/classic/vpc-endpoints">VPCエンドポイント登録の管理</a>を参照してください。</p>

**ユーザーへのインパクト**

このリリースノートは、DatabricksのVPCエンドポイントAPIに関する変更を伝えています。変更内容とユーザーへの影響は以下の通りです：

- VPCエンドポイントのCRUD（作成、読み取り、更新、削除）レスポンスJSONにおける`use_case`フィールドの値が、`WORKSPACE_ACCESS`から`GENERAL_ACCESS`に変更されます。
- この変更は**ほとんどのユーザーに影響を与えない**とされていますが、VPCエンドポイントAPIや関連する機能を使用している場合は注意が必要です。
- 詳細については、Databricksのドキュメント（VPCエンドポイントAPIおよびVPCエンドポイント登録の管理）が参照されています。

つまり、ほとんどのDatabricksユーザーにとって、この変更は直接的な影響を及ぼさない可能性が高いですが、VPCエンドポイントAPIを利用している場合は、今後のリリースに備えてAPIレスポンスの変更に注意を払う必要があります。

**ユーザーへのインパクト**

AI Gateway（ベータ）は、豊富な UI、改善された可観測性、拡張された API カバレッジなど、強化された機能を備えた LLM エンドポイントおよびコーディングエージェントを管理するためのエンタープライズコントロールプレーンです。
詳細については、<a href="https://docs.databricks.com/aws/ja/ai-gateway/overview-beta">AI Gateway（ベータ）</a>をご覧ください。

**ユーザーへのインパクト**

Databricks AIゲートウェイ（ベータ版）の新機能により、大規模言語モデル（LLM）エンドポイントとコーディングエージェントの管理が強化されます。主な利点は以下の通りです：

1. **強化されたエンタープライズコントロールプレーン**：LLMエンドポイントとコーディングエージェントを一元管理できます。
2. **豊富なUI**：ユーザインターフェースが改善され、管理作業が容易になります。
3. **改善された可観測性**：LLMエンドポイントとコーディングエージェントの監視とトラブルシューティングが容易になります。
4. **拡張されたAPIカバレッジ**：より多くのAPIがサポートされ、柔軟性が向上します。

これらの機能強化により、DatabricksユーザーはLLMエンドポイントとコーディングエージェントをより効率的に管理し、可観測性を向上させることができます。詳細については、Databricksのドキュメントを参照してください。

# [Genie（ジェニー）の機能強化と改良点](https://docs.databricks.com/aws/en/ai-bi/release-notes/2026#genie-enhancements-and-improvements-2)
**2026-02-12**
<ul>
<li><strong>ヒートマップとサンキーの視覚化</strong>: Genieでヒートマップとサンキーの視覚化を生成できるようになりました。</li>
<li><strong>ベンチマークのクエリタグ付け</strong>: クエリ履歴において、Genieはベンチマークから生成されたクエリにクエリタグを付与し、エンドユーザーからのワークロードとベンチマークを区別するのに役立ちます。</li>
<li><strong>スペースタイトルの自動生成</strong>: スペースタイトルは、選択したテーブルのコンテキストに基づいて自動的に生成されるようになりました。</li>
<li><strong>ナレッジストアの提案を永続化</strong>: ナレッジストアの提案はメッセージに永続化されるようになったため、Genie内の他のタブに移動して戻ってくる前に提案を受け入れることができます。</li>
<li><strong>ダウンロード時のナレッジストアへの追加提案</strong>: Genieは、クエリ結果をダウンロードする際にナレッジストアへの追加を提案するようになりました。</li>
<li><strong>検査モード（ベータ版）</strong>: 検査モードがベータ版になりました。このモードでは、最初に生成されたSQLをレビューし、クエリの特定の側面を検証するために小さなSQLステートメントを作成し、必要に応じて改善されたSQLを生成することで、標準のGenieの精度を自動的に向上させます。<a href="https://docs.databricks.com/aws/ja/genie#inspect-mode">検査モードを使用してレスポンスの精度を向上させる</a> を参照してください。</li>
<li><strong>テーブル数の制限増加</strong>: Genieスペースのテーブル数の制限が25から30に増加しました。</li>
</ul>

**ユーザーへのインパクト**

Genieの新機能と改良点は、Databricksユーザーに以下のような影響をもたらします：

*   ヒートマップとサンキーダイアグラムの視覚化がサポートされ、データの理解が深まります。
*   クエリ履歴でベンチマーククエリがタグ付けされるため、ワークロードとベンチマーククエリの区別が容易になります。
*   スペースタイトルが自動生成されるため、スペース作成の手間が省けます。
*   ナレッジストアの提案がメッセージ内に保存されるため、他のタブに移動しても提案が保持されます。
*   クエリ結果のダウンロード時にナレッジストアへの追加が提案され、簡単にナレッジを蓄積できます。
*   検査モード（ベータ版）が利用可能になり、生成されたSQLのレビューと改善が可能になり、Genieの精度が向上します。
*   Genieスペースで利用可能なテーブルの数が25から30に増加し、より多くのデータを扱えるようになりました。

これらの変更により、Genieの機能性と使い勝手が向上し、ユーザーがより効率的にデータ分析を行えるようになります。

**2026-02-11**
Databricks SQL バージョン 2025.40 が **プレビュー** チャンネルで利用できるようになりました。新しい機能、動作の変更、バグ修正については、次のセクションを参照してください。

### SQL スクリプティングが一般提供開始

<a href="https://docs.databricks.com/aws/ja/sql/language-manual/sql-ref-scripting">SQL スクリプティング</a>が一般提供開始されました。条件文、ループ、ローカル変数、例外処理を含む、手続き的なロジックを SQL で記述できるようになりました。

### より多くの SQL コンテキストでパラメータマーカーがサポートされるようになりました

名前付き（`:param`）および名前なし（`?`）のパラメータマーカーを、適切なタイプのリテラル値が許可されている場所であればどこでも使用できるようになりました。これには、`CREATE VIEW v AS SELECT ? AS c1` などの DDL ステートメント、`DECIMAL(:p, :s)` などのカラムタイプ、`COMMENT ON t IS :comment` などのコメントが含まれます。これにより、SQL インジェクション攻撃にコードをさらすことなく、さまざまな SQL ステートメントをパラメータ化できます。詳細は、<a href="https://docs.databricks.com/aws/ja/sql/language-manual/sql-ref-parameter-marker">パラメータマーカー</a>を参照してください。

### IDENTIFIER 句がより多くの SQL コンテキストで拡張されました

文字列を SQL オブジェクト名にキャストする `IDENTIFIER` 句が、識別子が許可されているほぼすべてのコンテキストでサポートされるようになりました。拡張されたパラメータマーカーとリテラル文字列の結合サポートと組み合わせることで、カラムエイリアス（`AS IDENTIFIER(:name)`）からカラム定義（`IDENTIFIER(:pk) BIGINT NOT NULL`）まで、あらゆるものをパラメータ化できます。詳細は、<a href="https://docs.databricks.com/aws/ja/sql/language-manual/sql-ref-names-identifier-clause">IDENTIFIER 句</a>を参照してください。

**ユーザーへのインパクト**

Databricks SQL バージョン 2025.40 のリリースにより、以下の新機能が導入され、Databricks ユーザーに影響を及ぼします。

1. **SQL スクリプティングの一般提供開始**: 条件文、ループ、ローカル変数、例外処理などの手続き的なロジックを SQL で記述できるようになりました。これにより、複雑なデータ処理タスクの実装が容易になります。

2. **パラメータマーカーのサポート拡張**: 名前付きおよび名前なしのパラメータマーカーを、リテラル値が許可されているほとんどの SQL コンテキストで使用できるようになりました。これにより、さまざまな SQL ステートメントをパラメータ化し、SQL インジェクション攻撃のリスクを軽減できます。

# [新しいジョブコンピュートのデフォルトが「自動」アクセスモードに](https://docs.databricks.com/aws/en/release-notes/product/2026/november#new-jobs-compute-defaults-to-auto-access-mode)
**2026-11-09**
UIで新しいジョブコンピュートを作成する際、アクセスモードのデフォルトが「Dedicated」から「Auto」に変更されました。Auto は、機械学習ランタイム、GPU インスタンスタイプ、または 14.3 より前の Databricks Runtime バージョンが選択されている場合を除き、「Standard」アクセスモードを使用します。別のアクセスモードを強制するクラスターポリシーがある場合は、引き続きそちらが優先されます。既存のジョブは変更されません。

<a href="https://docs.databricks.com/aws/ja/security/privacy/security-profile">コンプライアンスセキュリティプロファイル</a>が有効なワークスペースでは、この変更は 2026 年 12 月に適用されます。<a href="https://docs.databricks.com/aws/ja/release-notes/whats-coming#jobs-compute-auto-access-mode-csp">今後の予定</a>を参照してください。

<a href="https://docs.databricks.com/aws/ja/jobs/run-classic-jobs#use-standard-access-mode">標準アクセスモードの使用</a>を参照してください。

**ユーザーへのインパクト**

UIで新規ジョブコンピュートを作成する際の既定アクセスモードが、DedicatedからAutoに変わり、通常はStandardが選ばれます。ただしMLランタイム、GPUインスタンス、DBR 14.3未満ではDedicatedのままとなり、クラスターポリシーの指定が優先され、既存ジョブは影響を受けません。Standardでは一部の機能に制約（RDDやカスタムライブラリなど）があるため、新規ジョブでは動作確認をお勧めします。コンプライアンスセキュリティプロファイル有効のワークスペースには2026年12月から適用されます。

* **ダッシュボード変数の並べ替え**: 作成者はダッシュボードエディタでダッシュボード変数を直接並べ替えることができるようになりました。「[ダッシュボード変数を使用する](/aws/ja/dashboards/manage/filters/dashboard-variables)」を参照してください。
* **フィールド変数オプションの表示名**: 作成者は、フィールド変数の各オプション（たとえば、**売上合計**の代わりに**総収益**）の表示名を設定できるようになりました。Genie Codeに、これらの表示名の設定、名前の変更、またはクリアを依頼することもできます。また、Genie Codeは、変数を編集するときに、設定した名前を保持します。「[フィールドオプションの表示名を設定する](/aws/ja/dashboards/manage/filters/dashboard-variables#option-display-names)」を参照してください。
* **Genie CodeでUnity Catalogからリレーションシップをインポート（ベータ）**: ダッシュボード作成用のGenie Codeは、Unity Catalogメトリクスビューのリレーションシップ宣言をダッシュボードのリレーションシップとしてインポートできるようになりました。「[ダッシュボード作成にGenie Codeのリレーションシップを使用する](/aws/ja/uc-semantics/metric-views/relationships#genie-code)」を参照してください。
* **ウォーターフォールチャートのラベル**: ウォーターフォールチャートのラベルは、軸の上部または下部に近づいても表示されたままになります。

**ユーザーへのインパクト**

このリリースノートによると、Databricksユーザーはダッシュボードの機能強化を利用できます。主要な変更点は以下の通りです：

1. ダッシュボード変数の並べ替えが可能になり、エディタでの整理が容易になりました。
2. フィールド変数のオプションに表示名を設定できるようになり、わかりやすいラベルを使用できます。
3. Genie CodeでUnity Catalogからリレーションシップをインポートできるようになり（ベータ）、ダッシュボード作成がより効率化されます。
4. ウォーターフォールチャートのラベル表示が改善され、軸の端でも消えなくなりました。

これらの変更により、ダッシュボードの作成と管理がより柔軟かつ直感的になります。

# [AI機能を使用するには、Databricks Runtime 17.3 LTS以降が必要です。](https://docs.databricks.com/aws/en/release-notes/whats-coming#ai-functions-require-databricks-runtime-173-lts-or-above)

* シングルフィールドフィルターのデフォルト値がフィールド変更時にクリアされ、**All** または **None** にフォールバックするようになりました。
* ウィジェットレベルのフィルターの値が、ブラウザーの更新なしでデータセット変更時に更新されるようになりました。
* カスタムテーマが、クエリの表示ダイアログなどの一部要素に適用されなくなり、組み込みテーマと一貫した動作になりました。
* チャートをファネルチャートに変更する際に、フィールドが引き継がれるようになりました。
* タブ付きエディタのポップオーバーの高さが、開いたときのサイズを維持するようになりました。

これらの変更により、Databricksダッシュボードの使い勝手と一貫性が向上します。

# [Unity Catalog REST API のいくつかの操作に対するページ分割されていないリクエストは、近日中に拒否されるようになります。](https://docs.databricks.com/aws/en/release-notes/whats-coming#unpaginated-requests-to-some-unity-catalog-rest-api-operations-will-soon-be-rejected)
**2026-10-28**
Databricksは近日中に、リストカタログ、リストスキーマ、リストテーブルなどの一部のUnity Catalog REST API操作に対するページ分割されていないリクエストをHTTP<code>400</code>レスポンスで拒否し始めます。これ以前は、これらの操作に対するページ分割されていないリクエストは、段階的に厳しくなるレート制限の対象となり、HTTP <code>429</code> レスポンスを受け取る可能性があり、再試行によりジョブの実行が遅くなったり、クライアントがこれらのエラーを処理しない場合はジョブが失敗する可能性がありました。これらの操作のページ分割された形式は引き続き利用可能です。

これらの操作を直接呼び出す場合は、クライアントを更新して<code>max_results=0</code>を設定し、すべてのページが取得されるまで<code>next_page_token</code>で続きを取得するようにしてください。Databricks SDK または Databricks CLI を使用している場合は、デフォルトでこれらのフィールドを使用する最新リリースにアップグレードしてください。

影響を受ける操作の完全なリストと更新手順については、「Unity Catalog REST API 操作のページ分割」を参照してください。

- Unity Catalog REST APIのリストカタログ、リストスキーマ、リストテーブルなどの操作を直接呼び出しているユーザーは、クライアントを更新してページング処理(`max_results`と`next_page_token`の使用)を実装する必要があります。さもないと、近日中にHTTP `400`エラーを受け取ることになります。
- Databricks SDKまたはDatabricks CLIを使用しているユーザーは、最新リリースにアップグレードすることでデフォルトでページング処理が有効になり、影響を回避できます。
- 詳細と影響を受ける操作のリストについては、「Unity Catalog REST API 操作のページ分割」を参照する必要があります。

# [Unity Catalog ボリューム用のFiles API 3.0がベータ版になりました。](https://docs.databricks.com/aws/en/release-notes/product/2026/october#files-api-30-for-unity-catalog-volumes-is-now-in-beta)
**2026-10-23**
Files API 3.0 は <a href="https://docs.databricks.com/aws/ja/release-notes/release-types">ベータ版</a>であり、2 つの新しい機能が導入されています。
* マルチパート アップロード: Unity Catalog ボリュームに 5 GB を超えるファイルをアップロードします。
* 条件付き操作: 意図しない変更を防ぐために、現在のバージョンに基づいてファイルのアップロード、ダウンロード、削除を行います。

**ユーザーへのインパクト**

1. **5GBを超えるファイルのアップロードが可能に**：マルチパートアップロード機能により、それまでサイズ制限によりアップロードできなかった大容量ファイルの取り扱いが可能になります。これにより、大規模なデータセットや大きなファイルをUnity Catalogボリュームに簡単にアップロードできます。

これらの新機能により、Databricksユーザーはより効率的かつ安全にUnity Catalogボリュームを操作できるようになります。特に、大規模データの取り扱いや、チームでの共同作業が頻繁に行われる環境において、その利点が活かされるでしょう。詳細な操作方法やAPIの仕様については、Databricksのドキュメント「Files APIとは？」を参照することをお勧めします。

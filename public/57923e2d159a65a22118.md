**ユーザーへのインパクト**

サービスプリンシパル向けOAuth On-Behalf-Of(OBO)がGAとなり、既定で有効になったため、管理者がプレビューページで有効化する作業は不要です。Service Principal Managerロールを持つユーザーは、OAuthシークレットを発行せずに標準のU2M OAuthフローでそのサービスプリンシパルとして認証できます。シークレットの発行・ローテーション・保管の負担と漏洩リスクが減るので、開発や検証での利用では必要なユーザーに同ロールが付与されているかを確認してください。

<a href="https://docs.databricks.com/aws/ja/genie/genie-ontology">Genie Ontology</a>が<a href="https://docs.databricks.com/aws/ja/release-notes/release-types">一般提供</a>になりました。Genie Ontologyは、Genie One、Genie Code、その他のAIエージェントに、組織のビジネスを理解したマップを提供するコンテキストレイヤーです。<a href="https://docs.databricks.com/aws/ja/uc-semantics">Unity Catalog セマンティクス</a>で定義したモデル化された知識と、Genieがお客様のアセットや利用状況から抽出する学習済みの知識を組み合わせています。

**ユーザーへのインパクト**

# [Genie Search が一般提供を開始しました](https://docs.databricks.com/aws/en/release-notes/product/2026/november#genie-search-is-now-generally-available)
**2026-11-09**
<a href="https://docs.databricks.com/aws/ja/genie/genie-ontology/search-index">Genie Search</a>が一般提供(GA)になりました。Genie Searchは、Google Drive、Jira、Confluence、Workdayなどのソースにある組織のナレッジをインデックス化するため、Genie Oneでそれらすべてのナレッジを一箇所で検索できます。Databricksは各ドキュメントの権限をコンテンツとともにインデックス化し、両方を最新の状態に保つため、ユーザーにはソースで既にアクセス権を持っているドキュメントのみが表示されます。

Genie Searchは、Genie Oneの次の機能も支えています。

- 組織ディレクトリ: チームメイトを探したり、組織図を閲覧したり、Workdayのプロフィールを表示したりできます。<a href="https://docs.databricks.com/aws/ja/genie-one/people">Genie Oneで組織ディレクトリを閲覧する</a>を参照してください。
- Discoverでの検索: Databricksのアセットや接続済みソースのコンテンツを一箇所で検索できます。<a href="https://docs.databricks.com/aws/ja/genie-one/search">Genie OneでGenie Searchを使用する</a>を参照してください。

Databricksでは、Genie Searchを<a href="https://docs.databricks.com/aws/ja/genie-one/external-sources">MCPコネクタ</a>と併用することを推奨しています。MCPコネクタを使用すると、Genie Oneがチームで使用しているアプリケーション内のライブデータにアクセスし、アクションを実行できます。

**ユーザーへのインパクト**

Genie SearchがGAとなり、Google Drive、Jira、Confluence、Workdayなどの社内ナレッジをGenie Oneから横断検索できるようになります。ドキュメントの権限も一緒にインデックス化されるため、ユーザーはソースで既に閲覧権限を持つ情報だけが表示され、セキュリティ面も安心です。組織ディレクトリやDiscover検索も利用でき、ライブデータの参照や操作にはMCPコネクタとの併用が推奨されます。

# [新しいジョブコンピュートのデフォルトが「自動」アクセスモードに](https://docs.databricks.com/aws/en/release-notes/product/2026/november#new-jobs-compute-defaults-to-auto-access-mode)
**2026-11-09**
UIで新しいジョブコンピュートを作成する際、アクセスモードのデフォルトが「Dedicated」から「Auto」に変更されました。Auto は、機械学習ランタイム、GPU インスタンスタイプ、または 14.3 より前の Databricks Runtime バージョンが選択されている場合を除き、「Standard」アクセスモードを使用します。別のアクセスモードを強制するクラスターポリシーがある場合は、引き続きそちらが優先されます。既存のジョブは変更されません。

<a href="https://docs.databricks.com/aws/ja/security/privacy/security-profile">コンプライアンスセキュリティプロファイル</a>が有効なワークスペースでは、この変更は 2026 年 12 月に適用されます。<a href="https://docs.databricks.com/aws/ja/release-notes/whats-coming#jobs-compute-auto-access-mode-csp">今後の予定</a>を参照してください。

<a href="https://docs.databricks.com/aws/ja/jobs/run-classic-jobs#use-standard-access-mode">標準アクセスモードの使用</a>を参照してください。

**ユーザーへのインパクト**

UIで新規ジョブコンピュートを作成する際の既定アクセスモードが、DedicatedからAutoに変わり、通常はStandardが選ばれます。ただしMLランタイム、GPUインスタンス、DBR 14.3未満ではDedicatedのままとなり、クラスターポリシーの指定が優先され、既存ジョブは影響を受けません。Standardでは一部の機能に制約（RDDやカスタムライブラリなど）があるため、新規ジョブでは動作確認をお勧めします。コンプライアンスセキュリティプロファイル有効のワークスペースには2026年12月から適用されます。

これらの変更により、ダッシュボードの作成と管理がより柔軟かつ直感的になります。

# [Unity Catalogのシークレットに対する上限の引き上げとBROWSE権限のサポート](https://docs.databricks.com/aws/en/release-notes/product/2026/november#higher-limits-and-browse-support-for-unity-catalog-secrets)
**2026-11-02**
スキーマは最大1,000個のUnity Catalogシークレットを保持できるようになり、メタストアは最大10,000個まで保持できるようになりました（従来の制限はそれぞれ100と1,000）。これらの制限は、Databricksが管理するシークレット、およびAWS Secrets Managerによってバックアップされたシークレットに適用されます。カタログに対する<code>BROWSE</code>権限は、Unity Catalogシークレットに適用されるようになったため、ユーザーは値の読み取りやコード内のシークレットの参照はできませんが、シークレットとそのメタデータを検出できます。詳細は<a href="https://docs.databricks.com/aws/ja/security/secrets/unity-catalog-secrets#privileges-for-uc-secrets">Unity Catalogシークレットの権限</a>を参照してください。

**ユーザーへのインパクト**

Unity Catalogのシークレットに関する変更点とDatabricksユーザーへの影響は以下の通りです：

1. Unity Catalogシークレットの上限が引き上げられました。 
   - スキーマあたりのシークレットの最大数が100から1,000に増加しました。
   - メタストアあたりのシークレットの最大数が1,000から10,000に増加しました。

2. `BROWSE`権限がUnity Catalogシークレットに適用されるようになりました。これにより、ユーザーはシークレットの存在とメタデータを閲覧できますが、シークレットの値の読み取りやコードでの参照はできません。

これらの変更により、Databricksユーザーはより多くのシークレットを管理できるようになり、シークレットの検出が容易になります。ただし、`BROWSE`権限を持つユーザーはシークレットの値を直接アクセスすることはできません。

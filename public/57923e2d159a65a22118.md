**2026-10-29**
* **シングルフィールドフィルターのデフォルト**：シングルフィールドフィルターのフィールドを変更すると、前のフィールドのデフォルト値がクリアされるようになりました。フィルターは **All** にフォールバックします。**All** が許可されていない場合は **None** になります。
* **ウィジェットレベルのフィルターの更新**：ウィジェットレベルのフィルターの値は、ブラウザーを更新しなくても、データセットが変更されると更新されるようになりました。詳細については、[フィールドでフィルターする](/aws/ja/dashboards/manage/filters/field-filters) を参照してください。
* **カスタムテーマの範囲**：組み込みテーマの動作と一致させるため、カスタムテーマは、**クエリの表示** ダイアログ、ウィジェットコンテキストメニュー、データ参照ポップオーバーを色付けしなくなりました。
* **ファネルチャートフィールド**：チャートをファネルチャートに変更したり、ファネルチャートから変更したりすると、フィールドが引き継がれるようになりました。詳細については、[ファネルチャート](/aws/ja/dashboards/manage/visualizations/types#funnel) を参照してください。
* **タブ付きエディタのポップオーバーの高さ**：タブ付きエディタのポップオーバーは、サイズが拡大せず、開いたときの高さを維持するようになりました。

**ユーザーへのインパクト**

このリリースノートでは、Databricksダッシュボードに関するいくつかのバグ修正と改善が記載されています。Databricksユーザーへの影響は以下の通りです：

* シングルフィールドフィルターのデフォルト値がフィールド変更時にクリアされ、**All** または **None** にフォールバックするようになりました。
* ウィジェットレベルのフィルターの値が、ブラウザーの更新なしでデータセット変更時に更新されるようになりました。
* カスタムテーマが、クエリの表示ダイアログなどの一部要素に適用されなくなり、組み込みテーマと一貫した動作になりました。
* チャートをファネルチャートに変更する際に、フィールドが引き継がれるようになりました。
* タブ付きエディタのポップオーバーの高さが、開いたときのサイズを維持するようになりました。

これらの変更により、Databricksダッシュボードの使い勝手と一貫性が向上します。

Databricksは近日中に、リストカタログ、リストスキーマ、リストテーブルなどの一部のUnity Catalog REST API操作に対するページ分割されていないリクエストをHTTP<code>400</code>レスポンスで拒否し始めます。これ以前は、これらの操作に対するページ分割されていないリクエストは、段階的に厳しくなるレート制限の対象となり、HTTP <code>429</code> レスポンスを受け取る可能性があり、再試行によりジョブの実行が遅くなったり、クライアントがこれらのエラーを処理しない場合はジョブが失敗する可能性がありました。これらの操作のページ分割された形式は引き続き利用可能です。

これらの操作を直接呼び出す場合は、クライアントを更新して<code>max_results=0</code>を設定し、すべてのページが取得されるまで<code>next_page_token</code>で続きを取得するようにしてください。Databricks SDK または Databricks CLI を使用している場合は、デフォルトでこれらのフィールドを使用する最新リリースにアップグレードしてください。

影響を受ける操作の完全なリストと更新手順については、「Unity Catalog REST API 操作のページ分割」を参照してください。

**ユーザーへのインパクト**

Databricksユーザーに対する影響は以下の通りです：

- Unity Catalog REST APIのリストカタログ、リストスキーマ、リストテーブルなどの操作を直接呼び出しているユーザーは、クライアントを更新してページング処理(`max_results`と`next_page_token`の使用)を実装する必要があります。さもないと、近日中にHTTP `400`エラーを受け取ることになります。
- Databricks SDKまたはDatabricks CLIを使用しているユーザーは、最新リリースにアップグレードすることでデフォルトでページング処理が有効になり、影響を回避できます。
- 詳細と影響を受ける操作のリストについては、「Unity Catalog REST API 操作のページ分割」を参照する必要があります。

# [アカウントレベルのセキュリティ機能が一般提供開始時点でデフォルトで利用できるようになりました。](https://docs.databricks.com/aws/en/release-notes/product/2026/october#account-level-security-features-are-now-available-by-default-at-ga)
**2026-10-26**

なぜこの変更を行うのか？この変更により、新しいセキュリティ機能が一般に利用可能になるとすぐに、プラットフォームチームがセキュリティのベストプラクティスを簡単に発見し、採用できるようになります。これらの機能を利用できるようにしても、アカウントのセキュリティ設定が自動的に変更されたり、新しい制御が強制されたりすることはありません。アカウント管理者は、これらの機能を採用するかどうか、およびどのように採用するかを完全に制御できます。

**ユーザーへのインパクト**

このリリースノートは、Databricksのアカウントレベルのセキュリティ機能に関する変更について説明しています。主なポイントは以下の通りです：

- アカウントレベルのセキュリティ機能が一般提供（GA）になると、デフォルトで有効になります。
- これまでは、アカウント管理者がプレビューページで手動で有効にする必要がありました。
- 対象となる機能には、ネットワーク接続、ネットワークセキュリティ、暗号化、および強化されたセキュリティとコンプライアンスのための機能が含まれます。
- この変更の目的は、新しいセキュリティ機能が利用可能になったときに、プラットフォームチームがセキュリティのベストプラクティスを簡単に採用できるようにすることです。
- これらの機能がデフォルトで有効になっても、アカウントのセキュリティ設定が自動的に変更されたり、新しい制御が強制されたりすることはありません。
- アカウント管理者は、これらの機能を採用するかどうか、およびどのように採用するかを完全に制御できます。

つまり、Databricksユーザーは、一般提供開始時点で新しいセキュリティ機能を簡単に利用できるようになりますが、実際にそれらを利用するかどうかはアカウント管理者が決定できます。セキュリティ設定が自動的に変更されることはないため、管理者は引き続きセキュリティ設定を管理できます。

# [Unity Catalog ボリューム用のFiles API 3.0がベータ版になりました。](https://docs.databricks.com/aws/en/release-notes/product/2026/october#files-api-30-for-unity-catalog-volumes-is-now-in-beta)
**2026-10-23**
Files API 3.0 は <a href="https://docs.databricks.com/aws/ja/release-notes/release-types">ベータ版</a>であり、2 つの新しい機能が導入されています。
* マルチパート アップロード: Unity Catalog ボリュームに 5 GB を超えるファイルをアップロードします。
* 条件付き操作: 意図しない変更を防ぐために、現在のバージョンに基づいてファイルのアップロード、ダウンロード、削除を行います。
詳細については、<a href="https://docs.databricks.com/aws/ja/volumes/files-api">Files API とは?</a> を参照してください。

**ユーザーへのインパクト**

Files API 3.0のベータ版リリースにより、Unity Catalogボリュームの操作が改善されます。主な影響と新機能は以下の通りです：

1. **5GBを超えるファイルのアップロードが可能に**：マルチパートアップロード機能により、それまでサイズ制限によりアップロードできなかった大容量ファイルの取り扱いが可能になります。これにより、大規模なデータセットや大きなファイルをUnity Catalogボリュームに簡単にアップロードできます。

2. **条件付き操作によるデータの整合性向上**：ファイルのアップロード、ダウンロード、削除時に、現在のファイルバージョンに基づいて操作を行う条件付き操作が導入されました。これにより、複数のユーザーが同時にファイルを操作する際のデータの不整合や、意図しない変更を防ぐことができます。

これらの新機能により、Databricksユーザーはより効率的かつ安全にUnity Catalogボリュームを操作できるようになります。特に、大規模データの取り扱いや、チームでの共同作業が頻繁に行われる環境において、その利点が活かされるでしょう。詳細な操作方法やAPIの仕様については、Databricksのドキュメント「Files APIとは？」を参照することをお勧めします。

# [Lakebase Insightsがプロジェクトごとの設定に移行し、オンデマンド実行（ベータ版）が可能になりました。](https://docs.databricks.com/aws/en/release-notes/lakebase#lakebase-insights-moves-to-per-project-settings-with-on-demand-runs-beta)
**2026-10-19**
Lakebase Insightsは、`system.lakebase`システムテーブルからのテレメトリーを使用して問題を診断し、次のステップを推奨するようになりました。**Lakebase Insights**ワークスペースプレビューでは、自動テレメトリーキャプチャが有効になっています。**CAN MANAGE**権限を持つユーザーは、オブザーバビリティ設定を作成せずに、各プロジェクトの**設定**で直接Insightsを設定できます。
このプレビューは以前、**Lakebase Advanced Postgres Telemetry**と呼ばれていました。以前にInsightsを使用していたワークスペースでは、すでに有効になっています。Insightsを設定するには、以下の手順に従ってください。

* プレビューがすでに有効になっていない場合は、ワークスペース管理者に**Lakebase Insights**を<a href="https://docs.databricks.com/aws/ja/admin/workspace-settings/manage-previews">プレビューページ</a>から有効にするよう依頼してください。Insightsは、`system.lakebase`のテレメトリーを必要とするため、Insightsプレビューを有効にすると、**Lakebase Observability in System Tables**も有効になります。ワークスペース管理者は、オブザーバビリティプレビューを別途有効にして、Insightsなしでテレメトリーをキャプチャすることもできます。
* プロジェクトのInsights実行をスケジュールするには、そのプロジェクトに対する**CAN MANAGE**権限が必要です。**設定**でInsightsを有効にし、分析頻度を設定してください。
* スケジュール有無に関わらず、いつでもオンデマンドでInsightsを実行できます。

オブザーバビリティ設定を通じてInsightsをスケジュールしていた場合、それらのジョブは停止しています。それらのスケジュールは引き継がれません。それらの設定は、Unityカタログの宛先にテレメトリーを書き込まなくなるため、ダッシュボードは履歴データを保持しますが、新しいデータは受信しなくなります。

# [レイクベースサーチは、中国語、日本語、韓国語の全文検索をサポートしています。](https://docs.databricks.com/aws/en/release-notes/lakebase#lakebase-search-supports-chinese-japanese-and-korean-full-text-search)
**2026-10-15**
`lakebase_tokenizer` 拡張機能が、中国語、日本語、韓国語（CJK）のテキストに対するキーワード検索をサポートするようになりました。これらの言語では単語をスペースで区切らないため、PostgreSQLの標準全文検索では有用な検索キーワードに分割できません。新しい `tokenizer_morph` テンプレートでは、バンドルされた言語辞書を用いた形態素解析によって、CJKテキストを単語に分割します。

* **組み込み設定**: 拡張機能をインストールすると、`tokenizer_chinese`、`tokenizer_japanese`、`tokenizer_korean` が作成されます。これらは、辞書を作成せずに `to_tsvector` で直接使用できます。
* **複合語処理**: 言語に応じて、複合語をそのまま保持するか、より細かい粒度のキーワードに分割するか、あるいは両方を出力するかを選択できます。
* **言語認識フィルタリング**: 日本語の助詞や機能語を除外したり、日本語のキーワードを基本形に変換したり、韓国語の助詞や語尾をフィルタリングしたりすることで、検索結果が意味のあるキーワードに集中するようにします。

`tokenizer_wholeword` と同様に、GIN（一般化反転インデックス）インデックスや、`lakebase_text` および `lakebase_bm25` インデックスでのBM25（Best Match 25）ランキングで動作する標準の `tsvector` 値を生成します。CJKサポートは `lakebase_tokenizer` 0.2.0 で提供されます。すでに拡張機能を使用している場合は、`ALTER EXTENSION lakebase_tokenizer UPDATE` を実行してください。既存の設定やインデックスを変更する必要はありません。詳細については、[lakebase_tokenizer](https://example.com/aws/en/oltp/projects/lakebase-tokenizer) を参照してください。

**ユーザーへのインパクト**

このリリースノートは、Databricksのレイクベースサーチにおける全文検索機能の強化に関するものです。具体的には、中国語、日本語、韓国語（CJK）のテキストに対する検索サポートが追加されました。主な影響と変更点は以下の通りです：

1. **CJKテキストの検索サポート**: `lakebase_tokenizer` 拡張機能がCJKテキストを適切に単語に分割できるようになり、これらの言語でのキーワード検索が改善されました。
2. **組み込み設定の提供**: `tokenizer_chinese`、`tokenizer_japanese`、`tokenizer_korean` という組み込みの設定が利用可能になり、`to_tsvector` で直接使用できます。
3. **複合語処理と言語認識フィルタリング**: 言語に応じた複合語の処理や、不要な語のフィルタリングが可能になり、検索結果の質が向上しました。
4. **互換性**: GINインデックスや、`lakebase_text`、`lakebase_bm25` インデックスでのBM25ランキングで動作する標準の `tsvector` 値を生成します。
5. **アップデート方法**: `lakebase_tokenizer` 0.2.0にアップデートするには、`ALTER EXTENSION lakebase_tokenizer UPDATE` を実行します。既存の設定やインデックスを変更する必要はありません。

Databricksユーザーは、CJK言語のテキストに対する全文検索機能が強化されたことを利用できます。特に、これらの言語のテキストデータを扱っているユーザーにとって、検索の精度と有用性が向上するでしょう。アップデートは簡単で、既存の環境に大きな変更を加える必要はありません。

# [サーバーレス コンピューティングから AWS 管理リソースへのプライベート接続が一般提供開始されました。](https://docs.databricks.com/aws/en/release-notes/product/2026/october#private-connectivity-from-serverless-compute-to-aws-managed-resources-is-now-generally-available)
**2026-10-12**
以前はパブリックプレビューだった、Databricks サーバレス コンピューティングから S3 バケットなどの AWS 管理リソースへの AWS Private Link が一般提供を開始しました。データ トラフィックは完全に AWS ネットワーク内に留まり、パブリック インターネットを経由することはありません。<a href="https://docs.databricks.com/aws/ja/security/network/serverless-network-security/pl-aws-resources">AWS管理リソースへのプライベート接続の設定</a>を参照してください。

**ユーザーへのインパクト**

サーバーレスコンピューティングからAWS管理リソースへのプライベート接続が一般提供されました。これにより、DatabricksのサーバーレスコンピューティングとS3バケットなどのAWS管理リソース間のデータトラフィックがAWSネットワーク内に留まり、パブリックインターネットを経由しなくなりました。セキュリティが向上するため、ユーザーはプライベート接続の設定を検討する必要があります。詳細は、[AWS管理リソースへのプライベート接続の設定](https://docs.databricks.com/aws/ja/security/network/serverless-network-security/pl-aws-resources)を参照してください。

# [コンテキストベースのイングレス ポリシーが一般提供開始されました。これにより、受信プライベート接続をより細かく制御できます。](https://docs.databricks.com/aws/en/release-notes/product/2026/october#context-based-ingress-policies-for-inbound-private-connectivity-are-now-generally-available)
**2026-10-12**
インバウンド Private Link のコンテキストベースのイングレスポリシーが一般提供開始されました。これにより、登録済みのどの VPC エンドポイントがワークスペースに到達できるかを制御し、エンドポイントルールとアイデンティティおよびリクエストタイプの条件を同じポリシーで組み合わせることができます。アカウントの<strong>コンテキストベースのイングレス: Workspace Private Access ポリシー</strong>がまだ有効になっていない場合は、アカウント管理者がアカウントコンソールの<strong>プレビュー</strong>ページから有効にできます。<a href="https://docs.databricks.com/aws/ja/security/network/front-end/front-end-private-connect#private-access">プライベートアクセスポリシーを設定する</a>を参照してください。

**ユーザーへのインパクト**

コンテキストベースのイングレスポリシーが一般提供開始されました。これにより、Databricksワークスペースへの受信プライベート接続をより細かく制御できます。具体的には、どのVPCエンドポイントがワークスペースにアクセスできるかを制御し、エンドポイントルールとアイデンティティおよびリクエストタイプの条件を組み合わせたポリシーを設定できます。まだ有効にしていない場合は、アカウント管理者がアカウントコンソールのプレビューから「コンテキストベースのイングレス: Workspace Private Access ポリシー」を有効にできます。プライベートアクセスポリシーの設定方法については、Databricksのドキュメントを参照してください。

# [エージェントメモリパイプラインはベータ版です。](https://docs.databricks.com/aws/en/release-notes/product/2026/october#agent-memory-pipelines-are-in-beta)
**2026-10-12**
エージェントメモリパイプラインは<a href="https://docs.databricks.com/aws/ja/release-notes/release-types">ベータ版</a>です。メモリパイプラインは、セッションストアをメモリストアに接続します。各実行では、LLM を使用して、保存された会話から永続的な事実、設定、決定をメモリエントリに抽出し、エージェントが後続の会話で思い出せるようにします。パイプラインは、オンデマンドまたは約 24 時間ごとに実行できます。<a href="https://docs.databricks.com/aws/ja/agents/agent-memory/memory-pipelines">エージェントメモリパイプライン</a>を参照してください。

**ユーザーへのインパクト**

Databricksのエージェントメモリパイプラインがベータ版になりました。これにより、セッションストアとメモリストアが接続され、LLMを使用して過去の会話から重要な情報を抽出し、エージェントが後続の会話で参照できるようになります。パイプラインはオンデマンドまたは約24時間ごとに実行可能です。詳細はドキュメントをご参照ください。

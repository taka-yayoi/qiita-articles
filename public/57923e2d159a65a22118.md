既存の PostgreSQL データベースを、1 回限りの移行で Lakebase プロジェクトにコピーできるようになりました。Lakebase はソースデータベースの互換性を評価し、そのロール、スキーマ、データを指定したブランチにコピーします。移行は Lakebase アプリと Postgres API および SDK から実行でき、個別の有効化手順は不要です。移行の手順と利用可能なリージョンについては、<a href="https://docs.databricks.com/aws/ja/oltp/projects/migrations">Postgres データベースを Lakebase に移行する</a>を参照してください。

**ユーザーへのインパクト**

既存のPostgreSQLデータベースを、1回限りの移行でLakebaseプロジェクトの指定ブランチへロール、スキーマ、データごとコピーできるようになりました（ベータ版）。移行前にソースの互換性が自動評価され、Lakebaseアプリに加えてPostgres APIやSDKからも実行でき、個別の有効化は不要です。継続的な同期ではなく一度きりのコピーである点と、利用可能なリージョンが限られる点に注意してください。

# [OpenSharing のオープンな受信者向けの、受信者ごとに固有の URL](https://docs.databricks.com/aws/en/release-notes/product/2026/november#recipient-specific-urls-for-opensharing-open-recipients)
**2026-11-24**
ほとんどのリージョンでは、OpenSharing のオープン受信者は、ホスト名に受信者 ID を含む受信者固有の URL を使用するようになりました。2026 年 9 月以降に作成またはローテーションされたベアラートークンは新しい URL を使用し、OpenSharing の UI では OpenID Connect (OIDC) フェデレーション受信者向けに新しい URL が表示されます。受信者は、共有のリージョナルホスト名ではなく、受信者固有のホスト名への外向き通信 (egress) を許可できます。既存の URL とトークンは、有効期限が切れるまで引き続き使用できます。<a href="https://docs.databricks.com/aws/ja/release-notes/whats-coming#changes-to-open-delta-sharing-recipient-tokens">OpenSharing (旧 Delta Sharing) オープン受信者トークンの変更</a>を参照してください。

**ユーザーへのインパクト**

OpenSharingのオープン受信者は、受信者IDを含む固有のURLを使うようになり、2026年9月以降に作成・ローテーションされたベアラートークンから適用されます。共有のリージョナルホスト名ではなく受信者固有のホスト名へのegressだけを許可できるため、ファイアウォールのルールを絞り込めます。既存のURLとトークンは有効期限まで使えますが、ローテーション後は新URLに合わせて許可リストを更新してください。

# [AWS サーバーレスのネットワーク料金に関する今後の変更](https://docs.databricks.com/aws/en/release-notes/whats-coming#upcoming-changes-to-aws-serverless-networking-charges)

**ユーザーへのインパクト**

サービスプリンシパル向けOAuth On-Behalf-Of(OBO)がGAとなり、既定で有効になったため、管理者がプレビューページで有効化する作業は不要です。Service Principal Managerロールを持つユーザーは、OAuthシークレットを発行せずに標準のU2M OAuthフローでそのサービスプリンシパルとして認証できます。シークレットの発行・ローテーション・保管の負担と漏洩リスクが減るので、開発や検証での利用では必要なユーザーに同ロールが付与されているかを確認してください。

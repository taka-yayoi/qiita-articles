1. Databricks REST API のエンドポイントと認証トークンを取得します。

token = 'your-auth-token'

# ヘッダーを設定します
headers = {'Authorization': f'Bearer {token}'}

# JSON データを送信します
response = requests.put(databricks_url, headers=headers, data=data)

# 応答を確認します
if response.status_code == 200:
    print('Data written successfully')
else:
    print('Error writing data:', response.text)

<p>Genie Codeは、コードの実行やノートブックの編集などのツールアクションを、リクエストごとにプロンプトを表示せずに承認する自動承認モードを提供するようになりました。AI分類器が各アクションをレビューし、リスクのあるアクションをブロックします。自動承認は生産性向上のための機能であり、セキュリティ上の境界ではありません。本番データや共有リソースを扱う際には、Databricksは自動承認をオフにすることを推奨しています。詳細は<a href="https://docs.databricks.com/aws/ja/genie-code/use-genie-code#approve-tools">ツールアクションの承認</a>を参照してください。</p>

# [Databricks SQL バージョン2026.15 がプレビューで利用できるようになりました。](https://docs.databricks.com/aws/en/sql/release-notes/2026#databricks-sql-version-202615-is-now-available-in-preview)
**2026-05-26**
<p>Databricks SQL バージョン2026.15が<strong>プレビュー</strong>チャンネルで利用可能になりました。以下のセクションを確認して、新機能、動作の変更、バグ修正について学んでください。</p>
<h4>XPathが外部DTDを取得しなくなった</h4>
<p>XMLに対して<a href="https://docs.databricks.com/aws/ja/sql/language-manual/functions/xpath">xpath</a>を評価する際、Databricksはドキュメント内で宣言された外部DTD（Document Type Definitions）をロードしなくなりました。以前は、XMLに不正なURLや到達不能なエンドポイントを指す外部DTD参照が含まれている場合、XPathは失敗する可能性がありました。DTD検証はXPath評価とは別であるため、すでに成功していたクエリは以前と同じ結果を返します。以前は外部DTD取得中にのみ失敗していたクエリが、成功するようになりました。</p>

# [Databricks Runtime 18: 2026年5月18日](https://docs.databricks.com/aws/en/release-notes/runtime/18#databricks-runtime-18-may-18-2026)
**2026-05-18**
<h3><div></div>動作の変更</h3>
<p>このランタイムでクラスターが再起動したときに有効になる以下の変更を確認します。</p>
<ul>
<li><strong><code>CREATE OR REPLACE TABLE</code></strong>: <a href="https://docs.databricks.com/aws/ja/sql/language-manual/sql-ref-syntax-ddl-create-table"><code>CREATE OR REPLACE TABLE</code></a> は、デフォルトで既存の列およびテーブルのコメントを保持するようになりました。 以前は、テーブルを再作成するとコメントは削除されていました。 マネージドテーブルとビューは、 マテリアライズドビューとストリーミングテーブルの既存の動作と一致するようになりました。 </li>
<li><strong>DataFrame の名前による書き込み</strong>: <code>writeTo().append()</code>、<code>writeTo().overwrite()</code>、<code>writeTo().overwritePartitions()</code>、および <code>write.mode("append").saveAsTable()</code> は、ターゲットの Delta テーブルスキーマに一致するように、型互換の列（たとえば、<code>int</code> から <code>long</code>）を自動的にキャストするようになりました。 以前は、列の型は互換性があるものの同一ではない場合、これらの操作は <code>DELTA_FAILED_TO_MERGE_FIELDS</code> エラーで失敗していました。 この動作は、SQL の <code>INSERT INTO ... BY NAME</code> と一致するようになりました。 上書きモードの <code>save()</code> および <code>saveAsTable()</code> は影響を受けません。 </li>
<li><strong><code>pipelines.pipelineId</code> に対する <code>ALTER TABLE SET TBLPROPERTIES</code></strong>: <code>ALTER TABLE &#x3C;table> SET TBLPROPERTIES('pipelines.pipelineId' = '&#x3C;pipeline-id>')</code> は、指定されたテーブルをパイプラインによる書き込みの対象として設定しようとするようになりました。 以前は、通常のテーブルでこのプロパティを設定しても効果はありませんでした。 テーブルがパイプライン書き込みの対象でない場合、コマンドは <code>SETTING_PIPELINES_PIPELINE_ID_NOT_SUPPORTED</code> をスローします

**ユーザーへのインパクト**

Databricks Runtime 18へのアップデートにより、以下の変更がユーザーのワークフローに影響を及ぼします：

1. **`CREATE OR REPLACE TABLE`の動作変更**: テーブルを再作成する際に、既存の列やテーブルのコメントがデフォルトで保持されるようになりました。これにより、マネージドテーブルやビュー、マテリアライズドビュー、ストリーミングテーブルの動作が一貫します。

2. **DataFrameの名前による書き込みの改善**: `writeTo().append()`や`write.mode("append").saveAsTable()`などの操作で、Deltaテーブルのスキーマに一致するように、型互換の列（例：`int`から`long`）が自動的にキャストされるようになりました。これにより、SQLの`INSERT INTO ... BY NAME`と同様の動作になります。ただし、上書きモードの`save()`や`saveAsTable()`はこの変更の影響を受けません。

3. **`ALTER TABLE SET TBLPROPERTIES`の動作変更**: `pipelines.pipelineId`プロパティを設定する際に、指定されたテーブルをパイプラインによる書き込みの対象として設定するようになりました。テーブルがパイプライン書き込みの対象でない場合、コマンドはエラーをスローします。

これらの変更は、Databricks Runtime 18でクラスターが再起動したときに有効になります。ユーザーは、これらの変更が自分のワークフローに与える影響を確認し、必要に応じてコードの修正やテストを行う必要があります。特に、テーブルのメタデータの保持やDataFrameの書き込み動作に依存する処理がある場合は、注意が必要です。

具体的には、Databricks は以下のような HIPAA サポートを提供しています。

1. **ビジネス関連契約 (BAA)**：Databricks は、該当する顧客と BAA を締結し、保護された医療情報の取り扱いに関する合意を提供します。
2. **HIPAA コンプライアンスのドキュメント**: Databricks は、Excel 用 Databricks アドインを含む Databricks プラットフォームの HIPAA コンプライアンスに関するドキュメントを提供しています。
3. **セキュリティとプライバシーの機能**: Databricks プラットフォームには、データの暗号化、アクセスコントロール、監査ログなどのセキュリティとプライバシー機能が備わっており、HIPAA 要件を満たすのに役立ちます。

Databricks の HIPAA サポートにより、医療機関やビジネスパートナーは、Excel 用 Databricks アドインを使用して、保護された医療情報を含むデータを安全に処理および分析できます。](https://docs.databricks.com/aws/en/release-notes/product/2026/may#hipaa-support-for-the-databricks-add-in-for-excel)
**2026-05-11**
Excel 用 Databricks アドイン (パブリックプレビュー) が、サポートされているすべてのリージョンで HIPAA コンプライアンス準拠のワークスペースで利用できるようになりました。詳細については、「<a href="https://docs.databricks.com/aws/ja/integrations/excel">Microsoft Excel から Databricks に接続する</a>」を参照してください。

**ユーザーへのインパクト**

Excel 用 Databricks アドインが HIPAA 準拠のワークスペースで利用できるようになったため、医療機関のお客様は保護された医療情報を含むデータを安全に処理および分析できます。Databricks は BAA の締結、コンプライアンスドキュメントの提供、セキュリティ機能の強化により HIPAA 要件への準拠をサポートします。詳細は Databricks のドキュメントを参照してください。

# [Databricks Apps のアプリ テレメトリがパブリック プレビューで利用可能になりました](https://docs.databricks.com/aws/en/release-notes/product/2026/may#app-telemetry-for-databricks-apps-is-now-in-public-preview)
**2026-05-11**
<p>OpenTelemetry（OTel）プロトコルを使用して、Databricks Appsからトレース、ログ、メトリクスを収集し、Unity Catalogテーブルに永続化できるようになりました。詳細については、<a href="https://docs.databricks.com/aws/ja/dev-tools/databricks-apps/observability">Databricks Appsのテレメトリーの設定</a>を参照してください。</p>

**ユーザーへのインパクト**

Databricks Appsのアプリテレメトリがパブリックプレビューで利用可能になりました。これにより、OpenTelemetry（OTel）プロトコルを使用してDatabricks Appsからトレース、ログ、メトリクスを収集し、Unity Catalogテーブルに保存できます。これにより、DatabricksユーザーはDatabricks Appsの監視とデバッグをより効果的に行うことができます。詳細については、ドキュメント「Databricks Appsのテレメトリーの設定」を参照してください。

# [カタログ コミットが一般提供されるようになりました。](https://docs.databricks.com/aws/en/release-notes/product/2026/may#catalog-commits-are-now-generally-available)
**2026-05-08**
カタログ コミットが一般的に利用できるようになりました。カタログ コミットにより、Unity Catalogで管理されるテーブルの相互運用性が拡張され、Unity Catalogのガバナンス機能が強化され、複数ステートメント、複数テーブル トランザクションなどの新しい機能が解放されます。Unity Catalogで管理されるDeltaテーブルでカタログ コミットが有効になっている場合、Unity Catalogがテーブルの調整システムとなり、エンジン間でアクセスと状態の仲介を行います。Unity Catalogで管理されるテーブルへの読み取りまたは書き込みを行う製品は、カタログ コミットをサポートするようになりました。これには、<a href="https://docs.databricks.com/aws/ja/ldp/streaming-tables">ストリーミング テーブル</a>、<a href="https://docs.databricks.com/aws/ja/delta-sharing">Delta Sharing</a>、<a href="https://docs.databricks.com/aws/ja/ingestion/zerobus-ingest">Zerobus</a>、<a href="https://docs.databricks.com/aws/ja/ingestion/lakeflow-connect">Lakeflow Connect</a>、<a href="https://docs.databricks.com/aws/ja/ai-gateway">Mosaic AI Gateway</a>、MLflow、<a href="https://docs.databricks.com/aws/ja/jobs/triggers">Lakeflow Jobsトリガー</a>が含まれます。詳細は<a href="https://docs.databricks.com/aws/ja/delta/catalog-commits">カタログ コミット</a>を参照してください。

**ユーザーへのインパクト**

カタログ コミットの一般提供に伴い、Unity Catalogで管理されるDeltaテーブルの相互運用性とガバナンスが強化されます。これにより、複数ステートメント、複数テーブルトランザクションなどの新機能が利用可能になります。カタログ コミットが有効なテーブルでは、Unity Catalogが調整システムとなり、エンジン間でのアクセスと状態の管理を行います。ストリーミング テーブル、Delta Sharing、Zerobus、Lakeflow Connect、Mosaic AI Gateway、MLflow、Lakeflow Jobsトリガーなどの製品は、Unity Catalogで管理されるテーブルへの読み取り/書き込みでカタログ コミットをサポートするようになりました。

# [サーバーレス汎用コンピューティングでのスタンドアロン パイプライン（ベータ版）](https://docs.databricks.com/aws/en/release-notes/product/2026/may#standalone-pipelines-on-serverless-general-compute-beta)
**2026-05-07**
サーバーレスの汎用コンピュートで実行されているノートブックから、マテリアライズドビューやストリーミングテーブルを含むスタンドアロン パイプラインを作成できるようになりました。スタンドアロン パイプライン (Databricks SQLのパイプラインから名前が変更されました) は、SQL または Python を使用して作成できます。スタンドアロン パイプラインはベータ版です。「<a href="https://docs.databricks.com/aws/ja/ldp/dbsql/compute">スタンドアロン パイプラインの要件</a>」を参照してください。

**ユーザーへのインパクト**

サーバーレス汎用コンピューティングで実行されるノートブックから、マテリアライズドビューやストリーミングテーブルを含むスタンドアロン パイプラインを作成できるようになりました。スタンドアロン パイプラインは SQL または Python で作成でき、現在ベータ版です。要件については、ドキュメント「スタンドアロン パイプラインの要件」を参照してください。

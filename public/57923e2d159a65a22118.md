# [ジョブタスクのサブセットをその依存関係とともに実行する](https://docs.databricks.com/aws/en/release-notes/product/2026/june#run-a-subset-of-job-tasks-with-their-dependencies)
**2026-06-30**
<p>ジョブのタスクのサブセットを実行するときに、選択範囲を拡張して各タスクの依存関係を含めることができるようになりました。タスクキーに<code>+</code>修飾子を追加して、上流タスク(<code>+my_task</code>)、下流タスク(<code>my_task+</code>)、またはその両方(<code>+my_task+</code>)を実行します。UI、REST API、Databricks CLI、SDK、またはDeclarative Automation Bundlesから部分実行を開始します。 <a href="https://docs.databricks.com/aws/ja/jobs/run-now#run-task-subset">タスクのサブセットとその依存関係を実行する</a>を参照してください。</p>

**ユーザーへのインパクト**

1. **タスクの部分実行の柔軟性向上**：ジョブ内の特定のタスクを実行する際に、`+` 修飾子を使用して上流タスク (`+my_task`)、下流タスク (`my_task+`)、またはその両方 (`+my_task+`) を含めることができます。これにより、必要なタスクとその依存関係だけを実行でき、リソースの効率的な使用が可能になります。

2. **複数のインターフェースからの利用**：この機能は、DatabricksのUI、REST API、Databricks CLI、SDK、Declarative Automation Bundlesなど、さまざまなインターフェースから利用できます。これにより、ユーザーは自身が馴染んでいるツールやワークフローに合わせて、この新機能を簡単に統合できます。

3. **ドキュメントの提供**：詳細については、Databricksのドキュメント「[タスクのサブセットとその依存関係を実行する](https://docs.databricks.com/aws/ja/jobs/run-now#run-task-subset)」にアクセスすることが推奨されています。

このリリースは、Databricksジョブの実行をより柔軟かつ効率的に行うことを可能にし、ユーザーが特定のタスクに集中してリソースを最適化できるようにします。

</ul>

**ユーザーへのインパクト**

Databricks Runtime 19へのアップグレードにより、標準アクセスモードのクラスタで以下の変更が発生します：

1. 環境変数の利用制限: ユーザー定義の環境変数はSparkエンジンとinitスクリプトで利用できなくなり、代わりに事前定義された一部の変数（例：プロキシ設定、クラウド認証情報、カタログ変数）のみが利用できるようになります。ユーザーコードでは引き続き利用可能です。

2. 制限付きSpark設定: 特定のSpark設定プロパティ（例：`spark.driver.extraJavaOptions`、`spark.executor.extraJavaOptions`）を設定できなくなります。これらのプロパティを設定しているクラスタは、作成または編集時にエラーで失敗します。

これらの変更により、既存のクラスタ設定やコードの修正が必要になる場合があります。特に、標準アクセスモードで環境変数や制限付きSpark設定を使用している場合は、Databricksドキュメントの「環境変数の制限」と「Spark設定の制限」を参照し、必要な調整を行ってください。

<ul>
<li><strong>テーブルのヘッダーの色のカスタマイズ</strong>: テーブルの列ヘッダーのフォントの色、背景色、テキストフォーマットを著者が設定できるようになりました。 <a href="https://docs.databricks.com/aws/ja/dashboards/manage/visualizations/tables#table-layout-settings">テーブルのレイアウト設定</a>を参照してください。</li>

<li><strong>Power BIおよびTableauインポートのイメージアップロードの提案 (ベータ)</strong>: Genie Codeが、Power BIおよびTableauからのファイルインポート時に移行品質を向上させるためにイメージのアップロードを提案するようになりました。</li>
</ul>

**ユーザーへのインパクト**

Databricksのダッシュボード機能が強化されました。主な変更点は以下の通りです。

1. テーブルの列ヘッダーのカスタマイズが可能になり、フォントの色、背景色、テキストフォーマットを設定できるようになりました。
2. ダッシュボードリレーションシップがプライベートプレビューで利用できるようになり、複雑なマルチファクトデータモデルを作成できるようになりました。
3. ローカルメトリクスビューがパラメータをサポートし、UIでのユーザーの選択に基づいてクエリ入力を動的に変更できるようになりました。
4. ローカルメトリクスビューがワイルドカード式をサポートし、上流のテーブルまたはメトリクスビューからすべてのフィールドを継承できるようになりました。
5. Genie CodeがPower BI拡張レポートフォーマット（PBIR）でエクスポートされたPower BIファイルをサポートするようになりました（ベータ）。
6. Genie CodeがPower BIおよびTableauからのファイルインポート時にイメージのアップロードを提案し、移行品質を向上させるようになりました（ベータ）。

これらの変更により、Databricksユーザーはより柔軟にダッシュボードをカスタマイズし、複雑なデータモデルを作成できるようになります。また、Power BIやTableauからの移行もスムーズになることが期待されます。

1. セキュアなデータ共有: ファイアウォールやプライベートエンドポイントによって保護されたデータへのアクセスを容易にし、データ共有のセキュリティを強化します。
2. 簡略化されたネットワーク設定: 受信者のネットワークを許可リストに追加する必要がなくなり、共有プロセスが簡素化されます。
3. クリーンルームでの利用: クリーンルームでもSecureConnectが利用できるため、データ共有の柔軟性が向上します。

ユーザーは、SecureConnectを使用して、データ共有のセキュリティと利便性を向上させることができます。詳細については、Databricksのドキュメントを参照してください。

**2026-06-10**
<p>コンプライアンス対象外のオールパーパスコンピュートに対してコンピュートポリシーのコンプライアンスを適用する場合、即座に再起動させるのではなく、次にコンピュートが終了または再起動されるタイミングで設定更新をスケジュールできるようになりました。<strong>「次回の再起動時に適用」</strong>を選択すると、実行中のワークロードが中断するのを回避できます。<strong>「再起動して適用」</strong>を選択すると、直ちに更新が適用されます。ワークスペースの管理者は、単一のコンピュートリソースまたは全体ポリシーに対する予定されたポリシー適用をキャンセルできます。詳細は、<a href="https://docs.databricks.com/aws/ja/admin/clusters/policies#compliance">ポリシーコンプライアンスの適用</a>をご参照ください。</p>

**ユーザーへのインパクト**

このリリースノートは、Databricksの全般的なコンピューティングリソースに対するポリシー適用に関する変更について説明しています。主な影響は以下の通りです：

1. **ポリシー適用のタイミング選択**: コンプライアンス対象外のオールパーパスコンピューティングリソースに対して、ポリシーコンプライアンスを即座に適用するのではなく、次回の再起動またはシャットダウン時に適用するオプションが追加されました。これにより、実行中のワークロードを中断することなくポリシー更新をスケジュールできます。

2. **実行中のワークロードへの影響軽減**: 「次回の再起動時に適用」を選択することで、現在実行中のジョブやタスクを中断させることなくポリシー更新を計画できます。一方、「再起動して適用」を選択すると、ポリシー更新が即座に適用され、コンピューティングリソースが再起動されます。

3. **管理者の制御の強化**: ワークスペース管理者は、単一のコンピューティングリソースまたは全体のポリシーに対する予定されたポリシー適用をキャンセルする権限を持ちます。これにより、管理者は柔軟にポリシー適用のタイミングを管理できます。

この変更により、Databricksユーザーはポリシーコンプライアンスの適用をより柔軟に管理でき、特に重要なワークロードの実行中にポリシー更新による中断を避けることができます。管理者は、この機能を利用して、業務の連続性を保ちながらコンプライアンスを維持できます。

# [Lakeflow Spark宣言型パイプラインのupdate_flow APIが一般提供開始となりました。](https://docs.databricks.com/aws/en/release-notes/product/2026/june#the-update_flow-api-for-lakeflow-spark-declarative-pipelines-is-generally-available)
**2026-06-09**
Lakeflow Spark Declarative Pipelinesの<code>@dp.update_flow</code>デコレータを使用すると、更新フロー（update flow）を追加できます。更新フローは、更新出力モードでシンクに書き込み、各バッチで変更される行のみを出力します。追加フロー（append flows）とは異なり、更新フローは、ウォーターマークを必要とせずにステートフル集計をサポートします。詳細については、<a href="https://docs.databricks.com/aws/ja/ldp/developer/ldp-python-ref-update-flow">update_flow</a>、<a href="https://docs.databricks.com/aws/ja/release-notes/release-types">一般提供</a>を参照してください。

**ユーザーへのインパクト**

Lakeflow Spark宣言型パイプラインのupdate_flow APIが一般提供開始となりました。これにより、Databricksユーザーは更新フロー（update flow）を追加できるようになり、ステートフル集計をウォーターマークなしでサポートできるようになります。更新フローは、変更された行のみを出力するため、データ処理の効率化が期待できます。詳細については、公式ドキュメントのupdate_flowおよび一般提供に関するページを参照してください。

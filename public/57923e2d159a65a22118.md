# [Unity Catalog ボリューム用のFiles API 3.0がベータ版になりました。](https://docs.databricks.com/aws/en/release-notes/product/2026/october#files-api-30-for-unity-catalog-volumes-is-now-in-beta)
**2026-10-23**
Files API 3.0 は <a href="https://docs.databricks.com/aws/ja/release-notes/release-types">ベータ版</a>であり、2 つの新しい機能が導入されています。
* マルチパート アップロード: Unity Catalog ボリュームに 5 GB を超えるファイルをアップロードします。
* 条件付き操作: 意図しない変更を防ぐために、現在のバージョンに基づいてファイルのアップロード、ダウンロード、削除を行います。
詳細については、<a href="https://docs.databricks.com/aws/ja/volumes/files-api">Files API とは?</a> を参照してください。

**ユーザーへのインパクト**

Files API 3.0のベータ版リリースにより、Unity Catalogボリュームの操作が改善されます。主な影響と新機能は以下の通りです：

1. **5GBを超えるファイルのアップロードが可能に**：マルチパートアップロード機能により、それまでサイズ制限によりアップロードできなかった大容量ファイルの取り扱いが可能になります。これにより、大規模なデータセットや大きなファイルをUnity Catalogボリュームに簡単にアップロードできます。

2. **条件付き操作によるデータの整合性向上**：ファイルのアップロード、ダウンロード、削除時に、現在のファイルバージョンに基づいて操作を行う条件付き操作が導入されました。これにより、複数のユーザーが同時にファイルを操作する際のデータの不整合や、意図しない変更を防ぐことができます。

これらの新機能により、Databricksユーザーはより効率的かつ安全にUnity Catalogボリュームを操作できるようになります。特に、大規模データの取り扱いや、チームでの共同作業が頻繁に行われる環境において、その利点が活かされるでしょう。詳細な操作方法やAPIの仕様については、Databricksのドキュメント「Files APIとは？」を参照することをお勧めします。

**2026-10-15**
`lakebase_tokenizer` 拡張機能が、中国語、日本語、韓国語（CJK）のテキストに対するキーワード検索をサポートするようになりました。これらの言語では単語をスペースで区切らないため、PostgreSQLの標準全文検索では有用な検索キーワードに分割できません。新しい `tokenizer_morph` テンプレートでは、バンドルされた言語辞書を用いた形態素解析によって、CJKテキストを単語に分割します。

* **言語認識フィルタリング**: 日本語の助詞や機能語を除外したり、日本語のキーワードを基本形に変換したり、韓国語の助詞や語尾をフィルタリングしたりすることで、検索結果が意味のあるキーワードに集中するようにします。

`tokenizer_wholeword` と同様に、GIN（一般化反転インデックス）インデックスや、`lakebase_text` および `lakebase_bm25` インデックスでのBM25（Best Match 25）ランキングで動作する標準の `tsvector` 値を生成します。CJKサポートは `lakebase_tokenizer` 0.2.0 で提供されます。すでに拡張機能を使用している場合は、`ALTER EXTENSION lakebase_tokenizer UPDATE` を実行してください。既存の設定やインデックスを変更する必要はありません。詳細については、[lakebase_tokenizer](https://example.com/aws/en/oltp/projects/lakebase-tokenizer) を参照してください。

3. **複合語処理と言語認識フィルタリング**: 言語に応じた複合語の処理や、不要な語のフィルタリングが可能になり、検索結果の質が向上しました。
4. **互換性**: GINインデックスや、`lakebase_text`、`lakebase_bm25` インデックスでのBM25ランキングで動作する標準の `tsvector` 値を生成します。

Databricksユーザーは、CJK言語のテキストに対する全文検索機能が強化されたことを利用できます。特に、これらの言語のテキストデータを扱っているユーザーにとって、検索の精度と有用性が向上するでしょう。アップデートは簡単で、既存の環境に大きな変更を加える必要はありません。

# [近日中に、CREATE OR REPLACE VIEW によりデフォルトで権限、コメント、タグが保持されるようになります。](https://docs.databricks.com/aws/en/release-notes/whats-coming#create-or-replace-view-will-soon-preserve-grants-comments-and-tags-by-default)
**2026-10-06**
2026年12月2日から、<code>CREATE OR REPLACE VIEW</code>はビューを削除して再作成するのではなく、その場でビューを更新するようになります。権限付与、タグ、コメントは1つの注意事項つきで保持されます。

*   <code>CREATE OR REPLACE VIEW</code>で列を削除する前に、ビュー列の<a href="https://docs.databricks.com/aws/ja/admin/governed-tags">ガバナンスタグ</a>を削除する必要があります。そうしないと、ステートメントは、それらに依存する<a href="https://docs.databricks.com/aws/ja/data-governance/unity-catalog/abac">ABAC</a>ポリシーを保護するために<code>CANNOT_DROP_TAGGED_COLUMN</code>エラーで失敗します(<a href="https://docs.databricks.com/aws/ja/database-objects/tags#drop">詳細</a>)。

ビュー上の権限付与、タグ、およびコメントを明示的に削除するには、<code>CREATE OR REPLACE VIEW &#x3C;catalog>.&#x3C;schema>.&#x3C;view> NOCOPY * …</code>を使用します (ガバナンスタグは保持されます)。

詳細については、<a href="https://docs.databricks.com/aws/ja/sql/language-manual/sql-ref-syntax-ddl-create-view">CREATE VIEW</a> および <a href="https://docs.databricks.com/https://kb.databricks.com/dbsql/upcoming-change-to-create-or-replace-view-metadata-preservation">CREATE OR REPLACE VIEW メタデータ保存の今後の変更</a>を参照してください。

**ユーザーへのインパクト**

2026年12月2日以降、Databricksの`CREATE OR REPLACE VIEW`文の動作が変更され、デフォルトで権限、コメント、タグが保持されるようになります。この変更により、ビューを再作成するのではなく、その場で更新するようになります。主な影響と注意事項は以下の通りです：

1. **権限、コメント、タグの保持**：`CREATE OR REPLACE VIEW`を使用すると、これらのメタデータが保持されるようになります。
2. **列の削除に関する制約**：ビューから列を削除する前に、その列に付与されたガバナンスタグを削除する必要があります。そうしないと、`CANNOT_DROP_TAGGED_COLUMN`エラーが発生します。これは、そのタグに依存するABACポリシーを保護するためです。
3. **メタデータの明示的な削除**：ビュー上の権限付与、タグ、コメントを明示的に削除するには、`NOCOPY`句を使用します。ただし、ガバナンスタグは保持されることに注意してください。

この変更に対応するため、Databricksユーザーは以下の点に留意する必要があります：

* ビュー定義の更新時に意図しないメタデータの保持を避けるために、`NOCOPY`句の使用を検討する。
* ビューから列を削除する前に、関連するガバナンスタグを削除する。
* 詳細については、Databricksのドキュメント（CREATE VIEWおよびCREATE OR REPLACE VIEWメタデータ保存の今後の変更）を参照する。

# [サービス プリンシパル トークンの OAuth カスタム ID クレームが間もなく利用可能になります](https://docs.databricks.com/aws/en/release-notes/whats-coming#oauth-custom-identity-claims-for-service-principal-tokens-will-soon-be-available)
**2026-10-05**
アプリケーションは、`client_credentials` または `urn:ietf:params:oauth:grant-type:token-exchange` 付与タイプを使用するトークン要求に `custom_claim` パラメータを追加することで、サービスプリンシパルに対して要求する OAuth トークンにカスタム ID クレームを付与することができます。その後、`current_oauth_custom_identity_claim()` 関数を使用して SQL でその値を読み取ることができます。

カスタム ID クレームを使用すると、1 つのサービス プリンシパルを通じて多くのエンドユーザーをサポートしながら、各ユーザーが自分のデータのみを表示できるようになります。動的ビューは、列をクレームと比較することによって行をフィルタリングします。Genie Conversation API、SQL Statement Execution API、および Databricks JDBC ドライバーはクレームを尊重します。

トークンにカスタム ID クレームが含まれていない場合、この関数は `NULL` を返します。クレームが `NULL` の場合に、どの行にも一致しないフィルタを作成してください。

詳細については、「OAuth を使用して Databricks へのサービス プリンシパルのアクセスを認可する」および「Genie Agents API の使用」を参照してください。

**ユーザーへのインパクト**

Databricksユーザーは、サービスプリンシパルのOAuthトークンにカスタムIDクレームを追加できるようになります。これにより、1つのサービスプリンシパルで複数のエンドユーザーをサポートしつつ、ユーザーが自分のデータのみにアクセスできるように動的ビューを実装できます。具体的には、`current_oauth_custom_identity_claim()`関数を使用してSQLでクレーム値を読み取り、行をフィルタリングできます。Genie Conversation API、SQL Statement Execution API、およびDatabricks JDBCドライバーはこれらのクレームを尊重します。トークンにクレームがない場合は`NULL`が返されるため、`NULL`の場合にどの行にも一致しないフィルタを作成する必要があります。

# [Lakeflowパイプラインをグループとして実行する](https://docs.databricks.com/aws/en/release-notes/product/2026/october#run-lakeflow-pipelines-as-a-group)
**2026-10-05**
パイプラインの実行IDを、ユーザーまたはサービスプリンシパルに加えて、アカウントグループに設定できるようになりました。パイプラインの更新は、グループの権限で実行されるため、1人のアカウントに紐付けることなく、チームが自動化パイプラインを所有することができます。「<a href="https://docs.databricks.com/aws/ja/ldp/configure-pipeline#run-as-group">実行IDをグループに設定する</a>」を参照してください。

**ユーザーへのインパクト**

Lakeflowパイプラインの実行IDをグループに設定できるようになったため、チームでのパイプライン管理が容易になります。これにより、パイプラインの所有権を特定のアカウントに依存することなく、グループ単位で権限を管理できます。チームでの自動化パイプラインの共有と管理がより柔軟になります。詳細は、提供されたドキュメントリンク（https://docs.databricks.com/aws/ja/ldp/configure-pipeline#run-as-group）で確認できます。

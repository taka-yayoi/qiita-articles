# アプリの構築

**ローカルでの動作確認 -> Databricksへのデプロイ**という流れが推奨です。

## ローカルでの構築

[Databricks CLI](https://docs.databricks.com/aws/ja/dev-tools/cli/install)が必要なのでインストールしておきます。

リポジトリをクローンします。

```sh
git clone https://github.com/databricks/app-templates
```

```sh
cd app-templates/e2e-chatbot-app 
```

マニュアルには名に記載されていませんが、仮想環境を作ってからライブラリをインストールします。

```sh
python3 -m venv .venv
source .venv/bin/activate
```

```sh
pip install -r requirements.txt
```

ローカルで動かす際でも、UIで呼び出すLLMが必要となります。なので、デプロイ先のDatabricksにあるモデルサービングエンドポイントにアクセスできるように、ワークスペースのURLと[パーソナルアクセストークン](https://docs.databricks.com/aws/ja/dev-tools/auth/pat)をコピーしておきます。

![Screenshot 2025-08-15 at 11.08.18.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/88f6eec6-bb73-4283-ad79-4e9997f4f67e.png)

CLIの設定コマンドでURLとパーソナルアクセストークンからなるプロファイルを作成します。

```sh
databricks configure
```
![Screenshot 2025-08-15 at 11.29.21.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/546e7610-0f1e-432a-9dae-899153b0a287.png)

動作確認する前に、環境変数でモデルの名前を指定します。Databricksの**サービング**メニューでモデルを確認することができます。GPT-OSSでも動いたのですがレスポンスのフォーマットが異なっているようでしたので、ここではLlamaを使います。
![Screenshot 2025-08-15 at 11.08.27.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/c9863af8-89bc-47b9-821d-4812730ebae1.png)


```sh
export SERVING_ENDPOINT=databricks-llama-4-maveric
```

アプリを起動します。

```sh
streamlit run app.py
```

ローカルで起動しました！動きました！
![Screenshot 2025-08-15 at 11.11.23.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/76996dac-4a3f-4abf-93fa-3ff00656b7fb.png)

通常であれば、ここでUIの微調整などを行うことになりますが、一旦次に行きます。

## Databricksへのデプロイ

CLIにDatabricks Appsのコマンドがあるので、それらを使っていきます。

アプリを作成します。

```sh
databricks apps create --json '{
  "name": "my-agent-chatbot",
  "resources": [
    {
      "name": "serving-endpoint",
      "serving_endpoint": {
        "name": "'"$SERVING_ENDPOINT"'",
        "permission": "CAN_QUERY"
      }
    }
  ]
}'
```

Databricks側を確認すると、アプリの作成がスタートしています。
![Screenshot 2025-08-15 at 11.12.33.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/171e2445-8b8e-4940-a749-044cb1b8e03e.png)

この時点ではアプリが稼働可能な状態になっているだけなので、ソースコードをアップロードしてアプリにデプロイします。

```sh
DATABRICKS_USERNAME=$(databricks current-user me | jq -r .userName)
databricks sync . "/Users/$DATABRICKS_USERNAME/e2e-chatbot-app"
databricks apps deploy my-agent-chatbot --source-code-path "/Workspace/Users/$DATABRICKS_USERNAME/e2e-chatbot-app"
```

- 1行目: CLIで現在のDatabricksユーザー名を取得
- 2行目: ローカルのファイルをDatabricksのホームディレクトリにコピー
- 3行目: ソースコードをアプリにデプロイ

![Screenshot 2025-08-15 at 11.16.07.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/c31a5029-ee3c-49ea-8a65-5d7cf3ea1f06.png)

処理が完了するとアプリも動くようになっています。

![Screenshot 2025-08-15 at 11.16.41.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/f9fe7cf2-3728-4449-a4d3-f4f877f76b80.png)

以下のコマンドでアプリのURLを取得します。アプリの画面から直接アクセスしても構いません。

```sh
databricks apps get my-agent-chatbot | jq -r '.url'
```
![Screenshot 2025-08-15 at 11.17.00.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/a4e46da6-148c-4d29-b1c9-b40eefbd02aa.png)

先程はローカルでの稼働でしたが、今回はDatabricks上で稼働しています。
![Screenshot 2025-08-15 at 11.17.50.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/1d40f0ac-7ebd-4621-b986-aafda2f107c2.png)

あとは適切にアクセス権を設定すればアプリを共有できるというわけです。

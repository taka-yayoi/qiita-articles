# Databricksにおけるモデルコンテキストプロトコルを用いたエージェントの構築

これまでに、AIアプリケーションとその能力は、LLMのプロンプティングからretrieval-augmented generation (RAG)へと急激に進化し、外部のデータソース、API、ウェブ検索を問い合わせるためのツールにアクセス可能なエージェントAIシステムの開発をスタートするまでとなりました。今では、a) これらのエージェントシステムを構築し、b) あなたのエージェントシステムを実装、オーケストレーション、ツール利用を可能にする数多くのフレームワークが存在しています。

企業組織でエージェント開発を助けるさせる場合、エージェントやツールがどのようにコミュニケーションするのか、新たなツールを広大なエコシステムにどのように組み込むのかに関する標準が間違いなく必要となります。ここで、Anthropicが2024年に開発したModel Context Protocol (MCP)が活躍します。MCPは外部システムに対するエージェント接続のオープンソース標準です(MCPのドキュメントを引用すると「MCPをAIアプリケーションにおけるUSB-Cポートのようなものと考えてください」とのことです)。2026年には、MCPは**業界標準**となりました。MCPの基本学ぶには、[公式ドキュメントウェブサイト](https://modelcontextprotocol.io/docs/getting-started/intro)をご覧ください。

この記事では、DatabricksでどのようにMCPを活用するのかを探索します。このため、[こちらの記事](https://community.databricks.com/t5/technical-blog/building-an-ai-agent-for-transportation-applications-with/ba-p/119459)の旅行エージェントをDatabricksのMCPを活用した完全装備の旅行アシスタントへと拡張します。つまり、このエージェントは任意の目的地に対する最速のルートを提供するためにライブの列車ネットワークデータにアクセスします。はじめに、DatabricksでどのようにMCPを活用できるのかを説明し、AI旅行アシスタントのアーキテクチャを設計します。そして、迅速なテストのためにDatabricks Playgroundでエージェントシステムを構築、テストしますが、このソリューションを評価、プロダクションに展開するためにはコードを使用します。

# DatabricksにおけるMCP - マネージド、外部、カスタムMCPサーバーとは？

MCPは、Unity Catalog(UC)の関数ツール、エージェントコードツールとともに完全に[Databricks Mosaic AI](https://www.databricks.com/jp/product/machine-learning/retrieval-augmented-generation)(開発者が高品質な生成AIアプリケーションを構築、デプロイする助けとなるように設計されたツールスイート)に組み込まれていますので、ユースケース、ガバナンス、柔軟性、統合要件、用途に基づいて決断することができます(いくつかのガイドについては[ドキュメント](https://docs.databricks.com/aws/ja/generative-ai/agent-framework/agent-tool)をご覧ください)。

DatabricksのMCPは3つの方法でデプロイすることができます: マネージドMCPサーバー、外部MCPサーバー、カスタムMCPサーバーです。我々の旅行エージェントの例に沿ってこれらの選択肢をウォークスルーします。以下の図1でエージェントのビルディンググロックを探索しましょう。

*図1: MCPを用いた旅行アシスタントエージェントのハイレベルなアーキテクチャ*

以下の問い合わせに対して有用かつ正確なレスポンスを提供できるエージェントを開発するものとしましょう:

*「スイスのツェルマットにノルディックスキーをしに行きたいです。チューリッヒHBから明日の朝早くに出発したいです。計画を立ててください！」*

調整され、有用な回答を提供するには、汎用的なLLMのレスポンス以上のものが必要です。そこで、この記事で作成する3つのタイプのMCPサーバーを活用します:

- **マネージドMCPサーバー:** [TransportAPI](https://transport.opendata.ch/)からスイスの列車の接続を提供するUC関数。
- **外部MCPサーバー:** リアルタイムで適切なレジャー/スポーツ情報を取得するために[You\.com](https://documentation.you.com/developer-resources/mcp-server)を用いた外部Web検索サービス。
- **カスタムMCPサーバー:** [AccuWeather API](https://developer.accuweather.com/home)からデータを収集できるDatabricks App経由でホストされる[FastMCP](https://gofastmcp.com/getting-started/welcome)実装。

詳細に入ってDatabricksでMCPサーバーの開発を始める前に、それぞれのMCPサーバーが何で、いつ使うべきかをクイックにハイライトしたいと思います。

## マネージドMCPサーバー

DatabricksマネージドのMCPサーバーはすぐに使えるエンドポイントを提供します。これによって、Databricks内部で開発されるAIエージェントと外部のクライアントの両方は、UC関数、Vector Search、Genieスペース、Databricks SQL(DBSQL)エンジンのような機能を活用することができます。すべてのREST APIベースのサーバーは、UC経由でデータ権限とガバナンス作業性されるので、インフラストラクチャの管理は不要です。例えば、UC関数ツールを提供するマネージドMCPは以下のURLパターンで公開されます:

```
https://<workspace-hostname>/api/2.0/mcp/functions/{catalog}/{schema}
```

このURLはDatabricksでデプロイされたエージェントで活用できますが、マネージドMCPを活用したい外部システムによっても利用可能です。サンプルノートブックと詳細については[マネージドMCPのドキュメント](https://docs.databricks.com/aws/ja/generative-ai/mcp/managed-mcp)をご覧ください。

## 外部MCPサーバー

Databricks外でホストされているサードパーティMCPサーバーの活用は、外部MCPサーバーを通じて実装することができます。マネージドのプロキシーエンドポイントとUCのHTTP接続によって、資格情報を公開することなしに、外部ツールやAPIに対するセキュアなアクセスを実現することができます。外部サーバーをインストールするには、DatabricksマーケットプレースでMCPサーバーを特定、インストールするか、カスタムのUC接続を作成します。公開したものは以下のURLパターンを通じて取り扱われます:

```
https://<workspace-hostname>/api/2.0/mcp/external/{connection_name}
```

セットアップガイドやプログラムによる使用例については[外部MCPのドキュメント](https://docs.databricks.com/aws/ja/generative-ai/mcp/external-mcp)をチェックしてください。

## カスタムMCPサーバー

DatabricksカスタムMCPサーバーによって、Databricks AppsとしてサードパーティMCPサーバー実装やご自身のMCPサーバー実装をホストすることができ、エージェントにカスタムツールを公開するシンプルかつ管理された手段を提供します。実装においては、Databricks Appのデプロイが必要であり、サーバーでは(Streamable HTTPのような)HTTP互換のトランスポートを実装する必要があります。アプリのデプロイメント後は、以下のパターンでエンドポイントにアクセスできます:

```
https://<app‑url>/mcp
```

環境セットアップ、MCPサーバーの実装、Databricks Appとしてのサーバーのデプロイに関しては、[ドキュメント](https://docs.databricks.com/aws/ja/generative-ai/mcp/custom-mcp)をご覧ください。(ツールの一覧や起動のために)*WorkspaceClient*の*DatabricksMCPClient*を用いたプログラムによるアクセスには、使用するクライアントに応じた認証機構が必要です(ノートブックにおいては*WorkspaceClient*のデフォルト認証は無効化されているのでサービスプリンシパルが必要であるなど。詳細は[こちら](https://docs.databricks.com/aws/ja/generative-ai/mcp/custom-mcp#%E3%82%AB%E3%82%B9%E3%82%BF%E3%83%A0-mcp-%E3%82%B5%E3%83%BC%E3%83%90%E3%83%BC%E3%81%AB%E6%8E%A5%E7%B6%9A%E3%81%99%E3%82%8B)をご覧ください)。以下のセクションでこのセットアップも説明します。

## DatabricksマネージドMCPサーバーによる列車接続の取得

UC関数をホスト、公開し、Transport APIの*接続*エンドポイントに呼び出しを行うマネージドMCPサーバーからスタートします。APIやUC関数の詳細は[こちらのブログ記事](https://community.databricks.com/t5/technical-blog/building-an-ai-agent-for-transportation-applications-with/ba-p/119459)で確認できます - 詳細はそちらでチェックしてください。こちらがUC関数のコードとなります:

```sql
%sql
CREATE OR REPLACE FUNCTION travel_agents.train_agent.get_connections(
   from_station STRING COMMENT 'The train station of departure',
   to_station STRING COMMENT 'The train station of arrival',
   via_station STRING COMMENT 'The desired stops in between departure and arrival',
   date STRING COMMENT 'Date of the connection, in the format YYYY-MM-DD',
   time STRING COMMENT 'Time of the connection, in the format hh:mm'
)
RETURNS STRING
COMMENT 'Executes a call to the transport api and connections endpoint to retrieve relevant train connections given the input parameters from (departure), to (arrival), via (stops in between, if specified), date, and time.'
LANGUAGE PYTHON
AS $$
import requests

url = "http://transport.opendata.ch/v1/connections"
params = {
   "from": from_station,
   "to": to_station,
   "via": via_station,
   "date": date,
   "time": time,
   "transportations": "train"
}

response = requests.get(url, params=params)
if response.status_code == 200:
   next_connection = response.json()
   return next_connection['connections']
else:
   return f"Failed to retrieve connection. Status code: {response.status_code}"
$$;
```

このコードを実行する前に*travel_agents*カタログと、その配下に*train_agent*を作成しておく必要があることに注意してください。UC関数を作成すると自動的に以下のエンドポイント経由でマネージドMCPサーバーが公開されます:

```
https://<workspace-hostname>/api/2.0/mcp/functions/travel_agents/train_agent
```

ホスト名はお使いのDatabricksワークスペースのURLから決定されます。例えば、Azure Databricksを使っているのであれば、`https://adb-xxxx.yy.azuredatabricks.net/`のようなものになります。上のエンドポイントは当該スキーマを公開し、そのマネージドMCPサーバーの個々のツールとして、当該スキーマで作成されたすべての関数が公開されるということに注意してください。この機能を作成したら、a) 迅速なプロトタイピングのためにPlaygroundで活用、b) エンドポイントURLを取得しPythonでエージェントを実装することができます。次のセクションで両方のオプションを説明します。

## カスタムMCPサーバーによる天気予報の取得

最後に、旅行計画に整合する特定の位置と時間フレームにおける天気予報を取得するための能力で、我々のエージェントシステムを強化したいと思います。この実装では、以下のステップを踏みます:

- カスタムMCPサーバーをホストするためのDatabricks Appのデプロイ
- カスタムMCPアプリケーションを構築するためにFastMCPを用いたMCPアプリテンプレートの活用
- 天気予報を取得するためにAccuWeather APIを使用する2つのツールの実装

Databricks Appをデプロイするには、[Databricks Apps Cookbook](https://apps-cookbook.dev/)で説明されている[ステップ](https://apps-cookbook.dev/docs/deploy)を踏むことができます。Databricks Appsにおける新たなエージェントテンプレートの一つであり内部でFastMCPを使用している「MCP Server - Simple」を活用します。このテンプレートの依存関係はすでにインストールされており、MCPサーバーのヘルスチェックのような運用ツールも同梱されています。

:::note info
**ここで注意すべきこと:** PlaygroundでカスタムMCPサーバーを認識するために、アプリ名の頭で`mcp-`が使用されていることを確認してください。
:::

![](https://community.databricks.com/t5/image/serverpage/image-id/23062i6A75EED41B54CEBE/image-size/large?v=v2&px=999)
*図3: Databricks Appsのエージェントテンプレートを用いたカスタムMCPサーバーの作成*

カスタムMCPサーバーを作成したら、Databricks CLIを用いてローカルIDEにプロジェクトを同期します。お好きなIDEを使うことができます(VSCode、PyCharm、Cursorなど)。Databricks CLIの動作環境と、ワークスペースに対して認証プロファイルが設定されていることを確認してください([ドキュメント](https://docs.databricks.com/aws/ja/dev-tools/cli/install))。以下のCLIコマンドでプロジェクトを同期しましょう:

```sh
databricks workspace export-dir /Workspace/Users/<username>/mcp-weather-assistant -p <profile_name> .
```

これで、内部で2つの異なるAPIコールを行う2つのツールの実装を開始できます。初めに、AccuWeather固有の*location_key*を取得する必要があります。これは、forecast APIは位置に関する文字列を受け付けず、明示的な整数値を受け付けるので必要なステップです。そして、2つのパラメータ: `hourly`や`daily`のように粒度を表す`forecast_type`と、`24hour`や`1day`のフォーマットでホライゾンを表現する`forecast_horizon`を用いて予測を得るために、*location_key*を指定する必要があります。

MCPツールを表す2つの関数を実装します。FastMCPは、MCPの機能を実装するための一連のデコレーターを提供します。*app.py*テンプレートでは、呼び出し可能なツールを宣言するためのデコレータ`@mcp_server.tool`で使用するFastMCPクラスはすでにインスタンス化されています。

AccuWeather Core Weather APIの[ドキュメント](https://developer.accuweather.com/core-weather/location-key-currentconditions)を調査して、*location_key*を取得する以下の関数を実装します:

```py
@mcp_server.tool
def get_location_key_by_city(city_name: str):
      """
      Get the AccuWeather location key for a given city name.This tool searches for a city     
      by name and returns its unique AccuWeather location key, which is required for   
      fetching weather forecasts.

      Args:
          city_name: The name of the city to search for (e.g., "Zurich", "New York")
      Returns:
          dict: Contains 'key' (the location key string) and 'location' (full location     
                details)
      Raises:
          ValueError: If no locations are found for the given city name
          requests.HTTPError: If the API request fails
      """
      url = f"{BASE_URL}/locations/v1/cities/search"
      params = {"apikey": api_key, "q": city_name, "language": "en-us"}

      r = requests.get(url, params=params)
      r.raise_for_status()
      locations = r.json()
      if not locations:
          raise ValueError(f"No locations found for {city_name}")

      return {"key": locations[0]["Key"], "location": locations[0]}
```

取得した位置のディクショナリの最初の要素を返却することで、ベストマッチを提供し、対応する*location_key*を抽出します。次のステップとして、当該位置の予報を取得するためにこの整数値を使用します。このAPIは予測ホライゾン(どのプレミアムプランが必要なのかをチェックください！)において柔軟性があるので、`forecast_type`と`forecast_horizon`パラメータを受け取るツールを実装します:

```py
@mcp_server.tool
def get_24_hours_weather_forecast_by_location_key(location_key: str, 
    forecast_type: str = "hourly", forecast_horizon: str = "24hour"):
    """
    Get weather forecast for a given AccuWeather location key.
    Fetches hourly weather predictions for the forecast type and horizon, including
    temperature, precipitation probability, and weather conditions.

    Args:
        location_key: The AccuWeather location key (obtained from 
                      get_location_key_by_city)
        forecast_type: The type of forecast to fetch (e.g., "hourly", "daily")
        forecast_horizon: The horizon of the forecast to fetch (e.g., "24hour", "72hour", 
                       "1day", "7day")
    Returns:
        list: Array of hourly forecast objects containing:
             - DateTime: ISO timestamp for the forecast hour
             - Temperature: Temperature value and unit (metric/Celsius)
             - IconPhrase: Text description of weather conditions
             - PrecipitationProbability: Chance of precipitation (0-100%)
    """
    url = f"{BASE_URL}/forecasts/v1/{forecast_type}/{forecast_horizon}/{location_key}"
    params = {"apikey": api_key, "language": "en-us", "metric": "true"}
    r = requests.get(url, params=params)
    return r.json()
```

ツール実装の外で2つの変数を宣言していることに注意してください。APIエンドポイントに対応するベースURLと、dbutils経由で取得するAccuWeatherから収集されたAPIキーに対応する*api_key*です([ドキュメント](https://docs.databricks.com/aws/ja/security/secrets/))。

```py
BASE_URL = "https://dataservice.accuweather.com"
api_key = dbutils.secrets.get(scope="<scope-name>", key="<key-name>")
```

最後に、Databricks Appプロジェクトの*tool.py*にこれらのコードスニペットを実装します。完了したら、以下を実行することでDatabricksワークスペースにコードを同期し直すことができます:

```sh
databricks sync --watch . /Workspace/Users/<username>/databricks_apps/mcp-weather-assistant -p <profile_name>
```

そして、以下のCLIコマンドでアプリをデプロイします(UIでデプロイボタンをクリックすることでも同じことが可能です):

```sh
databricks apps deploy mcp-weather-assistant --source-code-path /Workspace/Users/<username>/mcp-weather-assistant
```

これで、カスタムの天気予報MCPサーバーをDatabricksにデプロイすることができました！

- Always produce a short travel plan including:
    - Train connection
    - Weather summary
    - Recommended activity
    - One-line reason linking activity to weather/context
- Replace umlauts in your output.

Workflow (in particular order)
1. Ask for departure station, destination, and activity if missing.
2. Check weather (use daily forecast if >12h ahead).
3. Search local sports/leisure options and pick up to 3 fitting the weather.

Refusal:

次のステップとして、DatabricksワークスペースのAPIとやり取りを行う統合インタフェースであるDatabricks SDKの一部である*WorkspaceClient*を設定する必要があります。

最もシンプルな方法は、ノートブックで*WorkspaceClient*を作成して、Databricksに自動でワークスペースとの接続とパーソナルアクセストークン(PAT)を管理させるというものです。しかし、我々はカスタムMCPサーバーを使用しているので、machine-to-machine (M2M)認証のためのサービスプリンシパルによるOAuthが必要となります。以下では、OAuth M2Mで必要な視覚情報を取得するためのステップを説明しています:

- このアプリケーションで使用するサービスプリンシパル(SP)が作成されていること。アカウント/ワークスペースレベルでのSP作成方法については[ドキュメント](https://docs.databricks.com/aws/ja/admin/users-groups/manage-service-principals#-%E3%82%B5%E3%83%BC%E3%83%93%E3%82%B9%E3%83%97%E3%83%AA%E3%83%B3%E3%82%B7%E3%83%91%E3%83%AB%E3%82%92%E3%82%A2%E3%82%AB%E3%82%A6%E3%83%B3%E3%83%88%E3%81%AB%E8%BF%BD%E5%8A%A0%E3%81%99%E3%82%8B)をご覧ください。
- SPにワークスペースアクセス権源、(ツールが必要とする場合)Databricks SQLアクセス(これらのオプションはSPの設定タブで確認できます)。
- [ドキュメント](https://docs.databricks.com/aws/ja/dev-tools/auth/oauth-m2m#-%E3%82%B9%E3%83%86%E3%83%83%E3%83%97-1-oauth-%E3%82%B7%E3%83%BC%E3%82%AF%E3%83%AC%E3%83%83%E3%83%88%E3%82%92%E4%BD%9C%E6%88%90%E3%81%99%E3%82%8B)のステップに従い、dbutilsを用いて再度クライアントIDとシークレットを格納します。
- SPに以下の権限があることを確認ください:
  - マネージドMCPサーバーを使用するための*EXECUTE UC FUNCTION*(*USE CATALOG*と*USE SCHEMA*の権限も追加)
  - 外部MCPサーバーをポイントするUC接続に対する*CAN USE*
  - ガスタムMCPサーバーをホストするDatabricks Appに対する*CAN USE*

これで、*WorkspaceClient*を作成するためにSP資格情報(dbutilsで格納されたクライアントIDとシークレット)を使う準備ができました。サンプルノートブックでは、PATを用いた標準の*WorkspaceClient*宣言をコメントアウト、削除することができます。

```py
import os

client_id = dbutils.secrets.get(scope="<scope-name>", key="<client-id>")
client_secret = dbutils.secrets.get(scope="<scope-name>", key="<client-secret>")

mcp_server_workspace_client = WorkspaceClient(
    host="https://adb-984752964297111.11.azuredatabricks.net/",
    client_id=client_id,
    client_secret=client_secret,
    auth_type="oauth-m2m",  # Enables service principal authentication
)
```

認証が成功したら、3つのMCPサーバーを定義するために*DatabricksMultiServerMCPClient*を活用します。OAuth M2MでSPを使用するので、上のWorkspaceClientオブジェクトはそれぞれのサーバーオブジェクトに引き渡されます:

# テスト、評価、プロダクションへのエージェントのデプロイ

マルチツールのエージェントの信頼性、効率性を確実なものにするために、プロダクションへのデプロイの前に厳密なテスト、評価が重要です。DatabricksのMosaic AI Agent Evaluationはエージェントのパフォーマンスの評価に対する包括的、構造化されたアプローチを提供します。

このフレームワークでは、LLM-as-a-judgeパターンを用いたプログラム的な評価をサポートしており、正解データシナリオの定義、シナリオに対するエージェントの実行、メトリクスの自動計算を可能にします。これによって、異なるLLMエンドポイント、プロンプトのバリエーション、MCPサーバー設定におけるA/Bテストが可能となります。このプロジェクトで使っているノートブックには、評価フレームワークの使い方の基礎が含まれています。LLM-as-a-judgeは[こちら](https://docs.databricks.com/aws/ja/mlflow3/genai/eval-monitor/concepts/scorers)で詳細が説明されています。

エージェントがパフォーマンス指標に合格したら、デプロイメントの準備ができました。このノートブックにはプロダクションへのパスに至る2つのステップが含まれています:

1. **MLflowの登録:** LangGraphベースのエージェントコードは、MLflowを用いて記録、Unity Catalogに登録され、エージェントモデルに対する明確なリネージとバージョン管理を確立します。
1. **モデルサービングエンドポイント:** 登録されたエージェントは、Databricksにおける低レーテンシーモデルサービングエンドポイントとしてデプロイすることができます。このプロセスは、必要なインフラストラクチャのスケーリングや、ツールアクセスのためのOAuth M2M設定に自動的に対応します。

最後に、エージェントに対するあなた自身のフロントエンドを作成したいのであれば、あなたのアプリケーションをホストし、デプロイされたモデルサービングエンドポイントを呼び出す、専用のDatabricks Appをデプロイすることができます。サンプルは[こちら](https://apps-cookbook.dev/docs/streamlit/aiml/ml_serving_invoke/)のDatabricks Apps Cookbookで確認することができます。

# まとめ

このブログ記事では、DatabricksにおけるModel Context Protocol (MCP)を活用することで、どのようにして洗練されたエージェント旅行アシスタントアプリケーションを構築するのかをデモンストレーションしました。a) APIから列車接続を取得し、b) you.comによるWeb検索を行い、c) 特定の場所の天気予報を取得できる3つの異なるMCPサーバー(マネージド、外部、カスタム)のインテグレーションを説明しました。ここでは、DatabricksのAgent FrameworkとUnity Catalogを通じた企業規模のエージェント開発のためのスケーラブルでセキュア、管理されたパスをハイライトしました。

**要点:**

1. **MCPがツールの相互運用性を標準化します:** Model Context Protocol (MCP)は、Databricksサービスと外部システムへのシームレスでオーケストレートされたアクセスを確実にすることで、組織におけるAIエージェント開発のスケーリングで重要な標準化されたインタフェースとして動作します。
1. **包括的なMCPサポートと相互運用性:** DatabricksはMCPプロトコルを完全にサポートし、開発者にガバナンスとセキュリティに対する最大の柔軟性を提供します。このサポートには、マネージド、外部、カスタムMCPサーバーのパターンが含まれます。さらに、このアーキテクチャによって、外部サービスが管理されたエンドポイント経由でDatabricksサービスを利用できるにし、発見可能性と双方向のコミュニケーションを確実なものにします。
1. **プロダクションへのセキュアで構造化されたパス:** このプラットフォームは、明確なプロダクションパス、Databricks Playgroundからコード(LangGraph)でのエージェントの定義への移行、OAuthによるアクセスの保護、MLflowとモデルサービングエンドポイントを通じたエージェントのデプロイを提供し、信頼でき、管理されたエージェントベースのAIを確実なものとします。MLflowによる継続的モニタリングと厳密な評価による継続的改善とシステムの信頼性をドライブしましょう。

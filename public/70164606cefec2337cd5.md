> **ジョブ向け SQL アラートタスク (Beta)**
> Databricks ジョブに SQL アラートタスクを追加し、ワークフローの一部として Databricks SQL アラートを評価できるようになりました。SQL アラートタスクを使用することで、データパイプライン内での自動条件チェックと通知が実現できます。詳細は[ジョブ向け SQL アラートタスク](https://docs.databricks.com/aws/ja/jobs/alert)を参照してください。

# はじめに

Databricks SQL のアラート機能は、2025年に大きく刷新されました。新しい「Databricks SQL アラート」(Public Preview) と、Jobs パイプラインに組み込むための「SQL アラートタスク」(Beta) が登場したことで、選択肢が増えた反面、何をどう使えばよいか混乱しやすくなっています。

本記事では以下の3つを整理した上で、実践的な使い分け方を解説します。

- レガシーアラート (従来の SQL アラート)
- 新しい Databricks SQL アラート
- SQL アラートタスク (Lakeflow Jobs のタスクタイプ)

# 3つの概念の整理

![Screenshot 2026-03-23 at 8.48.53.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/832a6350-1a5a-4287-b9bd-3e93e9657fd3.png)

## レガシーアラート

レガシーアラートは Databricks SQL アラートの初代バージョンです。ワークスペースに保存された既存のクエリを参照してアタッチし、定期的に実行して条件を評価し、条件を満たした場合に通知を送る仕組みです。

主な特徴は以下のとおりです。

- 既存の保存済みクエリを再利用してアタッチできる
- パラメータ付きクエリをサポート (SQL エディタのデフォルト値を使用)
- アラートのステータスは `OK` / `TRIGGERED` / `ERROR` / `UNKNOWN` の4種類
- Jobs の Alert タスクタイプとして利用可能
- Git 連携非サポート

SDK では `w.alerts_legacy` として提供されており、deprecated 扱いになっています。

## 新しい Databricks SQL アラート (Public Preview)

2025年にリリースされた最新のアラートです。アラート作成・管理のすべてを新しいマルチタブエディタで一元的に行える設計になっています。

レガシーアラートからの主な変更点は以下のとおりです。

- **クエリの独立性**: アラートがクエリ定義を所有し、既存の保存済みクエリは再利用できない。各アラートがクエリを内包する設計
- **ステータスの簡略化**: `UNKNOWN` が廃止され、`OK` / `TRIGGERED` / `ERROR` の3種類に整理
- **Jobs 連携**: SQL アラートタスク (Beta) として Lakeflow Jobs から呼び出せる
- **Git 連携**: Databricks Git フォルダでバージョン管理が可能
- **制約**: Public Preview 期間中はパラメータ付きクエリを非サポート

## SQL アラートタスク

https://docs.databricks.com/aws/ja/jobs/alert

SQL アラートタスクは Lakeflow Jobs のタスクタイプの1つです。アラートそのものではなく、**既存のアラートをジョブパイプラインの中で実行するための仕組み**です。

重要な点として、SQL アラートタスクは新しい Databricks SQL アラートのみを対象としており、レガシーアラートはサポートされていません。

# アラートと SQL アラートタスクの違い

混乱しやすいポイントなので改めて整理します。

| 観点 | アラート (単体) | SQL アラートタスク |
|------|--------------|----------------|
| 存在場所 | Databricks SQL の独立オブジェクト | Lakeflow Jobs のタスクの1つ |
| 管理場所 | サイドバーの Alerts | Jobs & Pipelines |
| スケジュール | アラート自身が保持 | ジョブのスケジュールで制御 |
| 他タスクとの依存関係 | なし | 設定可能 |
| 主目的 | データの定期監視・通知 | パイプラインへの監視の組み込み |
| パラメータ | 非サポート (Preview 中) | 非サポート |

SQL アラートタスクを実行しても、アラート自体に設定されたスケジュールには影響しません。また、SQL アラートタスクがレポートするステータスは以下の2種類のみです。アラートの条件がトリガーされたかどうかは関係なく、クエリが正常に実行できたかどうかで判定されます。

- `Succeeded`: 条件のトリガー有無に関わらず、アラートの評価が正常に完了した
- `Failed`: SQL ウェアハウスの接続問題やクエリエラーなど、評価中にエラーが発生した

# 使い分けのガイド

## シンプルな定期監視ならアラート単体

「毎朝売上が閾値を下回ったら Slack に通知する」のような用途であれば、アラート単体で完結します。SQL アラートタスクを使う必要はありません。

## パイプラインへの組み込みなら SQL アラートタスク

以下のようなユースケースでは SQL アラートタスクを使います。

- データ取り込みジョブが完了した後にデータ品質をチェックしたい
- 複数の処理ステップの中に監視を組み込みたい
- 他のタスクが失敗したときにアラート評価をスキップしたい

具体的には次のようなパイプラインが構成できます。

```
[ノートブック: System Tables からデータ集計]
         ↓
[SQL アラートタスク: 集計結果をアラートで評価・通知]
```

## パラメータが必要ならレガシーアラートか SQL タスク

パラメータ付きクエリが必要な場合、現時点では新しい SQL アラートも SQL アラートタスクもサポートしていません。この場合はレガシーアラートを継続して使うか、SQL タスクでクエリを実行する方法を検討してください。

# SQL アラートタスクの設定手順

## 前提条件

- ワークスペース管理者がプレビューを有効化していること (プレビューページから設定)
- ワークスペースに既存の新しい Databricks SQL アラートが存在すること
- 対象アラートに対して CAN RUN 以上の権限があること
- サーバーレスまたは Pro SQL ウェアハウスへのアクセス権があること

![Screenshot 2026-03-23 at 8.31.08.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/83f0db2d-2f6c-4af7-9ae0-c79fab9b31e3.png)

## 設定手順

1. ワークスペースのサイドバーから **ジョブとパイプライン** を開き、**作成 > ジョブ**をクリック
2. 対象のジョブを開き、**別のタスクタイプを追加** をクリック
3. **SQLアラート** を検索して選択
![Screenshot 2026-03-23 at 8.36.00.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/50047c90-bdb4-4d41-9fc6-eba6be592d4b.png)
4. **タスク名** を入力
5. **アラート** ドロップダウンから評価したい SQL アラートを選択
6. (任意) **SQLウェアハウス** ドロップダウンからウェアハウスを選択。未設定の場合はアラート内部のウェアハウスが使用される
7. (任意) **サプスクライバ** ドロップダウンで通知先を設定。未設定の場合はアラートに設定されたサブスクライバーが使用される
![Screenshot 2026-03-23 at 8.37.13.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/7fa7b466-91f0-4d29-95ca-421e50dfd5f5.png)
8. **タスクを保存** をクリック

# レガシーアラートから新アラートへの移行

両方のアラートは並行して使い続けることができます。アラート一覧画面では **アラート** タブに新しいアラート、**レガシーアラート** タブにレガシーアラートが表示されます。

移行を急ぐ必要はありませんが、以下の点から中長期的には新アラートへの移行を検討することをおすすめします。

- Jobsパイプラインへの組み込み (SQLアラートタスク) は新アラートのみ対応
- レガシーアラートの SDK は deprecated 扱いになっている
- Git連携など新機能は新アラートにのみ追加されていく

# 現時点の制約まとめ

SQL アラートおよび SQL アラートタスクはいずれもプレビュー段階のため、以下の制約があります。GA 時に変更される可能性があります。

- SQL アラートタスクは Beta 機能。利用にはワークスペース管理者によるプレビュー有効化が必要
- パラメータ付きクエリは新アラート・SQL アラートタスクともに非サポート
- SQL アラートタスクはサーバーレスまたは Pro SQL ウェアハウスが必要

# まとめ

Databricks のアラート機能を整理すると以下のようになります。

- **レガシーアラート**: 既存クエリを参照する従来方式。パラメータ対応。deprecated 扱い
- **新 SQL アラート**: クエリを内包する新方式。Git 連携・Jobs 連携対応。Public Preview
- **SQL アラートタスク**: 新アラートを Jobs パイプラインに組み込むタスクタイプ。Beta

シンプルな定期監視にはアラート単体、パイプラインへの統合には SQL アラートタスクという使い分けが基本になります。パラメータが必要な場合は当面レガシーアラートや SQL タスクで対応する必要があります。

今後 GA に向けてパラメータ対応など機能が充実していくと思われるため、引き続きリリースノートをウォッチしておくことをおすすめします。

# はじめに

Databricksの Unity AI Gateway が刷新され、左側のナビゲーションに新しい AI Gateway (ベータ) が登場しました。画面は「モデル」「プロバイダー」「MCP」「スキル」「エージェント」のタブ構成になり、これまでモデルサービングエンドポイント単位で設定していたモデルやMCPが、この Gateway 配下で一元的に設定・統治されるようになっています。

この記事では、最新構成 (ベータ) を二部構成で整理します。前半では、Unity AI Gateway が何を目指すものなのか、その全体像を DAIS 2026 の発表を引用しながら紹介します。後半では、新しい画面構成 (5つのタブ) のうち主要なタブを実機で確認し、「作る → 使う → 見る → 繋ぐ」の基本動線をウォークスルーとして辿ります。

なお、新しい AI Gateway は現時点でベータ版であり、画面が先行してドキュメントの整備が追いついていない箇所があります。該当箇所はその旨を明記します。

# Unity AI Gateway とは (DAIS 2026 の発表より)

Unity AI Gateway は、エージェント・LLMエンドポイント・MCPサーバー・コーディングエージェント向けの、Databricks の中央 AI ガバナンスレイヤーです。プロバイダーを横断した使用状況の分析、権限の設定、ガードレールの適用、容量の管理を、一箇所から行えます ([Unity AI Gateway](https://docs.databricks.com/aws/ja/ai-gateway/))。

DAIS 2026 では、この Unity AI Gateway を軸に、Unity Catalog のガバナンス対象を「データ」から「AI資産」へと広げる方針が示されました。発表では、Unity Catalog を拡張し、Databricks がホストするモデル・外部モデルプロバイダー・MCPサービス・エージェント・スキルを、組織がすでにデータに使用しているものと同じガバナンスフレームワークで登録・検出・保護・監査できるようになった、とされています。Unity Catalog と Unity AI Gateway が連携することで、AI資産とAIインタラクションの両方に統一されたガバナンスレイヤーを提供する、という位置づけです (出典: [Data + AI Summit 2026におけるAIガバナンス：Unity AI Gatewayの最新情報](https://www.databricks.com/jp/blog/ai-governance-data-ai-summit-2026-whats-new-unity-ai-gateway))。

つまり、これまでバラバラに管理されがちだったモデルやツールを、Unity Catalog という一つの傘の下に集約し、その上で Unity AI Gateway がランタイムの統治 (誰が・何に・何をしたか) を担う、という構図です。基盤モデルサービスは最初から用意され、Google Drive・Jira・Confluence・Slack・GitHub・SharePoint などのアプリケーション向けには managed MCP サービスが提供されます。

# 旧構成と新構成

新しい AI Gateway はベータ版で、アカウント管理者がアカウントコンソールの「プレビュー」ページから有効化します ([プレビューの管理](https://docs.databricks.com/aws/ja/admin/workspace-settings/manage-previews))。ベータ版の期間中は料金が発生しません。

従来の AI Gateway は、個々のモデルサービングエンドポイントに対して、使用状況の追跡やガードレールなどの機能をトグルする形でした。新しい AI Gateway は、この「エンドポイント単位で機能を付ける」発想から、「中央のレイヤーがAI資産を一元統治する」発想へと作り直されています。本記事ではレガシー側には深入りせず、新しい構成にフォーカスします。

# 新しい画面構成: 5つのタブ = 5つのAI資産

新しい AI Gateway を開くと、上部に5つのタブが並びます。

![Screenshot 2026-06-24 at 15.29.36.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/7d4414ae-8cbf-4c2c-9ffb-b9021d06f56f.png)

![unity_ai_gateway_5assets.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/1d643bef-76a6-463e-b654-d72cf4eb22a0.png)


この5つのタブは、DAIS 2026 で示された「5つのAI資産」とそのまま対応しています。

- モデル: Databricks がホストするモデル (モデルサービス)
- プロバイダー: 外部モデルプロバイダー (モデルプロバイダーサービス)
- MCP: managed / 外部 / カスタムのMCPサービス
- スキル: 再利用可能なスキルのインベントリ
- エージェント: 登録されたエージェントエンドポイント

いずれも Unity Catalog のオブジェクトとして登録され、UCの権限・リネージ・クロスワークスペースのガバナンスを引き継ぎます。以降、タブごとに見ていきます。

# モデル (モデルサービス)

「モデル」タブには、Databricks がホストする基盤モデル (system.ai 配下の claude-opus-4-8 など) が、Unity Catalog 上の「モデルサービス」として並びます。画面上部には「New! Model services in Unity Catalog」というバナーが表示され、モデルサービスがUCの権限・リネージ・クロスワークスペースのガバナンスを継承することが示されています。

![Screenshot 2026-06-24 at 15.31.26.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/742c44a2-5d71-454f-9705-1b56c7fa988c.png)

用語に一点注意があります。UI上は「モデルサービス」と呼ばれますが、ドキュメント上は「Unity AI Gatewayエンドポイント」という名前で、エンドポイント名とプライマリモデルを構成して作成する、と説明されています ([エンドポイントの設定](https://docs.databricks.com/aws/ja/ai-gateway/configure-endpoints-beta))。同じものを指していると考えて差し支えありません。

作成は、カタログ・スキーマ・名前を指定し (名前は作成後に変更できません)、配信先となるモデルを選ぶ、という流れです。

![Screenshot 2026-06-24 at 15.32.12.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/62239190-354c-4d83-908e-8e2d4daa27d9.png)

なお、旧来の「ワークスペースエンドポイント」については、Unity Catalog 管理外であり近く非推奨になる旨の予告が表示され、UCのモデルサービスへの移行が案内されます。

# プロバイダー (モデルプロバイダーサービス)

「プロバイダー」タブは、外部モデルプロバイダーを Unity Catalog に登録するためのタブです。何も登録していない状態では「Create a Model Provider Service to register a foundation model provider in Unity Catalog」と表示されます。

![Screenshot 2026-06-24 at 15.38.44.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/e672bc12-65f3-43db-b17f-b9c1dc647523.png)

「+ Provider」から作成画面を開くと、OpenAI・Azure OpenAI・Anthropic・Microsoft Foundry・Gemini Enterprise・Amazon Bedrock・カスタムからプロバイダーを選び、APIキーとベースURLを設定し、提供するモデルを選ぶ、という構成になっています。

![Screenshot 2026-06-24 at 15.39.02.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/02257924-23ec-49b2-94ee-67371288191f.png)

これは、旧来の「外部モデル」を Unity Catalog のオブジェクトとして登録し直したもの、と捉えると分かりやすいです。外部モデルは Databricks 外でホストされるサードパーティのモデルで、OpenAI や Anthropic などのプロバイダーの利用と認証情報を一元管理できます ([外部モデル](https://docs.databricks.com/aws/ja/generative-ai/external-models/))。旧来はServingの外部モデルサービングエンドポイントとして作っていたものが、新構成では「プロバイダー → モデルプロバイダーサービス」としてUC配下に登録される形に移りました。

注意点として、この「モデルプロバイダーサービス」については、ベータの専用操作ドキュメントが現時点では見当たりません。考え方は上記の外部モデルのページが近いものの、画面と手順は新しいUIと異なります。

# MCP

「MCP」タブには、Databricks が管理する MCP サーバーが並びます。MCP はエージェントをツールやデータに接続するためのオープン標準で、Databricks では MCP サーバーが Unity AI Gateway によって管理され、すべての MCP インタラクションの可視性・アクセス制御・監査ログが提供されます ([MCP概要](https://docs.databricks.com/aws/ja/generative-ai/mcp/))。

接続できる MCP サーバーは3系統です。

- managed MCP: AI検索・Genie Space・Databricks SQL・Unity Catalog関数向けの事前構成済みサーバー。セットアップ不要 ([managed MCP](https://docs.databricks.com/aws/ja/generative-ai/mcp/managed-mcp))
- 外部MCP: マネージド接続で Databricks 外のサーバーに安全に接続 ([外部MCP](https://docs.databricks.com/aws/ja/generative-ai/mcp/external-mcp))
- カスタムMCP: Databricks Apps としてホストする独自サーバー ([カスタムMCP](https://docs.databricks.com/aws/ja/generative-ai/mcp/custom-mcp))

managed MCP は常に Unity Catalog の権限を強制し、on-behalf-of-user の認証が効くため、エージェントもユーザーも、許可されたツール・データにしかアクセスできません。

なお、以前の Vector Search は AI検索に改名され、URLも `/api/2.0/mcp/ai-search/...` となりました。また Databricks SQL サーバー (`/api/2.0/mcp/sql`) が新たに加わっています。

# スキルとエージェント

残る「スキル」と「エージェント」タブも、DAIS 2026 で示された5つのAI資産の一部です。本記事では、現時点で実機での操作確認ができていないため、位置づけの紹介にとどめます。

スキルは、ガイダンス・ベストプラクティス・再利用可能なコード・実行可能スクリプトをまとめた、ドメイン固有のタスク向けのパッケージです。Agent Skills というオープン標準に従います ([Genie Codeのスキル](https://docs.databricks.com/aws/ja/genie-code/skills))。DAIS 2026 では、Unity Catalog がガバナンスされた再利用可能なスキルのインベントリを提供し、チームがエージェントエンドポイントを登録し、承認されたスキルを公開して、組織全体で検出可能にできるようになった、と発表されました。

エージェントは、登録されたエージェントエンドポイントを統治・発見可能にするものです。

これら2つのタブはベータの操作ドキュメントがまだ薄く、UIが先行している状態です。具体的な登録・公開の手順は、別記事で改めて検証する予定です。

# ウォークスルー: 最新構成を一周する

ここからは、最新構成の基本動線を「作る → 使う → 見る → 繋ぐ」の順に辿ります。前提として、新しい AI Gateway ベータが有効で、サーバーレスコンピュートが有効、対象のスキーマや Genie space、AI Search インデックスに Unity Catalog の権限がある状態とします。

## ステップ1: 画面構成を掴む

左側のナビゲーションから AI Gateway を開き、「モデル」「プロバイダー」「MCP」「スキル」「エージェント」の5タブと、各エンドポイントの設定群がどう並んでいるかを確認します。ここが全体の地図になります。

## ステップ2: モデルサービス (エンドポイント) を作る

「モデル」タブから「+ Model」(Unity AI Gatewayエンドポイントの作成) を開きます。カタログ・スキーマ・名前を指定し (名前は作成後に変更できません)、配信先となるモデルを選んで作成します。作成後、`catalog.schema.name` の Unity Catalog オブジェクトとして登録されることを確認します ([エンドポイントの設定](https://docs.databricks.com/aws/ja/ai-gateway/configure-endpoints-beta))。

作ったエンドポイントを実際に呼び出します。AI Playground の場合は、モデル選択で「モデルのタイプ」を Model Service にし、作成したサービスを選んで応答を確認します。コードの場合は、OpenAI クライアントからエンドポイントを叩きます ([エンドポイントへのクエリ](https://docs.databricks.com/aws/ja/ai-gateway/query-endpoints-beta))。

## ステップ4: 使われ方を見る

ガバナンスの基本として、使われ方を確認します。使用状況は `system.ai_gateway.usage` システムテーブルに記録されます (アカウント管理者が `ai_gateway` システムテーブルスキーマを有効化している必要があります)。リクエストとレスポンスの中身まで見たい場合は、推論テーブルを有効化します (指定したカタログ・スキーマに `CREATE TABLE` 権限が必要です)。ステップ3で投げたリクエストがここに現れれば、「作る → 使う → 見える」が繋がります ([使用状況の監視](https://docs.databricks.com/aws/ja/ai-gateway/usage-tracking-beta)、[推論テーブル](https://docs.databricks.com/aws/ja/ai-gateway/inference-tables-beta))。

## ステップ5: (任意) プロバイダーで外部モデルを登録する

「プロバイダー」タブから「+ Provider」を開き、OpenAI や Anthropic などのプロバイダーを選びます。APIキー (シークレット参照を推奨) とベースURLを設定し、提供するモデルを選んで登録します。登録後、外部モデルが Unity Catalog のオブジェクトとして見えることを確認します。

![Screenshot 2026-06-24 at 15.46.30.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/971c53a6-2a23-48e4-a70e-68b7740e359e.png)

## ステップ6: MCPと組み合わせる

最後に MCP と組み合わせます。ここで一点注意があります。MCP (Tools) を利用できるのは、ツール呼び出しに対応したモデルサービスに限られます。AI Playground のエンドポイント選択画面で「モデルサービス」のタイプ欄を見ると、Claude や Gemini など `system.ai` 配下のツール対応モデルサービスには🔧アイコンが付いています。一方、ステップ2で自分で作成したモデルサービスにはこのアイコンが付かず、ツールを設定できません。

そのため、MCP を試す際は、🔧アイコンが付いたツール対応のモデルサービス (例: `system.ai` 配下の Claude や Gemini) を選びます。その上で managed MCP (Genie・AI検索・Unity Catalog関数など) を有効化し、ツールが発火することを確認します ([managed MCP](https://docs.databricks.com/aws/ja/generative-ai/mcp/managed-mcp))。

# エンドポイントに付与できるガバナンス機能 (概観)

モデルサービス (エンドポイント) には、設定をトグルすることで以下のガバナンス機能を付与できます。本記事では一覧の紹介にとどめ、個別の深掘りは別記事に譲ります。

- 使用状況の追跡 (デフォルトで有効、`system.ai_gateway.usage`): [ドキュメント](https://docs.databricks.com/aws/ja/ai-gateway/usage-tracking-beta)
- 推論テーブル (リクエスト/レスポンスを Unity Catalog の Delta テーブルに記録): [ドキュメント](https://docs.databricks.com/aws/ja/ai-gateway/inference-tables-beta)
- レート制限 (QPM/TPM をエンドポイント・ユーザー・グループ単位で設定): [ドキュメント](https://docs.databricks.com/aws/ja/ai-gateway/rate-limits-beta)
- ガードレール (PII検出やコンテンツモデレーションなどのポリシー): [ドキュメント](https://docs.databricks.com/aws/ja/ai-gateway/guardrails)
- フォールバック (プライマリモデルが 429/5XX を返したとき、別のモデルへ順に切り替え)
- トラフィック分割 (複数のモデルバックエンドにトラフィックを割合で分散): [ドキュメント](https://docs.databricks.com/aws/ja/ai-gateway/configure-traffic-splitting-beta)
- コーディングエージェント統合 (Cursor・Gemini CLI・Codex CLI・Claude Code): [ドキュメント](https://docs.databricks.com/aws/ja/ai-gateway/coding-agent-integration-beta)

# まとめ

今回の刷新の要点は、Databricks がホストするモデル・外部モデルプロバイダー・MCPサービス・スキル・エージェントという5つのAI資産が、Unity Catalog という同じ傘の下に揃い、Unity AI Gateway がそれらを統治する構造になった、という点です。新しい AI Gateway の5つのタブを「5つのAI資産」と対応づけて捉えると、画面全体が腹落ちします。

なお、ウォークスルーで見たように、MCP (Tools) を組み合わせられるのはツール対応のモデルサービスに限られ、自分で作成したモデルサービスはツール非対応です。MCP を試す際は🔧アイコン付きのモデルサービスを選んでください。

今後は、コスト管理・統合トレーシング・Service Policies など、DAIS 2026 で予告された機能が順次乗ってきます。まずは本記事で辿った「作る・使う・見る」の土台を押さえておけば、機能が増えても追従しやすくなります。

streamlitはまあまあ触ったことはあるのですが、今の時代一からコーディングするのもあれなので、Claude Codeを使ったDatabricks Appsのバイブコーディングに挑戦してみました。

# 最初のアプローチ: 全部Claude Codeにやってもらう

`databricks-apps`というフォルダを作って、その中で`/init`したら、必要なライブラリをインストールしてくれたり、アクセス先のDatabricksの接続設定を聞いてきたりしてくれて驚きました。

そして、Databricksワークスペースへのデプロイには[Databricks Asset Bundles](https://docs.databricks.com/gcp/ja/dev-tools/bundles/)までも使ってくれるという。
![Screenshot 2025-07-11 at 13.34.15.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/fa3424e2-6be3-46f2-9693-273cf63e688c.png)

[Databricks CLI](https://docs.databricks.com/aws/ja/dev-tools/cli/commands#%E3%82%A2%E3%83%97%E3%83%AA%E3%81%AE%E3%82%B3%E3%83%9E%E3%83%B3%E3%83%89)を使ってアプリも起動してくれます。

しかし、アプリが起動しても以下のようなメッセージでアクセスできませんでした。

> App Not Available
>  Sorry, the Databricks app you are trying to access is currently 
> unavailable. Please try again later.

生成されたファイルを見てみると、Databricks Appsのお作法には正確に従っていない感じでした。あと、アプリが起動していない状態でコードをデプロイしようしたりと、思った通りの挙動になってくれませんでした。ということで、アプローチ変更です。

# 2番目のアプローチ: Claude.mdで指示

この辺のマニュアルの情報を盛り込みます。途中試行錯誤したのちこんな感じになりました。事前にアプリ自体は作っておいて、コードのみをデプロイする形にしています。

https://docs.databricks.com/aws/ja/dev-tools/databricks-apps/app-runtime

````md
# 使用するコマンド

## ワークスペースへのコードの同期
databricks sync  . /Workspace/Users/takaaki.yayoi@databricks.com/databricks_apps

## アプリの起動

databricks apps start taka-test

アプリが停止している場合、起動には2-3分を要しますので、起動中の際にはアプリのコードのデプロイは待ってください。

## アプリへのコードのデプロイ
databricks apps deploy taka-test \
   --source-code-path /Workspace/Users/takaaki.yayoi@databricks.com/databricks_apps

## ローカルでのStreamlit起動手順

### 1. 仮想環境の作成（初回のみ）
```bash
python3 -m venv venv
```

### 2. 仮想環境の有効化と依存関係のインストール（初回のみ）
```bash
source venv/bin/activate
pip install -r requirements.txt
```

### 3. Streamlitアプリの起動
```bash
source venv/bin/activate
streamlit run app.py
```

または、バックグラウンドで実行する場合：
```bash
source venv/bin/activate
nohup streamlit run app.py > streamlit.log 2>&1 &
```

### 4. アクセス
以下のURLでアプリにアクセスできます：
- http://localhost:8501
- http://127.0.0.1:8501

### 注意事項
- ローカル環境では、Unity Catalogテーブルの代わりにダミーデータが表示されます
- プロセスを停止する場合は `pkill -f streamlit` を使用してください
   
# ファイルの説明

## app.py

アプリの実装。

## requirements.txt

依存ライブラリを列挙。必要な依存関係が追加された場合には更新してください。

## app.yaml

アプリの実行方法を定義します。

# コード更新後の挙動

- ローカルでテストしたいので、ローカルで起動させてください。
````

# まとめ

Claude Codeを活用することで、Databricksでも推奨している[以下のフロー](https://docs.databricks.com/aws/ja/dev-tools/databricks-apps/app-development)を実現することができました。

```
[ローカル開発]          [Databricks ワークスペース]
     |                          |
  開発・テスト      →      デプロイ・本番運用
     |                          |
  高速な反復開発          スケーラブルな実行環境
```

しかも、コード自体は一行も書かずに実装できてしまいます。今後は、Databricksのリソース(SQLウェアハウス、モデルサービング、Genieなど)を活用したアプリをバイブコーディングで作ってみます。

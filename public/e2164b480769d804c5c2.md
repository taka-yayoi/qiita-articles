# はじめに

[apx](https://github.com/databricks-solutions/apx) は Databricks Apps を構築するためのツールキットです。開発・ビルド・デプロイのライフサイクル全体をカバーしており、React（フロントエンド）と FastAPI（バックエンド）を組み合わせたフルスタックアプリを手軽に作れます。

https://databricks-solutions.github.io/apx/

この記事では apx を使ってローカルで開発し、Databricks Apps としてデプロイするまでの手順をまとめます。

# 技術スタック

apx が生成するプロジェクトの技術スタックは以下のとおりです。

| 役割 | 技術 |
|------|------|
| フロントエンド | React + TypeScript + Vite + Tailwind CSS + shadcn/ui |
| バックエンド | FastAPI + Pydantic |
| 依存管理（Python） | uv |
| 依存管理（JavaScript） | Bun |
| コア（CLIツール本体） | Rust |

# 前提条件

- Databricks CLI がインストール済みで認証済みであること
- Databricks のウェアハウス ID を把握していること

# インストール

macOS / Linux の場合は以下のコマンドでインストールできます。

```bash
curl -fsSL https://databricks-solutions.github.io/apx/install.sh | sh
```

インストール後はバージョンを確認しておきましょう。

```bash
apx --version
```

# プロジェクトの初期化

プロジェクトを作成したいディレクトリに移動し、`apx init` を実行します。

```bash
cd ~/Workspace
apx init myapp -n myapp
```

`[APP_PATH]` はプロジェクトを作成するパスで、`-n` はアプリ名です。省略するとどちらも対話形式で入力を求められます。

![Screenshot 2026-03-05 at 11.42.37.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/47d327de-f6d9-48ed-85ca-60a75c0f389d.png)

## アドオンの選択

初期化時にアドオンを選択できます。スペースキーで選択、Enterキーで確定です。

| アドオン | 内容 |
|---------|------|
| ui | React + Vite + TanStack Router によるフロントエンド |
| sidebar | サイドバーナビゲーション（ui を含む） |
| sql | SQLウェアハウス接続 |
| lakebase | Lakebase（Postgres）連携 |
| claude | Claude Code 向けのスキル・MCP 設定・フック |
| cursor | Cursor IDE 向けのルール・MCP 設定 |

今回は `sidebar`・`sql`・`claude` を選択しました。

# 環境変数の設定

プロジェクトルートに `.env` ファイルが生成されています。デフォルトでは以下のような内容になっています。

```
# this is an example dotenv file.
# to pass properties into your app, use following format:
# MYAPP_PROP1=SOMETHING
DATABRICKS_CONFIG_PROFILE=DEFAULT
```

`DATABRICKS_CONFIG_PROFILE` を実際のプロファイル名に変更します。また、sql アドオンを追加した場合、起動時に `DATABRICKS_SQL_WAREHOUSE_ID` が必須であることがエラーから判明したため、合わせて追記します。

```
DATABRICKS_CONFIG_PROFILE=<your-profile>
DATABRICKS_SQL_WAREHOUSE_ID=<your-warehouse-id>
```

:::note warn
`DATABRICKS_SQL_WAREHOUSE_ID` の必要性は公式ドキュメントに明記されていませんが、sql アドオンのソースコードで `env_prefix="DATABRICKS_SQL_"` が使われており、この環境変数が必須となっています。設定しないとバックエンドが起動しません。
:::

# ローカル開発

## 開発サーバーの起動

```bash
cd myapp
apx dev start
```

フロントエンド・バックエンド・データベース（PGLite）が同時に起動します。起動後は `http://localhost:9000` でアプリを確認できます。

![Screenshot 2026-03-05 at 11.54.57.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/031cf506-d51e-4e33-8a4a-e6247454a8ef.png)
![Screenshot 2026-03-05 at 12.06.52.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/315264c1-9b05-415f-8a3e-0acdcd3609bb.png)

## サーバーの状態確認

```bash
apx dev status
```

```
🚀 Dev server is running at http://localhost:9000
Frontend: healthy
Backend: healthy
```
`Frontend: healthy`・`Backend: healthy` になっていれば正常です。

## ログの確認

```bash
apx dev logs
```

バックエンドのみのログを見たい場合は以下のようにします。

```bash
apx dev logs be
```

## ローカルでの認証について

`/api/current-user` など、ユーザー認証（OBO トークン）を必要とするエンドポイントは、ローカルでも apx のプロキシが `X-Forwarded-Access-Token` ヘッダーを自動で注入してくれます。Databricks CLI で認証済みであれば追加設定は不要です。

# デプロイ

## ビルド

```bash
apx build
```

![Screenshot 2026-03-05 at 12.12.03.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/9ce3153d-7525-41fc-877c-cd9a4e63157e.png)

`.build/` ディレクトリに成果物（Python ホイール、`requirements.txt`、`app.yml`）が生成されます。

## Databricks へのデプロイ

Databricks Asset Bundles（DAB）を使ってデプロイします。

```bash
databricks bundle deploy --profile <your-profile>
```

## アプリの起動

デプロイ後はアプリを起動します。

```bash
databricks bundle run myapp-app --profile <your-profile>
```

成功すると以下のようにアプリの URL が表示されます。

```
✓ App started successfully
You can access the app at https://myapp-XXXXXXXXXXXXXXXXX.aws.databricksapps.com
```

# トラブルシューティング

## バックエンドが起動しない（ローカル）

`.env` の `DATABRICKS_CONFIG_PROFILE` が `DEFAULT` のままになっていないか確認してください。また、sql アドオンを使っている場合は `DATABRICKS_SQL_WAREHOUSE_ID` の設定も必要です。

## デプロイ後に "App Not Available" が表示される

本番環境に環境変数が渡されていない可能性があります。`databricks.yml` にアプリの設定として環境変数を追記してください。

```yaml
resources:
  apps:
    myapp-app:
      name: "myapp"
      description: "myapp created with apx"
      source_code_path: ./.build
      config:
        env:
          - name: DATABRICKS_SQL_WAREHOUSE_ID
            value: <your-warehouse-id>
```

追記後に再度デプロイと起動を実行します。

```bash
databricks bundle deploy --profile <your-profile>
databricks bundle run myapp-app --profile <your-profile>
```

# まとめ

apx を使うと、Databricks Apps のフルスタック開発環境を数コマンドで構築できます。ローカル開発からデプロイまでの流れをまとめると以下のとおりです。

1. `apx init` でプロジェクト生成
2. `.env` に Databricks のプロファイルとウェアハウス ID を設定
3. `apx dev start` でローカル確認
4. `apx build` でビルド
5. `databricks bundle deploy` でデプロイ
6. `databricks bundle run` でアプリ起動

Databricks Apps の開発をこれから始める方にとって、最初の一歩として非常に手軽なツールだと感じました。ぜひ試してみてください。

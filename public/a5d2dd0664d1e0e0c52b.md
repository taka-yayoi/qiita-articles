:::note
本記事は [Databricks Apps のテレメトリを構成する](https://docs.databricks.com/aws/ja/dev-tools/databricks-apps/observability) をベースに、実践的な設定手順をまとめたものです。アプリテレメトリは現在 **ベータ版** です。
:::

Databricks Apps では OpenTelemetry (OTel) プロトコルを使ったテレメトリ機能が利用できます。トレース・ログ・メトリックを自動収集して Unity Catalog のテーブルに保存できるため、アプリの動作監視やデバッグが格段に楽になります。

![Screenshot 2026-03-08 at 7.15.55.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/e9bea4b9-2124-424e-87e8-3b7cec0ca6bb.png)

# 要件

設定を始める前に、以下の要件を満たしているか確認してください。

**対応リージョン**

ワークスペースが以下のリージョンにある必要があります。

`ap-northeast-1` / `ap-northeast-2` / `ap-south-1` / `ap-southeast-1` / `ap-southeast-2` / `ca-central-1` / `eu-central-1` / `eu-west-1` / `eu-west-2` / `sa-east-1` / `us-east-1` / `us-east-2` / `us-west-2`

東京リージョン (`ap-northeast-1`) はサポートされています。

**Unity Catalog の権限**

| ケース | 必要な権限 |
|---|---|
| 新規テーブル作成 | ターゲットカタログ・スキーマへの `CAN MANAGE` + スキーマへの `CREATE TABLE` |
| 既存テーブルへの書き込み | `CAN MANAGE`、または全ユーザーが `USE CATALOG` / `USE SCHEMA` / `SELECT` / `MODIFY` を持つ |

また、ターゲットテーブルはワークスペースと同じリージョンの **マネージド Delta テーブル** である必要があります。クエリパフォーマンス向上のため、[予測的最適化](https://docs.databricks.com/aws/ja/optimizations/predictive-optimization) の有効化も推奨されています。

# アプリテレメトリを有効にする

**プレビュー**で**OpenTelemetry for Databricks Apps**を有効化します。

![Screenshot 2026-03-08 at 7.03.22.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/3cc342ff-2c6a-44e3-ad49-99d6d66b4363.png)

:::note
テレメトリのベータ版より前に作成したアプリは、設定前に一度停止してから再起動する必要があります。
:::

1. Databricks ワークスペースでアプリの詳細ページを開く
![Screenshot 2026-03-08 at 7.08.13.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/d1e45ac4-6143-4a29-9595-b9d6313b05b8.png)
2. 概要タブの **アプリテレメトリ** セクションで **追加** をクリック
3. テレメトリデータの書き込み先となるカタログとスキーマを入力または参照して選択
   - Databricks は選択した場所に `otel_metrics` / `otel_spans` / `otel_logs` の 3 テーブルを作成します
![Screenshot 2026-03-08 at 7.08.30.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/65d6fcf0-2875-424a-aa00-57e005d27b71.png)
4. (任意) テーブルプレフィックスを指定すると `<prefix>_otel_metrics` のように命名されます
![Screenshot 2026-03-08 at 7.08.51.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/17583a92-e64f-40a0-be57-9afc7fd42a53.png)
5. **保存** をクリック
6. テレメトリが Unity Catalog に流れ始めるようにアプリを **再デプロイ**

![Screenshot 2026-03-08 at 7.09.56.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/c8f1a089-b00b-4d96-9842-680eeb21371d.png)

# テレメトリデータを検証する

再デプロイ後、`otel_logs` テーブルにはデータが自動的に流れ込みます。`otel_spans` と `otel_metrics` は後述のカスタムインストルメンテーションを追加した後に使われます。

動作確認の手順は以下の通りです。

1. アプリの URL にアクセスしてアクティビティを生成する
2. 数秒待つ
3. Databricks SQL で次のクエリを実行して確認する

```sql
SELECT * FROM <catalog>.<schema>.otel_logs
LIMIT 10;
```

![Screenshot 2026-03-08 at 7.19.21.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/5660a869-ffb8-41fe-aebc-d175e35fec9b.png)

# テレメトリデータのクエリ

テーブルのスキーマを確認するには次を実行します。

```sql
DESCRIBE TABLE <catalog>.<schema>.otel_logs;
```

![Screenshot 2026-03-08 at 7.19.52.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/cff9fe18-dd3f-41b3-90b6-8d3f3d9a5e23.png)


フィルタリングや相関分析に役立つ主な列は以下です。

| 列名 | 説明 |
|---|---|
| `time` | イベント発生時刻 |
| `service_name` | アプリ名 |
| `trace_id` | トレース ID |
| `span_id` | スパン ID |
| `attributes` | イベント固有メタデータのマップ (`event.name` など) |

直近 1 時間の ERROR ログを取得する例です。

```sql
SELECT time, body
FROM <catalog>.<schema>.otel_logs
WHERE service_name = '<app-name>'
  AND severity_text = "ERROR"
  AND time >= current_timestamp() - INTERVAL 1 HOUR
ORDER BY time DESC
LIMIT 100;
```

# カスタムインストルメンテーションを追加する

自動計測を有効にすることで、カスタムトレース・メトリクス・ログを生成できます。フレームワークごとに `app.yaml` と依存ファイルを更新します。

## Streamlit

`app.yaml` を更新します。

```yaml
command: ['opentelemetry-instrument', 'streamlit', 'run', 'app.py']
env:
  - name: OTEL_TRACES_SAMPLER
    value: 'always_on'
```

`requirements.txt` を更新します。

```
streamlit==1.38.0

# Auto-instrumentation
opentelemetry-distro
opentelemetry-exporter-otlp-proto-grpc

# Required for Streamlit
opentelemetry-instrumentation-tornado

# Host metrics (CPU, memory)
opentelemetry-instrumentation-system-metrics
```

## Dash

`app.yaml` を更新します。

```yaml
command: ['opentelemetry-instrument', 'python', 'app.py']
env:
  - name: OTEL_TRACES_SAMPLER
    value: 'always_on'
```

`requirements.txt` を更新します。

```
dash
dash-bootstrap-components
pandas
plotly
databricks-sql-connector
databricks-sdk
python-dotenv
dash-ag-grid
opentelemetry-distro[otlp]
opentelemetry-instrumentation-flask
opentelemetry-exporter-otlp-proto-grpc
```

## Flask

`app.yaml` を更新します。

```yaml
command: ['opentelemetry-instrument', 'flask', '--app', 'app.py', 'run', '--no-reload']
env:
  - name: OTEL_TRACES_SAMPLER
    value: 'always_on'
```

`requirements.txt` を更新します。

```
opentelemetry-distro
opentelemetry-exporter-otlp-proto-grpc
opentelemetry-instrumentation-flask
```

## Node.js

`otel.js` ファイルを作成します。

```javascript
'use strict';

import { NodeSDK } from '@opentelemetry/sdk-node';
import { getNodeAutoInstrumentations } from '@opentelemetry/auto-instrumentations-node';
import { PeriodicExportingMetricReader } from '@opentelemetry/sdk-metrics';
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-proto';
import { OTLPMetricExporter } from '@opentelemetry/exporter-metrics-otlp-proto';
import { OTLPLogExporter } from '@opentelemetry/exporter-logs-otlp-proto';

const sdk = new NodeSDK({
  traceExporter: new OTLPTraceExporter(),
  metricReader: new PeriodicExportingMetricReader({
    exporter: new OTLPMetricExporter(),
    exportIntervalMillis: 10000,
  }),
  instrumentations: [
    getNodeAutoInstrumentations({
      '@opentelemetry/instrumentation-fs': { enabled: false },
    }),
  ],
});

try {
  sdk.start();
} catch (e) {
  console.error('OTel SDK failed to start', e);
}

async function shutdown() {
  try {
    await sdk.shutdown();
  } catch (e) {
    console.error('OTel SDK shutdown failed', e);
  } finally {
    process.exit(0);
  }
}
process.on('SIGTERM', shutdown);
process.on('SIGINT', shutdown);
```

`package.json` の `dependencies` に OTel 関連パッケージを追加し、`start` スクリプトで `otel.js` を `-r` フラグでロードします。

```json
{
  "name": "nodejs-otel",
  "version": "0.1.0",
  "private": true,
  "main": "app.js",
  "scripts": {
    "start": "node -r ./otel.js app.js"
  },
  "dependencies": {
    "express": "^4.21.2",
    "morgan": "^1.10.0",
    "@opentelemetry/api": "^1.9.0",
    "@opentelemetry/sdk-node": "0.203.0",
    "@opentelemetry/auto-instrumentations-node": "0.67.3",
    "@opentelemetry/exporter-trace-otlp-proto": "0.203.0",
    "@opentelemetry/exporter-metrics-otlp-proto": "0.203.0",
    "@opentelemetry/exporter-logs-otlp-proto": "0.203.0",
    "@opentelemetry/sdk-metrics": "2.0.1"
  }
}
```

# 環境変数

テレメトリを有効にすると、Databricks はアプリランタイムの環境変数を自動設定します。設定される内容は OTLP コレクターエンドポイント、エクスポートプロトコル、リソース属性、バッチ処理設定などです。

OTel 環境変数の完全なリストは[アプリテレメトリ環境変数](https://docs.databricks.com/aws/ja/dev-tools/databricks-apps/system-env#otel-env)を参照してください。

# 制限 (上限値)

| 項目 | 上限 |
|---|---|
| レコードサイズ | レコードあたり 10 MB |
| リクエストサイズ | リクエストあたり 30 MB |
| ログラインサイズ | ログ行あたり 1 MB |
| レート制限 | ワークスペースあたり 100 エクスポートリクエスト/秒 |
| 耐久性 | 単一 AZ のみ (ゾーン障害時にダウンタイムが発生する可能性あり) |
| 配信保証 | At-least-once (確認応答 = Delta テーブルへの永続書き込み完了) |

# 制限事項

- テーブル名には ASCII 文字・数字・アンダースコアのみ使用可能
- ターゲットテーブルで Arclight のデフォルトストレージは使用不可
- ターゲットテーブルの再作成は不可
- スキーマ進化 (Schema Evolution) は未サポート

# まとめ

Databricks Apps のテレメトリ機能を使えば、OpenTelemetry の標準的な仕組みをそのまま活用しながら、ログ・トレース・メトリックを Unity Catalog に集約できます。Streamlit / Flask / Dash / Node.js といった主要フレームワークに対応しており、設定変更も最小限です。現時点ではベータ版ですが、本番運用を見据えた可観測性の基盤として早めに導入を検討する価値があります。

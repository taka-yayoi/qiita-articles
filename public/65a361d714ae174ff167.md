# MLflowプロンプトレジストリとは

MLflowプロンプトレジストリは、生成AIアプリケーションで使用するプロンプトテンプレートを一元管理する機能です。Unity Catalogと統合され、プロンプトのバージョン管理、再利用、チーム間での共有が可能になります。この記事では、プロンプトの作成から編集、アプリケーションでの使用方法まで、実践的な流れを解説します。テンプレート変数を使った動的なプロンプト生成により、様々なユースケースに対応できる柔軟な仕組みを提供します。GitHubのようなバージョン管理により、プロンプトの改善履歴を追跡し、必要に応じて以前のバージョンに戻すことも可能です。

## 機能概要

MLflow プロンプトレジストリは、生成AIプロジェクトにおけるプロンプト管理の課題を解決する機能です。主な特徴は以下の通りです：

**プロンプトテンプレートの一元管理**
- Unity Catalogスキーマに関数として保存
- 組織全体でプロンプトを共有・再利用可能
- タグ付けによる分類と検索

**バージョン管理システム**
- Gitのような履歴管理
- コミットメッセージで変更内容を記録
- 特定バージョンへのロールバック可能

**動的なテンプレート変数**
- 二重中括弧構文 ({{variable}}) でパラメータを定義
- 実行時に値を動的に挿入
- 再利用性の高いプロンプト設計

## アーキテクチャ概要

Unity Catalogのスキーマに含まれる関数として取り扱われます。

```
Unity Catalog
    └── Schema (workspace.default)
        └── Prompt Function
            ├── Version 1
            ├── Version 2
            └── Version N
```

## 実装フローの図解

```
[プロンプト作成]
    ↓
[Unity Catalogに保存]
    ↓
[アプリケーションで読み込み]
    ↓
[変数を埋め込んで実行]
    ↓
[フィードバックを収集]
    ↓
[新バージョンを作成] → [プロンプト作成]に戻る
```

## メリット、嬉しさ

**1. チーム開発の効率化**
- プロンプトの重複開発を防止
- ベストプラクティスの共有が容易
- レビュープロセスの標準化

**2. 品質管理の向上**
- バージョン間の比較が可能
- A/Bテストの実施が簡単
- 改善履歴の追跡

**3. 運用の安定性**
- プロダクション環境での安全な更新
- 問題発生時の迅速なロールバック
- 監査証跡の自動記録

**4. 開発速度の向上**
- 既存プロンプトの再利用
- テンプレート化による標準化
- APIによる自動化

## プロンプトの作成と編集

このガイドでは、MLflow Python SDK を使用して MLflow プロンプト レジストリで新しいプロンプトを作成し、そのバージョンを管理する方法を示します。

## ステップ 1. 新しいプロンプトを作成する

プログラムでプロンプトを作成するには、`mlflow.genai.register_prompt()` を使用します。プロンプトはテンプレート変数にダブルブレース構文 (`{{variable}}`) を使用します。

```py
import mlflow

# CREATE FUNCTION権限があるUnity Catalogスキーマに置き換えてください
uc_schema = "takaakiyayoi_catalog.prompts"
# 以下のテーブルは上記で指定したUCスキーマに作成されます
prompt_name = "summarization_prompt"

# 変数付きのプロンプトテンプレートを定義
initial_template = """
提供された内容を{{num_sentences}}文で要約してください。

内容: {{content}}
"""

# 新しいプロンプトを登録
prompt = mlflow.genai.register_prompt(
    name=f"{uc_schema}.{prompt_name}",
    template=initial_template,
    # 以下のパラメータはすべてオプションです
    commit_message="要約プロンプトの初期バージョン",
    tags={
        "author": "takaaki.yayoi@databricks.com",
        "use_case": "document_summarization",
        "task": "summarization",
        "language": "ja",
        "model_compatibility": "gpt-4"
    }
)

print(f"プロンプト '{prompt.name}' が作成されました (バージョン {prompt.version})")
```
```
プロンプト 'takaakiyayoi_catalog.prompts.summarization_prompt' が作成されました (バージョン 1)
```

この辺りは[モデルレジストリ](https://docs.databricks.com/aws/ja/machine-learning/manage-model-lifecycle/)と同じです。

## ステップ 2. アプリケーションでプロンプトを使用する

次のセルは、レジストリからプロンプトをロードし、シンプルなアプリケーションで使用します。

```py
# URI構文を使って特定のバージョンを読み込む
prompt = mlflow.genai.load_prompt(name_or_uri=f"prompts:/{uc_schema}.{prompt_name}/1")

# URIを使わない別の構文
prompt = mlflow.genai.load_prompt(name_or_uri=f"{uc_schema}.{prompt_name}", version="1")
```

以下では`num_sentences=1`で1文への要約を指示しています。

```py
from openai import OpenAI

# MLflowの自動ロギングを有効にして、アプリケーションにトレースを追加
mlflow.openai.autolog()

# 同じ認証情報を使用してOpenAI経由でDatabricks LLMに接続
# あるいは、ここで独自のOpenAI認証情報を使用することも可能
mlflow_creds = mlflow.utils.databricks_utils.get_databricks_host_creds()
client = OpenAI(
    api_key=mlflow_creds.token,
    base_url=f"{mlflow_creds.host}/serving-endpoints"
)

# トレースデコレータを使用してアプリケーションのエントリーポイントをキャプチャ
@mlflow.trace
def my_app(content: str, num_sentences: int):
    # 変数でフォーマット
    formatted_prompt = prompt.format(
        content=content,
        num_sentences=num_sentences
    )

    response = client.chat.completions.create(
      model="databricks-claude-sonnet-4",  # この例ではDatabricksホストのLLMを使用しています。独自のOpenAI認証情報を提供する場合は、有効なOpenAIモデル（例：gpt-4）に置き換えてください。
      messages=[
          {
          "role": "system",
          "content": "あなたは役に立つアシスタントです。",
          },
          {
          "role": "user",
          "content": formatted_prompt,
          },
      ],
    )
    return response.choices[0].message.content

result = my_app(content="このガイドでは、MLflowプロンプトレジストリからプロンプトをGenAIアプリケーションに統合する方法を紹介します。プロンプトの読み込み、動的データでのフォーマット、およびプロンプトバージョンをMLflowモデルにリンクすることで完全な系譜を確保する方法を学びます。", num_sentences=1)
print(result)
```
```
このガイドは、MLflowプロンプトレジストリからプロンプトをGenAIアプリケーションに統合する手順を説明し、プロンプトの読み込み、動的データでのフォーマット、プロンプトバージョンとMLflowモデルのリンクによる完全な系譜確保の方法を解説しています。
```

## ステップ 3. プロンプトを編集する

特定バージョンのプロンプトは作成後に変更することはできません。プロンプトを編集するには、新しいバージョンを作成する必要があります。このGitのようなバージョン管理により、完全な履歴が保証され、ロールバックが可能になります。

次のセルでは、既存のプロンプト名を使用して `mlflow.genai.register_prompt()` を呼び出すことで新しいバージョンを作成する方法を示します:

```py
# 改善されたテンプレートを定義
new_template = """
あなたは要約の専門家です。以下の内容を、重要なポイントを正確に捉えた{{ num_sentences }}文の明確で有益な文章に要約してください。

内容: {{content}}

要約の条件:
- ちょうど{{num_sentences}}文で構成すること
- 最も重要な情報のみを含めること
- 中立的かつ客観的なトーンで書くこと
- 元の文章と同じレベルのフォーマルさを保つこと
"""

# 新しいバージョンを登録
updated_prompt = mlflow.genai.register_prompt(
    name=f"{uc_schema}.{prompt_name}",
    template=new_template,
    commit_message="出力品質向上のための詳細な指示を追加",
    tags={
        "author": "takaaki.yayoi@databricks.com",
        "改善点": "要約の品質に関する具体的なガイドラインを追加"
    }
)

print(f"'{updated_prompt.name}' のバージョン {updated_prompt.version} が作成されました")
```
```
'takaakiyayoi_catalog.prompts.summarization_prompt' のバージョン 2 が作成されました
```

# 注意点

**1. 権限管理**
- Unity Catalogスキーマへの`CREATE FUNCTION`権限が必須
- チーム間でのアクセス権限を適切に設定

**2. バージョンの不変性**
- 一度作成したバージョンは編集不可
- 変更は必ず新バージョンとして作成

**3. 命名規則**
- プロンプト名は`catalog.schema.prompt_name`形式
- 分かりやすく一貫性のある命名を推奨

**4. パフォーマンス考慮事項**
- 大量のプロンプトがある場合は適切なフィルタリングを使用
- 頻繁に使用するプロンプトはキャッシュを検討

**5. ベストプラクティス**
- コミットメッセージは具体的に記載
- タグを活用して分類・検索性を向上
- テンプレート変数は明確で理解しやすい名前を使用

# まとめ

MLflow プロンプトレジストリは、生成AIアプリケーション開発におけるプロンプト管理の課題を包括的に解決します。Unity Catalogとの統合により、エンタープライズレベルのガバナンスとセキュリティを確保しながら、開発チームの生産性を向上させます。

バージョン管理機能により、プロンプトの継続的な改善が可能になり、テンプレート変数による柔軟性も相まって、様々なユースケースに対応できます。今後の生成AI開発において、プロンプトレジストリは標準的なツールとして活用されることが期待されます。

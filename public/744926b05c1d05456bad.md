# インフラストラクチャではなくインサイトにフォーカス

本日のData + AIサミットにおいて、[Databricks SQL](https://databricks.com/jp/product/databricks-sql)(DBSQL)のサーバレスコンピュートがAWSでパブリックプレビューになったことを発表できて嬉しく思っています。DB SQLサーバレスを用いることで、レイクハウスでデータウェアハウスの作業を容易にスタートできるようになります。サーバレスを用いることで、時間を解放し、コストを引き下げ、そして、インフラストラクチャの管理ではなくあなたのビジネスに最大の価値をもたらすことにフォーカスできるようになります。

# 低コスト、パフォーマンスの改善のためのDatabricks SQLサーバレス

[Databricks SQL Serverless](https://qiita.com/taka_yayoi/items/2aef9099adcf146def91)は、お客さまが直面している計算資源、管理、インフラストラクチャのコストに関する課題の解決に役立ちます。

- **インスタントかつ柔軟**: サーバレスコンピュートは、あなたのニーズに合わせてすぐに利用できスケールする、真に弾力性のある常時稼働の環境を提供します。アイドル時間の課金を心配することなしに、シンプルな使用量ベースの課金によるメリットを得ることができます。クエリーを実行できるようになるまでクラスターを待つ必要がなくなることや、使用量のスパイクに対応するためにリソースを過剰に配備することがなくなることを想像してみてください。Databricks SQLサーバレスは、あなたが実行するいかなるワークロードに対応するために動的に拡大、縮退します。
- **管理のオーバーヘッドの削減**: サーバレスはDBSQLを完全なマネージドサービスにし、キャパシティ管理、クラスターのパッチ、アップグレード、パフォーマンスの最適化が不要となります。あなたはデータとデータに含まれる洞察にのみフォーカスできるようになります。 さらに、シンプルな課金モデルは、使用量に基づくコストを確認するための請求書が一つのみであることを意味します。
- **インフラストラクチャコストの低減**: あなたがリソースを必要とした際、内部ではサーバレスコンピュートプラットフォームは適切な計算リソースを提供し、スケールさせるために機械学習アルゴリズムを活用します。これによって、手動でクラスターをシャットダウンすることなしに、劇的にコストを削減することが可能となります。Scribdのようなお客様は、サーバレスを導入することで自身のSQLウェアハウスの利用率を向上し、インフラストラクチャのコストを劇的に削減できることを発見しました。

> *「我々のアナリストによって使用されるBIツールを強化するためにDatabicks SQLを活用しています。Databricks SQLサーバレスを用いることで、我々のインフラストラクチャをより効率的なものにするとともに、Databricks SQLのパワーを活用できています。サーバレスを確認してみると、インフラストラクチャのコストを3倍削減できていることがわかったので、さらに多くのデータパイプラインにDatabricks SQLサーバレスをインテグレーションしています。」– R Tyler Croy, Director of Platform Engineering, Scribd*

実際、我々の内部テストにおいて、Databricks SQLサーバレスが従来のデータウェアハウスと比較してベストなコストパフォーマンスを示していることがわかりました。
![](https://databricks.com/wp-content/uploads/2022/06/image3.png)
*ソース - 2022 Cloud Data Warehouse Benchmark Report; Databricks research*

サーバレスプラットフォームにおいては、blobストレージに対する[プライベートネットワーク接続](https://qiita.com/taka_yayoi/items/c6bdbb6452f6a0895961)、皆様の組織のガバナンスコントロールを維持しつつ、機微あるいはプロダクションのワークロードを実行できるようにする、格納データの暗号化のための[顧客管理キー](https://qiita.com/taka_yayoi/items/a93cc81ed0c803401bb7)のようなエンタープライズレベルのセキュリティをサポートしています。

# 使い始める

AWSをご利用なのであれば、アカウントコンソールからサーバレスを有効化するように管理者に依頼して、SQLウェアハウス(以前のSQLエンドポイント)を作成してください。また、ウェアハウス設定ページでサーバレスオプションをオンにすることで、既存のSQLウェアハウスでサーバレスを使用するように切り替えることができます。詳細は[サーバレスコンピュート](https://qiita.com/taka_yayoi/items/685a11ea726b2b34a174)のドキュメントを参照ください。

Azureを利用されている場合には、リクエストを[送信](http://bit.ly/DBSQLServerless-Azure)していただければ、Azure DatabricksでDatabricks SQLサーバレスが利用できるようになったら皆様をオンボードいたします。

Databricksが提供する[AI Dev Kit](https://github.com/databricks-solutions/ai-dev-kit)に含まれるBuilder Appをローカル環境でセットアップする際に、いくつかハマりポイントがあったのでまとめます。

# AI Dev Kitとは

AI Dev Kitは、Claude CodeやCursorなどのAIコーディングアシスタントからDatabricksを操作するためのツールキットです。主要コンポーネントは以下の通りです。

https://github.com/databricks-solutions/ai-dev-kit

- **databricks-tools-core**: Databricks操作のための高レベルPythonライブラリ
- **databricks-mcp-server**: MCP(Model Context Protocol)サーバー
- **databricks-skills**: AIアシスタントにDatabricksのベストプラクティスを教えるスキル集
- **databricks-builder-app**: チャットUIを備えたフルスタックWebアプリ(Visual Builder App)

この記事ではBuilder Appのローカルセットアップに焦点を当てます。

# Builder App(Visual Builder App)とは

Builder Appは、AI Dev Kitに含まれるWebベースのビジュアル開発ツールです。React(フロントエンド)+ FastAPI(バックエンド)のフルスタック構成で、チャットUIを通じてDatabricksの開発を行えます。

主な特徴は以下の通りです。

- チャットUIを備えたWebベースのDatabricks開発環境
- Claude Code統合(`claude-agent-sdk`を利用)
- MCPサーバー経由でDatabricksの各種ツールにアクセス可能
- スキル(ベストプラクティス集)によりDatabricksのパターンを理解した上でコードを生成
- バックエンドのデータストアとしてLakebase(DatabricksのOLTPデータベース)を使用

![Screenshot 2026-02-18 at 8.55.08.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/620d23ef-7487-4a10-9abc-bb8dac90fa49.png)

上の画面はBuilder Appの実際のUIです。チャットで「What tables and data do I have in my project?」と質問すると、Unity Catalogのテーブルやボリュームの一覧をカテゴリ別に整理して表示してくれます。左側のサイドバーには「Generate synthetic customer data...」「Create a dashboard to visualize...」などのプリセットも用意されており、よくあるDatabricks開発タスクをすぐに始められます。

# 前提条件

- Python 3.12+
- Node.js / npm
- [uv](https://docs.astral.sh/uv/)(Pythonパッケージマネージャー)
- Databricks CLI
- Databricksワークスペースへのアクセス
- Lakebase(プロビジョニング済みインスタンス)

# セットアップ手順

## リポジトリのクローンと初期セットアップ

```bash
git clone https://github.com/databricks-solutions/ai-dev-kit.git
cd ai-dev-kit/databricks-builder-app
./scripts/setup.sh
```

`setup.sh`が依存関係のインストールや初期設定を行います。

## Databricks認証の設定

環境変数でDatabricksワークスペースへの認証情報を設定します。

```bash
export DATABRICKS_HOST="https://your-workspace.cloud.databricks.com"
export DATABRICKS_TOKEN="dapi..."
```

またはDatabricks CLIプロファイルを使用します。

```bash
export DATABRICKS_CONFIG_PROFILE="your-profile"
```

## Lakebase接続の設定

Builder AppはバックエンドのデータストアとしてLakebase(DatabricksのOLTPデータベース)を使用します。ローカル開発では`.env.local`ファイルに静的な接続URLを設定します。

```
LAKEBASE_PG_URL=postgresql://<ユーザー名>:<パスワード>@<ホスト>:5432/databricks_postgres?sslmode=require
```

:::note info
**注意**
今回は[Postgres ロールとパスワードを使用した認証](https://docs.databricks.com/aws/ja/oltp/instances/authentication#postgres-%E3%83%AD%E3%83%BC%E3%83%AB%E3%81%A8%E3%83%91%E3%82%B9%E3%83%AF%E3%83%BC%E3%83%89%E3%82%92%E4%BD%BF%E7%94%A8%E3%81%97%E3%81%9F%E8%AA%8D%E8%A8%BC)を用いてLakebaseに接続しています。Postgresロールを作成後、[権限付与](#6-lakebase-postgresロールの権限不足)を行った上で、`.env.local`ファイルには以下の設定をしています。

```
LAKEBASE_PG_URL=postgresql://<Postgressロール>:<Postgresロールのパスワード>@<Lakebaseホスト>:5432/databricks_postgres?sslmode=require
```

:::


## 開発サーバーの起動

```bash
source .venv/bin/activate
./scripts/start_dev.sh
```

正常に起動すると、フロントエンドが `http://localhost:3000` 、バックエンドが `http://localhost:8000` で動作します。

データストアとしてLakebaseが動いているので、会話履歴や設定も永続化されます。

# ハマりポイントと対処法

ローカルセットアップで遭遇した問題とその解決策をまとめます。

## 1. uvicorn: command not found

`start_dev.sh`実行時にバックエンドが起動しない。

```
./scripts/start_dev.sh: line 39: uvicorn: command not found
```

**原因**: `setup.sh`で作成された仮想環境(`.venv`)がactivateされていない。

**対処法**: 起動前に仮想環境をactivateする。

```bash
source .venv/bin/activate
./scripts/start_dev.sh
```

## 2. Invalid access token

バックエンド起動時にDatabricks認証エラーが発生する。

```
ValueError: Could not determine current user: Invalid access token.
```

**原因**: Personal Access Token(PAT)の期限切れ、または値の誤り。

**対処法**: Databricksワークスペースで新しいPATを生成して環境変数を更新する。

1. ワークスペースにログイン
2. Settings → Developer → Access tokens → Generate new token
3. 環境変数を更新: `export DATABRICKS_TOKEN="dapi..."`

## 3. 接続URLの`@`エンコード問題

Lakebaseのユーザー名にメールアドレス(例: `user@databricks.com`)を使用すると、URLパースが壊れる。

**原因**: ユーザー名内の`@`がURL区切り文字として解釈される。

**対処法**: `@`を`%40`にURLエンコードする。

```
# NG
postgresql://user@databricks.com:password@host:5432/db

# OK
postgresql://user%40databricks.com:password@host:5432/db
```

ただし、ネイティブPostgresロール(メールアドレスではないユーザー名)を使う場合はこの問題は発生しません。

## 4. Lakebaseインスタンスが見つからない

```
databricks.sdk.errors.platform.NotFound: Resource not found
```

**原因**: `LAKEBASE_INSTANCE_NAME`で指定したインスタンスがワークスペースに存在しない、またはアプリが動的OAuthモードにフォールバックしている。

**対処法**: `.env.local`に`LAKEBASE_PG_URL`を設定して静的URLモードを使用する。`LAKEBASE_PG_URL`が設定されていれば、SDK経由でのインスタンス検索は行われません。

## 5. fe_sendauth: no password supplied

PostgreSQL接続時にパスワードが供給されないエラー。

```json
{"detail":"Internal Server Error","error":"(psycopg.OperationalError) connection failed: fe_sendauth: no password supplied"}
```

**原因**: Alembic(DBマイグレーションツール)の`env.py`が`.env.local`を読み込むが、接続情報が`.env`にしか記載されていない。

```python
# alembic/env.py
load_dotenv('.env.local')  # .env ではなく .env.local を読む
```

**対処法**: `.env.local`に`LAKEBASE_PG_URL`を正しく設定する。

```bash
# .env.local に接続URLが設定されているか確認
grep LAKEBASE_PG_URL .env.local
```

## 6. Lakebase Postgresロールの権限不足

ネイティブPostgresロールを作成しても、データベース操作でエラーになる。

**原因**: ネイティブロールは作成直後はPUBLICに付与された権限しか持たない。

**対処法**: インスタンスオーナーとしてpsqlで接続し、必要な権限をGRANTする。

```sql
-- データベースへの接続許可
GRANT CONNECT ON DATABASE databricks_postgres TO <ロール名>;

-- スキーマの使用・作成許可
GRANT USAGE ON SCHEMA public TO <ロール名>;
GRANT CREATE ON SCHEMA public TO <ロール名>;

-- テーブル・シーケンスへの全操作許可
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO <ロール名>;
GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA public TO <ロール名>;

-- 今後作成されるオブジェクトへの自動権限付与
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT ALL PRIVILEGES ON TABLES TO <ロール名>;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT ALL PRIVILEGES ON SEQUENCES TO <ロール名>;
```

Lakebaseの認証・権限管理の詳細は[データベース・インスタンスに対する認証](https://docs.databricks.com/aws/ja/oltp/instances/authentication)を参照してください。

# まとめ

Builder Appをローカルで動かすためのポイントは以下の通りです。

1. **仮想環境のactivateを忘れずに**: `source .venv/bin/activate`してから`start_dev.sh`を実行
2. **PATの有効期限に注意**: 期限切れの場合は再生成
3. **Lakebase接続はURL内の特殊文字に注意**: 特にメールアドレスをユーザー名に使う場合は`@`のエンコードが必要
4. **`.env.local`に接続情報を設定**: Alembicマイグレーションは`.env.local`を参照する
5. **ネイティブPostgresロールには明示的に権限付与が必要**: `GRANT`文で必要な権限を設定

これらを押さえておけば、ローカル環境でBuilder Appを動かしてDatabricksプロジェクトの開発を始められます。

# ETLとは

ETLとは、

- **E**xtract(抽出): ソースシステムからのデータの取り込み
- **T**ransformation(変換): ターゲットシステムに投入する前に必要な変換処理を適用
- **L**oad(ロード): ターゲットシステムへのロード

の組み合わせなわけですが、E(抽出)はソースシステムとのインタフェースやフォーマット、取り込み形態(バッチやストリーミング、洗い替えなのか差分取り込みなのか)に注意すれば良いわけで、ロードも同様にどのようにターゲットシステムにロードするのかさえ特定すれば良いわけです(とは言っても、実際に実装する際には悩むことはあります)。

## 変換戦略の立案

手元のテーブルを見ながら、最終的にどのような形式のテーブルにしたいのかを考えます。

ここでは以下の変換をかけます。[こちらの記事](https://aws.amazon.com/jp/what-is/etl/?nc1=h_ls)のいくつかの変換処理を実行します。なお、すべてSQLで実行します。下に行くほど難しいかと。

1. **データ重複排除:** 重複レコードの排除
1. **データクレンジング:** 不要列の除外
1. **分割:** 姓名を別の列に分離
1. **データ形式の改訂:** 文字列になっている`currency`列を数値に変換
1. **暗号化:** メールアドレスの`@`の前半を匿名化

## 重複レコードの排除

意図的にレコードを重複させておいてなんですが、まずはレコードの重複排除から行います。SELECTの`DISTINCT`を使用します。

```sql:SQL
SELECT
  DISTINCT *
FROM
  takaakiyayoi_catalog.etl_in_action.bronze;
```
重複が排除されました。

## 姓名を別の列に分離

[split関数](https://docs.databricks.com/ja/sql/language-manual/functions/split.html)を使います。戻り値が配列になるので、[添字を指定](https://ganeshchandrasekaran.com/databricks-how-to-split-a-string-using-spark-sql-ada34ec2de82)して性と名それぞれの列に分割します。

```sql:SQL
SELECT
  DISTINCT split(name, ' ') [0] AS first_name,
  split(name, ' ') [1] AS sir_name,
  email,
  phone,
  country,
  region,
  address,
  postalZip,
  currency
FROM
  takaakiyayoi_catalog.etl_in_action.bronze;
```
![Screenshot 2023-11-25 at 19.21.22.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/6e621b8c-ca38-d68b-5a5e-47e8f1e0b474.png)

## 文字列になっている`currency`列を数値に変換

`$`を除外した上で数値型に変換します。先頭文字を除外するので[substring関数](https://docs.databricks.com/ja/sql/language-manual/functions/substring.html)を使います。戻り値は数値型に変換可能な形になっているので、型の[cast](https://docs.databricks.com/ja/sql/language-manual/functions/cast.html)を行います。

```sql:SQL
SELECT
  DISTINCT split(name, ' ') [0] AS first_name,
  split(name, ' ') [1] AS sir_name,
  email,
  phone,
  country,
  region,
  address,
  postalZip,
  cast(substring(currency, 2) AS DOUBLE) AS currency_num
FROM
  takaakiyayoi_catalog.etl_in_action.bronze;
```

数値型に変換されました。
![Screenshot 2023-11-25 at 19.29.09.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/3649121c-fb70-d625-02c7-c1c7a5a91628.png)

## メールアドレスの`@`の前半を匿名化

最後の処理です。正規表現を使うので、[regexp_replace関数](https://docs.databricks.com/ja/sql/language-manual/functions/regexp_replace.html)を使います。

```sql:SQL
SELECT
  DISTINCT split(name, ' ') [0] AS first_name,
  split(name, ' ') [1] AS sir_name,
  regexp_replace(email, '.*@', 'xxxxx@') AS anonymized_email,
  phone,
  country,
  region,
  address,
  postalZip,
  cast(substring(currency, 2) AS DOUBLE) AS currency_num
FROM
  takaakiyayoi_catalog.etl_in_action.bronze;
```

匿名化されました！

## シルバーテーブルへのロード

この結果は、[メダリオンアーキテクチャ](https://www.databricks.com/jp/glossary/medallion-architecture)におけるシルバーテーブルに該当するので、テーブルに書き込みます。CTAS(Create Table As Select)を使います。

```sql:SQL
CREATE TABLE takaakiyayoi_catalog.etl_in_action.silver AS
SELECT
  DISTINCT split(name, ' ') [0] AS first_name,
  split(name, ' ') [1] AS sir_name,
  regexp_replace(email, '.*@', 'xxxxx@') AS anonymized_email,
  phone,
  country,
  region,
  address,
  postalZip,
  cast(substring(currency, 2) AS DOUBLE) AS currency_num
FROM
  takaakiyayoi_catalog.etl_in_action.bronze;
```
シルバーテーブルの完成です！
![Screenshot 2023-11-25 at 19.36.50.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/1168882/0fb2eb54-bffa-9d52-b8c9-81ca886f7128.png)

通常はこれよりも多いレコード数になりますので、これらを集計することでゴールドテーブルを作る形となります。

# まとめ

- 変換処理を実装する際には、生のデータ(ブロンズテーブル)からロードするデータ(シルバーテーブル)をイメージし、どのような処理が必要なのかを洗い出しましょう。
- いきなりすべての処理を実装するのではなく、ステップバイステップで実装していき動作を確認しましょう。
- すべての変換処理が実装できたら、シルバーテーブルにロードしましょう。
- 必要な処理のほとんどはビルトインの関数で準備されていますので、[マニュアル](https://docs.databricks.com/ja/sql/language-manual/index.html)にも目を通しておきましょう。

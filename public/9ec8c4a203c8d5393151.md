こちらの記事では、[MLflowのLLMジャッジ](https://mlflow.org/docs/latest/genai/eval-monitor/scorers/llm-judge/)を使ったエージェントの評価方法を説明しています。[評価観点を日本語で定義](https://qiita.com/taka_yayoi/items/8da95446d03123548cb5#%E3%82%A8%E3%83%BC%E3%82%B8%E3%82%A7%E3%83%B3%E3%83%88%E3%82%92%E3%82%A8%E3%83%BC%E3%82%B8%E3%82%A7%E3%83%B3%E3%83%88%E8%A9%95%E4%BE%A1%E3%81%A7%E8%A9%95%E4%BE%A1%E3%81%99%E3%82%8B)できて便利なのですが、別な評価観点としては「特定のツールを呼び出しかどうか」というものがあると思います。この場合は、LLMよりもルールベースでの評価が必要となります。

ということで、問い合わせに応じてエージェントが適切なツールを呼び出したかどうかを評価してみます。こちらにある[コードベースのカスタムスコアラー](https://mlflow.org/docs/latest/genai/eval-monitor/scorers/custom/)を定義します。

以下は変更分のみを記載します。

# カスタムのコードベースのスコアラーの定義

次が大きな変更点です。`Guidelines`で定義されるLLMスコアラーに加えて、カスタムのコードスコアラーである`specific_tool_check`を定義しています。ここでは、入力クエリーに含まれているキーワードに基づいて呼び出されるべきツールを`required_tools`で定義しています。実装次第ではここにLLMを組み込めると思います。

ここで鍵となるのはトレース`trace`へのアクセスです。エージェントがどのツールを呼び出したのかはトレースに含まれているので、これにアクセスしてチェックしています。

- `search_product_docs`: ベクトルDB検索ツール
- `get_todays_date`: 今日の日付取得ツール

ここで、`色`に`get_todays_date`をマッピングしているのは意図的に評価に失敗するようにするためです。

```py
from mlflow.genai.scorers import Guidelines, scorer
from mlflow.entities import Feedback, Trace
import mlflow.genai
import pandas as pd
import re

# 評価用データセットを作成
eval_data = []
for request, facts in zip(data["request"], data["expected_facts"]):
    eval_data.append({
        "inputs": {
            "query": request  # 関数の引数と一致させる
        },
        "expectations": {
            "expected_response": "\n".join(facts)
        }
    })


# ツール評価スコアラー
@scorer
def specific_tool_check(inputs: dict, trace: Trace) -> Feedback:
    """特定のツールが適切に使用されたかを評価"""
    
    # inputsからクエリを取得
    query = inputs.get("query", "")
    
    required_tools = {
        "色": ["get_todays_date"],
        "掃除": ["search_product_docs"],
        "サイズ": ["search_product_docs"],
        "仕様": ["search_product_docs"],
        "価格": ["search_product_docs"],
        "今日": ["get_todays_date"]
    }
    
    # クエリからクエリタイプを判定
    query_type = None
    for keyword in required_tools.keys():
        if keyword in query:
            query_type = keyword
            break
    
    if not query_type:
        return Feedback(
            value="yes", 
            rationale=f"クエリ '{query[:30]}...' は特定のツールチェック対象外"
        )
    
    # トレースから使用されたツールを取得（改善版）
    tools_used = []
    if trace and hasattr(trace, 'data'):
        for span in trace.data.spans:
            span_name = span.name if hasattr(span, 'name') else ""
            span_type = span.span_type if hasattr(span, 'span_type') else ""
            
            # ツールの識別
            if span_type == "TOOL":
                clean_name = re.sub(r'_\d+$', '', span_name)
                tools_used.append(clean_name)
            elif any(pattern in span_name.lower() for pattern in ['search', 'query', 'retrieve']):
                # 一般的なスパンを除外
                if span_name not in ['LangGraph', 'start', 'end', '__start__', '__end__'] and not span_name.startswith('agent'):
                    clean_name = re.sub(r'_\d+$', '', span_name)
                    tools_used.append(clean_name)
    
    # 重複を除去
    tools_used = list(set(tools_used))
    
    # 必要なツールが使用されたかチェック
    required = required_tools[query_type]
    found_any = False
    for tool in tools_used:
        for req_tool in required:
            if req_tool in tool:
                found_any = True
                break
    
    if not found_any and tools_used:
        return Feedback(
            value="no",
            rationale=f"'{query_type}'関連のクエリで期待されるツール{required}が使用されず、{tools_used}が使用されました"
        )
    elif not found_any:
        return Feedback(
            value="no",
            rationale=f"'{query_type}'関連のクエリで期待されるツール{required}が使用されていません"
        )
    else:
        used_required = [tool for tool in tools_used for req_tool in required if req_tool in tool]
        return Feedback(
            value="yes",
            rationale=f"'{query_type}'関連のツール{list(set(used_required))}が適切に使用されました"
        )

# 評価用スコアラーを定義
scorers = [
    # 既存のガイドラインスコアラー
    Guidelines(
        guidelines="""応答にはすべての期待される事実が含まれている必要があります:
        - 該当する場合はすべての色やサイズを列挙する（部分的なリストは不可）
        - 該当する場合は正確な仕様を記載する（例:「5 ATM」など曖昧な表現は不可）
        - 掃除手順を尋ねられた場合はすべての手順を含める
        いずれかの事実が欠落または誤っている場合は不合格とする。""",
        name="completeness_and_accuracy",
    ),
    Guidelines(
        guidelines="""応答は明確かつ直接的でなければなりません:
        - 質問に正確に答える
        - 選択肢はリスト形式、手順はステップ形式で記載
        - マーケティング的な表現や余計な背景説明は不要
        - 簡潔かつ完全であること。""",
        name="relevance_and_structure",
    ),
    Guidelines(
        guidelines="""応答は話題から逸脱しないこと:
        - 質問された製品のみについて回答する
        - 架空の機能や色を追加しない
        - 一般的なアドバイスは含めない
        - リクエストに記載された製品名を正確に使用すること。""",
        name="product_specificity",
    ),
    # カスタムツールスコアラーを追加
    specific_tool_check,  # 詳細なツールチェック
]
```

# 評価の実施

評価を実施します。

```py
# 評価の実行
with mlflow.start_run():
    results = mlflow.genai.evaluate(
        predict_fn=predict_wrapper, 
        data=eval_data,
        scorers=scorers
    )
```

今後エージェントの普及が進むと、その複雑性も増加していくことが予想されます。期待した通りにエージェントが動作しているかどうかを評価するためにも、さまざまな観点で評価できるように今の時点から評価ツールに慣れておくことには大きな意義があると思います。

# イントロダクション

人工知能はビジネスランドスケープを変革しており、企業に対して過去数年間うまくいっていた戦略の再評価を求めています。AIの進展に伴って組織は、これらの革新的な技術を取り込んで、よりデータ駆動のアプローチに適応したいと考えています。**エージェントAI**は重大なマイルストーンを示しています。これらのインテリジェントなエージェントは数分で複雑なタスクに対応し、情報に基づく意思決定を行い、包括的なリサーチを実施することができます。この自動化は、これまで予想ができなかった規模でチームの取り組み方法を変革させており、Databricksではこれまで以上にエージェントの作成が容易になっています。

Data + AIサミット2025の[発表](https://www.databricks.com/jp/blog/mosaic-ai-announcements-data-ai-summit-2025)に続いて、新たなツールが利用できるようになっており、お客様にとってはDatabricksプラットフォームでのAIベースのソリューションの構築が容易になっています。これらのアップデートの中には、Databricksにおけるエージェント構築の継続中の取り組みをサポートする企業レベルの進歩が反映されています。本書では、Unity Catalog、Playground、MLflow 3.0のようなDatabricksの機能を活用してリアルタイムでパーソナライズされたコンテンツの提供を行うプロダクションレベルのシスt目うの作成方法を学ぶことになります。

# なぜ重要なのか

すべてのアドテック/マーテック企業は、膨大な顧客のデータセットを有しています。ブラウジングの挙動、購入履歴、エンゲージメントパターン、デモグラフィック情報などです。しかし、ほとんどの企業はリアルタイムのパーソナライゼーションのためにこのデータを活用することに苦戦しています。それぞれのキャンペーンタイプに個別のMLモデルを構築したり、基本的なセグメンテーションルールに依存するのではなく、エージェントAIを用いることで、単一のインテリジェントシステムを通じてあなたのすべてのデータを活用することができます。

プロダクションにデプロイすることで企業が享受できるメリットは何なのでしょうか？

- キャンペーン作成時間の削減
- データ駆動の洞察を通じたEメール駆動の収益の改善
- 線形のコストなしにスケール可能

マーケティングチームが手動で膨大なEメールのバリエーションを作成したり、データサイエンスのリソースを数週間待つのではなく、あなたの顧客のデータを理解し、リアルタイムでパーソナライズされたコンテンツを生成する**単一のエージェントシステム**をデプロイするのです。このエージェントはすべてのインタラクションから学習を行い、通常はキャンペーンの複雑生と線形にスケールするオペレーション上のオーバーヘッドを削減しつつも、継続的にパフォーマンスを改善します。

# シナリオ

プロダクションレベルのソリューションの作成に飛び込む前に、シナリオの概要を説明しましょう。

> 企業Aのマーケティングチームは、彼らのアクティブユーザーベースに対して様々なキャンペーンのために高度にパーソナライズされたEメールのタイトルを提供するという圧力の下にいます。この課題に対応するために、エージェントAIを用いてプロセスを自動化しようとしています。彼らのデータインフラストラクチャの大部分は、Databricksに存在しているので、このソリューションはクイックにデプロイでき、スケーラブルであり、シームレスに既存のユーザーのデータシステムと連携できるに違いありません。

# 目的

エンゲージメントの最大化を狙っって、特定のオーディエンスに対してパーソナライズされたメールタイトルを生成するエージェントを作成します。このエージェントは、オーディエンスの文脈に基づいて決定を行い、リアルタイムの洞察と過去のユーザーの挙動を用いて継続的に戦略を改善します。

# AIフレンドリーなツールキットの構築

エージェントはインテリジェントですが、効果的に動作するためのサポートを必要とします。ここで、ツールカタログが役立ちます。[Unity Catalog](https://www.databricks.com/jp/product/unity-catalog)においては、ユーザー定義関数でツールを定義することができ、エージェントの能力を基礎知識以上に拡張し、より良い意思決定を行うために必要な文脈をエージェントに提供します。

この例においてエージェントがインテリジェントに振る舞うためには、以下の質問に対する回答とテクノロジーで武装する必要があります:

- このユーザーは誰？彼らに対して我々は何を知っている？
- 過去にこのユーザーはどのような振る舞いをした？
- 過去を振り返ってみて似た挙動をしたユーザーはいるのか？

Databricksで[SQL UDF](https://www.databricks.com/blog/2021/10/20/introducing-sql-user-defined-functions.html)を作成することで、これらの質問のそれぞれに回答することができます。*適切なデータ*を取得する関数を意図的に設計することで、エージェントが確実にリアルタイムのパーソナライゼーションのための適切な文脈を受信できるようになります。以下の関数は我々のマーケティングシナリオでエージェントが活用できるように、**Unity Catalogのツール**として格納されます。

```sql
-- Summarized Function: Who is this User?
CREATE OR REPLACE FUNCTION fn_get_user_demographics(user_id_param BIGINT)
RETURNS STRUCT<
  segment: STRING,
  age_range: STRING,
  income_range: STRING,
  signup_date: DATE,
  preferred_channel: STRING
>
RETURN (
  SELECT STRUCT(
    segment,
    age_band as age_range,
    income_band as income_range,
    signup_date,
    preferred_channel
  )
  FROM catalog.schema.user_demographics
  WHERE user_id = user_id_param
);
```

```sql
-- Summarize Function on User Behavior: How has this user behaved?
CREATE OR REPLACE FUNCTION fn_get_user_behavior(user_id_param BIGINT)
RETURNS STRUCT<
  total_purchases: INT,
  total_spent: DECIMAL(10,2),
  avg_order_value: DECIMAL(10,2),
  last_purchase_date: DATE,
  most_purchased_category: STRING
>
RETURN (
  SELECT STRUCT(
    COUNT(order_id) as total_purchases,
    SUM(order_amount) as total_spent,
    AVG(order_amount) as avg_order_value,
    MAX(order_date) as last_purchase_date,
    MODE(product_category) as most_purchased_category
  )
  FROM catalog.schema.user_orders
  WHERE user_id = user_id_param
);
```

```sql
-- Summarization on Segment Behavior: How has a segment behaved?
CREATE OR REPLACE FUNCTION fn_get_segment_behavior(user_id_param BIGINT)
RETURNS STRUCT<
  segment_avg_purchases: DECIMAL(8,2),
  segment_avg_spent: DECIMAL(10,2),
  segment_avg_order_value: DECIMAL(10,2),
  segment_top_category: STRING
>
RETURN (
  SELECT STRUCT(
    AVG(total_purchases) as segment_avg_purchases,
    AVG(total_spent) as segment_avg_spent,
    AVG(avg_order_value) as segment_avg_order_value,
    MODE(most_purchased_category) as segment_top_category
  )
  FROM catalog.schema.user_behavior_summary u
  JOIN catalog.schema.user_demographics d ON u.user_id = d.user_id
  WHERE d.audience = (
    SELECT audience 
    FROM catalog.schema.user_demographics 
    WHERE user_id = user_id_param
  )
);
```

# プロダクションレベルのエージェントの作成

Databricks Playgroundでのエージェントのプロトタイピングと改善のあとのプロダクションへの移行はシンプルです。Databricksは、Playgroundから「エージェントノートブック」を自動で生成し、あなたのエージェントのツール、ツールのインテグレーションや設定を、きれいに整理してプロダクションレベルのワークフローにパッケージングします。

![](https://miro.medium.com/v2/resize:fit:1400/format:webp/0*hOgOEQQOEHj1x1Ie)

エージェントノートブックを生成すると、すでに記入済みのセクションを確認できるはずです。このノートブックでは、Pythonを用いてエージェントの開発と実験を継続することができ、Playgroundから既存のコードを構築することができます。あるいは、Playgroundでやり取りしたエージェントをデプロイするために「すべてを実行」を選択することもできます。

[モデルサービング](https://www.databricks.com/jp/product/model-serving)を通じてDatabricksでエージェントをデプロイする際には、以下のキーとなるステップを順に実行する必要があります:

- エージェントコードの生成
- MLflow 3.0によるテスト
- Unity Catalogにモデルを記録
- プロダクションへのデプロイ

:::note info
**注意:** あなたのエージェントのコードを作成する際には、MLflow 3.0のトレーシングを有効化するために以下の行を追加してください。
:::

```py
# Sets up MLflow 3.0 to automatically track and log aspects of the Langchain Workflow
mlflow.langchain.autolog()
```

# モニタリングと評価

MLflow 3.0トレーシングのおかげで、あなたがデプロイしたエージェントに対して完全な透明性を得ることができます。MLflowは検討なトラッキング、ロギング、モニタリングの機能を提供し、以下を可能にします:

- 使用されたツールと意思決定プロセスを含むエージェントのアクティビティに関する詳細なログ。
- パフォーマンスメトリクスの追跡、エージェントの出力の時間変化の監視。
- あなたのエージェントが期待した通りに動作し、価値を提供していることを確実にするためのアラートとダッシュボードのセットアップ。

# 実装のヒント

1. **小さく始めましょう** - 小規模なツールキットで一つのユースケースにフォーカスしましょう。
1. **AIを念頭に置いて関数を設計しましょう** - エージェントのように考えましょう。この問題の解決の助けとなるような情報にはどのようなものがありますか？文脈が多いほど、エージェントは適切に動作します。
1. **パフォーマンスを監視しましょう** - MLflow 3.0の新機能によって、エージェントのやり取りを追跡し、意思決定を行うことができます。ファインチューンの際にはこの利点を活用しましょう。

# まとめ

Databricksは、大規模な自動化やパーソナライズ体験を行うAIエージェントの構築、デプロイを行う方法を非常にシンプルなものにします。Unity Catalog、プロトタイピングのためのPlayground、ターゲティングされたUDF、モニタリングのためのMLflow 3.0のようなツールを活用することで、かつては数ヶ月要していたカスタム開発を数時間で完了することができます。この変化によって、チームは技術的な課題ではなくビジネスロジックにフォーカスすることができ、Databricksをデータをインテリジェントで自動化された意思決定に変換するための最先端のプラットフォームとして確立することができます。我々のEメールパーソナライゼーションの例では、適切なプラットフォームが複雑なアドテック/マーテックの問題を、効率的でスケーラブルなソリューションに変換することを示しています。Databricksは、収集された顧客データを、計測可能なビジネス成果につながるインテリジェントで自動化された意思決定に変換するための基盤となるデータプラットフォームです。
